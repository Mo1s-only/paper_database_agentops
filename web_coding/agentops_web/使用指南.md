# AgentOps Web 使用指南

本机入口：http://127.0.0.1:3017/overview 。首次使用包含 3 个项目、6 条固定演示 Trace；项目、策略、标签和后续导入均保存在本机 SQLite，不消耗模型 API 费用。

## 启动与停止

在 PowerShell 运行：

```powershell
cd 'C:\Users\Administrator\Desktop\论文方向\web_coding\agentops_web'
powershell -ExecutionPolicy Bypass -File .\Start-AgentOpsWeb.ps1
```

脚本会识别已运行的 AgentOps Web；否则启动本地开发预览。保持终端开启，Ctrl+C 停止。端口冲突时使用 `-Port 3018`，访问对应地址。需要 Node.js 24+；首次缺少依赖需先执行 `pnpm install`。当前会话已启动时直接打开网页即可。

## 推荐的五分钟体验路线

1. **总览**：顶部选“全部项目”，时间选“最近 24 小时”。查看 Trace、Span、Token、成本与错误率。改为“最近 1 小时”，演示数据从 6 条变为 2 条；点击“刷新数据”会重新请求服务端。
2. **失败队列**：点击总览“打开失败队列”，或进入 Traces 把状态切为“错误”。可按名称、ID、标签检索，按延迟、成本或 Token 排序；右侧箭头打开快速详情，名称链接打开完整回放。
3. **执行回放**：打开 `incident_root_cause_analysis`。左侧选择 Span，查看输入、输出、错误和原始数据。切换“失败归因”可查看规则基线给出的可疑 Span 与证据。
4. **人工标注与评测**：在失败归因页点击“标注根因”，选择 Span、失败类型并填写证据。保存后到“评测”页查看标签覆盖与候选一致性，并导出 JSON。自动候选分数是启发式评分；本地单人标签与演示样本均不构成论文准确率结论。
5. **保存常用视图**：Traces 设置好项目、时间、关键词和状态后点击“保存当前视图”。之后点击视图名称即可恢复这些筛选。收藏按钮与 JSON 导出也基于当前结果。

时间筛选：本地模式相对于全部数据（含导入）的最新 Trace 时间计算；远程模式相对于请求时间计算。范围提示和图表桶使用 UTC，Trace 列表时间采用北京时间。新建项目没有 Trace，因此列表为空是正常现象。

## 页面用途

| 页面 | 如何使用 | 保存/执行范围 |
| --- | --- | --- |
| 总览 | 选择项目、时间，进入失败队列或性能页 | 由当前 Trace 派生指标；没有伪造环比 |
| Traces | 搜索、筛选、排序、收藏、保存视图、JSON 导出、下钻 | 收藏和视图保存在此浏览器 |
| Metrics | 查看 P95、模型成本、调用类型和延迟排行 | 与总览使用相同项目和时间范围 |
| 评测 | 查看失败样本、人类标签与规则候选一致性 | Ground Truth 保存在服务端 SQLite；按项目与来源统计 |
| 项目 | 新建或编辑名称、环境，点“查看 Traces”切换项目 | 本地模式保存至服务端 SQLite；远程模式只读 |
| 告警 | 新建/编辑策略 → 应用到草稿 → 保存策略 | SQLite 持久化与版本校验；邮件/Webhook 尚未投递 |
| 设置与接入 | 点击“测试连接”，检查实际服务端数据源 | 查看存储说明、导入指南和最近 100 条本机操作 |
| MCP / Deploy | 查看配置与部署交互 | 流程原型，不会实际启动云资源 |

项目、告警策略、人工标签和导入数据已从浏览器迁至 `.data/agentops.sqlite`。旧浏览器配置不会自动覆盖数据库，可在对应页面载入草稿后确认保存。只有搜索视图、收藏、主题和筛选偏好仍依赖浏览器。多窗口保存时版本冲突返回提示，不静默覆盖。

## 接入真实观测数据

### 本地 JSON 导入

1. 在项目页创建项目，然后进入 Traces，点击“导入 Trace”。
2. 下载结构示例，或准备符合 `lib/types.ts` 的 Trace 数组；也支持 `{ "traces": [...] }` / `{ "data": [...] }`。
3. 选择目标项目并上传或粘贴 JSON，点击“校验并预览”，检查数量、来源与脱敏情况，再确认导入。
4. 导入成功后自动切换到目标项目和全部时间。单批上限 5 MiB、100 条 Trace、2000 个 Span；ID 重复时整批拒绝，不覆盖旧数据。
5. 总览、Traces、Metrics 可按“仅示例数据 / 仅用户导入”筛选；评测页也有独立来源筛选。示例仍保留演示标记，用户导入不代表数据真实性已核验。

数据库默认位于 `.data/agentops.sqlite`，可用 `AGENTOPS_DB_PATH` 指定其他位置。正常停止服务后复制整个 `.data` 目录做备份；容器需挂载持久化卷。服务重启不清空保存的数据。当前是单机工作区，不是多租户服务。

### 远程只读 API

复制 `.env.example` 为 `.env.local`，设置 `AGENTOPS_DATA_MODE=remote`、`AGENTOPS_API_URL` 以及可选的服务端 `AGENTOPS_API_TOKEN`，然后重启。后端需要实现 README 中的 `/v1/*` 数据契约；远程列表返回数组，Trace/Span 字段参照 `lib/types.ts`。无效字段、父节点缺失或环形调用树会被拒绝。

当前 Web 没有原生 AgentOps SDK/OTLP 写入服务，不能只填写官方 SDK 密钥就开始采集。可先通过 Traces 的 JSON 导入接入规范化记录；健康检查只验证控制台的读取链路。真实实验工作台仍是独立应用，本轮没有接入它的实验执行、凭据或收费调用。

## 当前交付边界

已实现产品控制台交互、可恢复数据请求、动态刷新、SQLite 持久化、事务导入、并发版本检查、本机操作记录与基础安全响应头，并完成本地验证。公网商业上线还需要身份认证、租户隔离/RBAC、生产数据层与备份恢复、采集后端、真实告警投递、合规审计和负载测试。当前开发服务器仅绑定 127.0.0.1，用于本机演示。

工程校验：`pnpm typecheck`、`pnpm test`、`pnpm build`。Docker 构建排除本地环境文件；实际部署前要配置上述服务与访问控制。
