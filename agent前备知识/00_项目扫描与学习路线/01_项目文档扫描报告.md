| 主干 | 为什么必须学 | 项目证据状态 |

| Agent 执行模型 | 不理解状态、步骤、工具和环境，就无法定义 trace 单元 | 基础概念需系统补齐；项目中有大量实例 |

| 实验与论文方法 | 需要从 demo 转为可复现、可比较的论文证据 | `UNVERIFIED`：30–50 条最小失败闭环尚未完成 |

## 3. 项目当前最强资产

### VERIFIED

1. 文献库已覆盖观测、归因、诊断、预警、可靠性和 Agent 评价。
2. AgentSight 已在本地形成系统级执行证据：进程、文件、工具、模型调用、Token 与网络端点。
3. Watson 已完成离线流程验证和小规模真实 API demo。
4. `my_paper/metric/` 已形成任务、过程、归因、干预、开销和统计指标池。
5. `my_paper_coding/p0_pairing/` 已把请求—响应可靠配对列为 P0 门槛。

### INFERRED

项目最有辨识度的能力不是某个模型，而是“系统级证据采集—执行图—归因/诊断—复验”的纵向链路。

### UNVERIFIED

- 跨层证据是否显著优于最终输出、消息日志或 LLM judge；
- 责任 Agent、步骤、边和根因真值是否可稳定标注；
- 诊断能否减少人工排查时间或提高修复成功率；
- 跨框架、跨模型、跨任务是否仍成立。

## 4. 学习优先级判断

### P0：必须掌握

- Agent 执行循环与统一事件表示；
- 工具调用和副作用；
- 多 Agent 通信、拓扑和协调；
- 失败分类、传播与静默错误；
- trace、事件 schema、证据关联；
- Agent/Step/Edge 级归因与反事实；
- 成功、进展、稳定性、归因和开销指标；
- 可复现实验与真值构造。

### P1：重点补齐

- Linux/WSL2、进程树、文件与网络边界；
- HTTP/TLS、SQLite、时间戳与并发；
- MCP、Skill/Plugin、权限边界；
- OpenTelemetry 与 eBPF 的作用边界；
- 安全、隐私、审计和最小权限；
- 统计检验、置信区间、效应量和标注一致性。

### P2：按论文方案深入

- LLM 内部机理和训练细节；
- 完整结构因果模型、Shapley 值等高级因果方法；
- 大规模分布式推理与 GPU 调度；
- 在线预警、自适应采样和自治修复。

## 5. 扫描后的结论

项目材料已经足够支持一条定向学习路线，但不适合按“逐篇论文”学习。更有效的方式是按同一问题的证据链学习：

```text
一个任务怎样运行？
→ 在哪里可能失败？
→ 什么信号能看见失败？
→ 如何把信号组成执行图？
→ 怎样证明某个 Agent/步骤/边有责任？
→ 如何评价诊断是否可靠且值得付出观测成本？
```

下一研究闸门：学习到第 11 章后，用一个真实 `session.db` 完成“事件抽取—配对—执行图—候选根因报告”；到第 12 章后，再决定是否进入 30–50 条失败 trace 的最小论文闭环。
