# 第 12 章详细教程：把工程问题变成可检验的论文

## 1. 从兴趣到研究问题

兴趣：“我想研究 Agent 故障诊断。”

不可检验问题：“怎样让 Agent 更可靠？”

可检验问题：

> 在带工具调用和多轮协作的 LLM 多智能体任务失败中，加入系统层进程/文件/网络证据，是否比只使用消息日志更准确地定位决定性错误步骤？代价是多少？

它明确了对象、干预、比较、结果和成本。

## 2. RQ 六要素逐项写

```text
Object       研究什么系统或行为？
Intervention 引入什么方法或改变？
Measurement  用什么证据判断有效？
Baseline     与谁比较？
Boundary     在哪里不主张成立？
Mechanism    为什么可能有效？（建议额外写）
```

教学填写：

| 要素 | 示例 |
|---|---|
| Object | 2–3 个 MAS 框架中的工具与通信失败 |
| Intervention | 跨层执行图 + 候选排序 + 局部重放 |
| Measurement | Step Top-1/MRR、证据完整率、延迟 |
| Baseline | output-only、message-only、最后错误、强 LLM |
| Boundary | 可获取执行证据、可重放的受控任务 |
| Mechanism | 系统副作用补足消息日志遗漏，重放排除伪相关 |

## 3. Claim–Evidence：论文的骨架

错误写法：

> 本系统能准确定位多智能体根因。

改写：

| ID | Claim | 需要证据 | 当前状态 |
|---|---|---|---|
| C1 | 跨层 trace 能覆盖消息日志遗漏的副作用 | 事件覆盖审计 | 未验证 |
| C2 | 完整 trace 提高 step-level 归因 | 四档证据消融 | 未验证 |
| C3 | 反事实重放减少伪阳性 | 有/无 replay 消融 | 未验证 |
| C4 | 额外成本可接受 | 时间、CPU、存储、隐私成本 | 部分具备 |

每一个主张都要能对应一张表、一个图、一个定性分析或明确限制。

## 4. 文献综述不是逐篇摘要

系统综述流程可参考 Kitchenham 的软件工程综述指南；它强调规划、执行和报告三阶段。你的综述问题可以是：

> 现有 Agent 故障分析工作在哪个观测层采集什么信号，以什么责任粒度归因，并用什么真值和干预验证？

比较轴：

| 论文 | 观测层 | 粒度 | 在线/离线 | 真值 | 反事实 | 开销 |
|---|---|---|---|---|---|---|
| AgentSight | 系统边界 | 进程/文件/网络 | 在线采集 | 案例事实 | 否 | 报告 |
| Who&When | 执行日志 | Agent/Step | 离线 | 人工/构造 | 定义层 | 非主项 |
| EDGE | 错误依赖图 | 多错误/边 | 离线+重放 | 反事实 | 是 | 待核验 |
| Watson | 认知重建 | 推理轨迹 | 旁路 | judge/统计 | 局部 | 成本需审计 |

最终段落应比较能力缺口，而非“一篇一段”。

## 5. Demo、Pilot 与主实验

### Demo

证明流程能运行。例如 AgentSight 捕获到进程、文件和模型事件。

### Pilot

用小样本验证实验设计、标签协议、方差和成本是否可行。

### 主实验

按预注册方案回答 RQ，包含足量样本、基线、重复、统计和限制。

项目当前 13/13 与 Watson 小样例属于复现/流程证据，不能直接回答跨层归因是否更准。

## 6. 最小闭环为什么是 30–50 条

这是当前规划中的 pilot 规模，不是通用统计定律。作用是尽早发现：

- 失败是否能稳定触发；
- 真值是否可标；
- schema 是否缺字段；
- 方法是否有初步区分度；
- 单样本成本是否可承担。

主实验样本量应根据 pilot 方差、效应量目标和统计功效重新决定。

## 7. 一个端到端实验设计

### RQ

完整跨层证据是否提高 step-level 归因？

### 任务

文件分析、API 查询、协作写作三类。

### 故障

工具静默错误、handoff 丢失关键字段、控制流提前停止。

### 真值

确定性注入位置 + clean/faulty 成对轨迹 + 局部修复重放。

### 证据档

```text
D0 最终输出
D1 消息/工具日志
D2 D1 + 进程/文件/网络证据
D3 D2 + 反事实结果
```

### 基线

最后错误、最早错误、LLM 读消息、LLM 读全 trace。

### 指标

Step Top-1/MRR、Agent Top-1、证据完整率、诊断时间、日志字节。

### 关键威胁

注入痕迹泄漏标签；同一模板进入训练和测试；重放环境漂移；LLM judge 与诊断模型共享偏差。

## 8. 威胁有效性

### Construct validity

“根因”标签是否真的表示可修复原因，还是只表示最早错误？

### Internal validity

准确率提升是否来自更多答案信息、模型升级或实验顺序？

### External validity

结果能否推广到其他框架、模型、任务和真实自然故障？

### Conclusion validity

样本量、方差、统计方法和多重比较是否支持结论？

## 9. 可复现研究清单

[NeurIPS Paper Checklist](https://neurips.cc/public/guides/PaperChecklist)强调主张、限制、实验复现、数据代码、伦理和社会影响。[ACM SIGSOFT Empirical Standards](https://www2.sigsoft.org/EmpiricalStandards/)提供软件工程不同研究方法的证据期望。

至少保存：

- 代码 commit 与依赖版本；
- 模型/服务版本和调用参数；
- 任务、故障注入与排除规则；
- 原始数据和派生脚本；
- 标签协议和分歧；
- 主次指标与统计脚本；
- 所有失败运行，而非只留成功样本。

## 10. Go/No-Go 的真实意义

Go 不是“结果必须好”，而是：问题可测、数据可信、方法差异可解释。

No-Go 也不是研究失败。如果跨层证据没有提升，仍可能支持实证结论：哪些信号冗余、哪些观测成本不值得、哪些失败无法从 trace 归因。但需要预先允许负结果，而不是事后换主指标。

## 11. 答案要点

- 好 RQ 同时规定对象、干预、比较、测量和边界。
- 先建立 Claim–Evidence 表，再写结论措辞。
- Demo 证明可运行，主实验才评价有效性。
- Pilot 规模用于校准设计，不能机械充当主实验依据。
- 负结果也可有价值，但不能靠事后改问题包装。
