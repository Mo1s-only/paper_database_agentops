# 第 12 章：论文研究方法与课题衔接

本章正文：[详细教程](详细教程.md)；学习后完成：[练习与验收](练习与验收.md)；最后对照：[练习与验收答案](练习与验收答案.md)。

## 本章定位

把技术学习转化为一个可答辩、可复现、可被反驳的研究问题。本章不要求同时完成五个候选方向，而是用最小证据决定主线。

## 当前 RQ 草案

在多智能体任务失败时，能否利用跨层、可追溯的执行轨迹，可靠识别责任 Agent、责任步骤和根因类型，并在观测成本受限时保持可接受的诊断准确率与延迟？

## 研究问题六要素

| 要素 | 当前内容 |
|---|---|
| Object | 有消息传递、工具调用和多轮协作的 LLM MAS |
| Intervention | 跨层事件采集、执行图、候选归因、反事实验证 |
| Measurement | Agent/Step/Edge 归因、证据完整率、延迟、开销 |
| Baseline | 最终输出、消息日志、规则/时序、现有图或 LLM 方法 |
| Boundary | 不解决无任何证据的黑盒系统，不等同自动修复 |
| Evidence | 失败 trace、责任真值、消融、反事实复验 |

## 可能贡献

1. **方法**：跨层执行证据模型或可验证诊断算法。
2. **基准**：含完整轨迹、责任步骤/边和根因标签的数据集。
3. **实证**：证据粒度、缺失和成本如何影响归因效果。
4. **系统**：可重复采集、关联和诊断的 AgentOps 原型。

至少应形成两种互相支撑的贡献；仅把 AgentSight、Who&When 和 Watson 串联，容易被认为是工程拼接。

## 最小实验矩阵

| 维度 | 最小设置 |
|---|---|
| 框架 | 2–3 个可复现实验框架 |
| 故障 | 至少 3 类：工具、通信/传播、控制流或模型步骤 |
| 样本 | 先做 30–50 条带可信真值的失败 trace |
| 证据档 | 最终输出 / 消息 / 完整轨迹 / 轨迹+反事实 |
| 真值 | 可执行判据 + 人工标注 + 分歧处理 |
| 指标 | Agent/Step/Edge、F1/MRR、完整率、延迟、开销 |
| 对照 | 无方法、强基线、关键消融 |
| 统计 | 重复、区间、效应量、失败与排除规则 |

## Go / No-Go

### Go

- 配对与 schema 稳定；
- 责任真值可复核；
- 完整证据相对弱证据产生稳定、非泄漏的增益；
- 反事实能验证至少一部分候选根因；
- 观测成本可报告且可接受。

### No-Go / 转向

- 长期无法可靠配对或构造可信标签；
- 增加跨层证据没有稳定增益；
- 贡献只剩工具拼接；
- 实验规模无法支持方法主张。

此时可转向“预算约束下的自适应可观测性”或“AgentOps 观测信号实证研究与指标校准”。
