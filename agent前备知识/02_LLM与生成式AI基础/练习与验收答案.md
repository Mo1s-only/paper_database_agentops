# 练习与验收答案：LLM 与生成式 AI 基础

> 参考解强调可复现实验。任何输出样例均为教学示例，不代表某个模型的实测结论。

## 一、练习参考解

### 1. 同提示重复实验

建议固定一个任务，例如“从故障日志中抽取根因类别并输出 JSON”，至少运行 10 次，而不是只比较两次。

| 字段 | 示例记录 |
|---|---|
| model/provider/version | 必须写完整；未知则记 `UNVERIFIED` |
| prompt_hash | 规范化提示的 SHA-256 |
| temperature/top_p/seed | 不支持的参数明确记 `unsupported` |
| context_hash | 系统提示、历史、检索内容的组合摘要 |
| output_hash | 原始输出摘要 |
| input/output tokens | 从 API usage 获取，不用字符数冒充 |
| latency_ms | 单调时钟测量 |
| schema_valid | 布尔值及错误路径 |

结果分析至少报告：完全一致率、语义一致率、schema 合法率、任务正确率和延迟分布。即使温度为 0，也不能预设完全确定；服务端版本、浮点并行、路由和隐藏提示都可能变化。

### 2. 结构化输出 schema 与失败样例

```json
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "properties": {
    "label": {"enum": ["tool", "model", "environment", "unknown"]},
    "confidence": {"type": "number", "minimum": 0, "maximum": 1},
    "evidence_ids": {
      "type": "array", "items": {"type": "string"}, "uniqueItems": true
    },
    "rationale": {"type": "string", "minLength": 1}
  },
  "required": ["label", "confidence", "evidence_ids", "rationale"],
  "additionalProperties": false
}
```

| 故障 | 输入片段 | 应判定 |
|---|---|---|
| 缺字段 | `{"label":"tool"}` | schema invalid：缺 `confidence/evidence_ids/rationale` |
| 类型错 | `"confidence":"high"` | schema invalid |
| 截断 | `{"label":"tool",` | JSON parse error，尚未进入 schema 校验 |
| 额外文本 | `答案如下：{...}` | 严格 JSON parse error |
| 越界 | `"confidence":1.2` | schema invalid |
| 幻觉证据 | 合法 JSON 但 ID 不存在 | 语义/引用完整性失败，不是 schema 失败 |

关键点：解析正确、schema 正确、引用存在、任务正确是四个不同门槛。

### 3. 规则、LLM judge、人工评审

| 评审器 | 优点 | 主要风险 | 适用范围 |
|---|---|---|---|
| 确定性规则 | 便宜、可复现 | 覆盖不了语义 | 格式、字段、精确条件 |
| LLM judge | 能评开放文本 | 偏好、位置、同源模型偏差 | 规模化初筛 |
| 人工评审 | 能处理语境 | 成本、疲劳、分歧 | 金标准子集与争议样本 |

专业流程：先用规则过滤硬失败；对语义指标设计有锚点的 rubric；两名人工对盲化样本独立标注并报告一致性；用人工金标准校准 judge 的准确率、偏差和置信区间。不能让 judge 的解释文本代替其有效性证据。

### 4. 自然语言到结构化记录

教学输入：“工具已经返回成功，但生成的 report.md 是空文件。”

```json
{
  "label": "tool",
  "confidence": 0.82,
  "evidence_ids": ["tool_call:C17", "file_event:F9"],
  "rationale": "调用状态成功，但目标文件大小为 0，属于显式状态与副作用不一致。"
}
```

实验表必须同时保留原始文本、原始模型输出、解析错误、schema 错误、引用校验结果和最终任务判断。只记录“解析成功”会掩盖语义错误。

## 二、验收问题参考答案

1. **固定提示为何仍不稳定？** 提示只是输入的一部分；模型版本、采样、服务端路由、隐藏上下文、工具返回和数值计算都可能变化。可复现性应描述控制了哪些变量，而非承诺位级一致。
2. **应记录哪些上下文？** 系统/用户提示、消息顺序、检索片段、工具 schema 与结果、记忆快照、模型标识、参数、时间、软件版本和请求 ID；敏感内容可以加密保存并另存不可逆摘要。
3. **judge 为什么只是代理？** 它测量的是 rubric 下的模型判断，不是真实世界效用本身。必须与人工金标准、环境成功条件或可执行测试建立效标关系。
4. **token 减少为何不等于系统成本降低？** 可能增加调用次数、延迟、失败重试、工具 I/O 或人工复核。应报告端到端成本：模型费、计算、存储、网络、尾延迟与人工时间。

## 三、评分标准（100 分）

重复实验 25 分；schema 与负例 25 分；三类评审器比较 20 分；完整数据记录 20 分；证据边界 10 分。若把 JSON 合法率等同任务正确率，最高 60 分。
