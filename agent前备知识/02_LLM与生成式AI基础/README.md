# 第 2 章：LLM 与生成式 AI 基础

本章正文：[详细教程](详细教程.md)；学习后完成：[练习与验收](练习与验收.md)；最后对照：[练习与验收答案](练习与验收答案.md)。

## 本章定位

Agent 不是单纯的 LLM，但 LLM 是其不确定决策核心。需要理解模型调用的输入、输出和随机性，才能区分“模型能力问题”与“Agent 编排问题”。

## 学习目标

- 理解 Token、上下文窗口、系统/用户/工具消息和缓存。
- 理解自回归生成、temperature、top-p、停止条件和非确定性。
- 理解提示词、few-shot、结构化输出、解析与重试。
- 区分模型知识、外部检索、工具返回和运行时状态。
- 理解幻觉、上下文污染、长上下文退化和 judge 偏差。

## 核心知识

### 1. 一次模型调用的最小记录

至少记录：模型与版本、消息/Prompt、采样参数、工具定义、响应、Token、缓存、延迟、状态码、重试和调用标识。缺少这些字段时，不应声称两次运行可严格复现。

### 2. 输出正确不等于过程正确

模型可能用错误理由得到正确答案，也可能推理合理但因解析器或工具失败导致任务失败。论文需同时观察结果、过程和系统副作用。

### 3. 结构化输出

JSON、表格、代码或领域协议可降低传输和解析成本，但会带来 schema 不匹配、截断、转义和版本兼容问题。结构化并不自动等于真实或安全。

### 4. LLM-as-a-Judge

Judge 适合提供辅助评价，但不能天然成为真值。需要校准、重复评判、人类一致性或可执行判据补强，并报告模型、提示和偏差。

## 不必先深挖

Transformer 的完整数学推导、预训练集群优化和大模型微调不是当前主线的先决条件。先掌握它们如何影响 Agent 行为、记录和评测，再按论文需要深入。

## 本章完成标准

看到一次 Agent 失败时，能提出至少三类竞争解释：模型生成错误、上下文/提示错误、Agent 编排或工具链错误，并说明需要什么证据区分它们。
