# 第 4 章详细教程：模型怎样安全地使用工具

## 1. 工具调用不是“模型执行了函数”

模型通常只生成一个结构化的**调用建议**：

```json
{
  "name": "read_file",
  "arguments": {"path": "report.md"}
}
```

真正执行流程是：

```text
模型生成调用建议
→ Agent 控制器解析
→ schema 校验
→ 权限检查
→ 工具进程/API 执行
→ 返回结果
→ Agent 将结果加入状态或上下文
```

任何一层都可能失败。[Toolformer](https://arxiv.org/abs/2302.04761)研究模型学习“是否、何时、如何调用 API”；工程系统还必须解决执行、权限和审计。

## 2. 一个好工具契约长什么样

以只读文件工具为例：

```json
{
  "name": "read_text_file",
  "description": "读取工作区内 UTF-8 文本文件",
  "inputSchema": {
    "type": "object",
    "properties": {
      "path": {"type": "string"},
      "max_bytes": {"type": "integer", "minimum": 1, "maximum": 1048576}
    },
    "required": ["path"],
    "additionalProperties": false
  }
}
```

还应在实现或政策中说明：

- 路径相对哪个根目录；
- 是否允许符号链接；
- 文件不存在和权限不足如何表示；
- 是否读取二进制；
- 内容是否脱敏；
- 最大大小和超时；
- 调用是否可重试。

只写 JSON Schema 还不足以表达全部业务约束。

## 3. 六类工具错误

### 3.1 选择错误

应查数据库却调用网页搜索。根因在策略或工具描述。

### 3.2 参数错误

```json
{"path":"../secret.env"}
```

可能类型合法，但越出授权根目录。需要语义和权限校验。

### 3.3 显式执行错误

工具返回 `permission_denied`、HTTP 500 或异常。容易检测，但还要决定是否重试。

### 3.4 静默错误

工具返回格式正常、状态成功，但数值或内容错误。[Tools Fail](https://aclanthology.org/2024.emnlp-main.790/)特别研究这类问题。

教学例子：坏计算器收到 `15 × 58`，返回 `8702` 且 `ok=true`。仅检查状态码无法发现，需要冗余计算、范围约束或后续事实验证。

### 3.5 结果解释错误

工具正确返回“3 条失败记录”，模型却解释为“3 次成功”。证据在 tool output 与下一步决策之间。

### 3.6 副作用错误

工具声称已写文件，但路径错误、写入一半、被覆盖或产生重复操作。

## 4. 重试与幂等

### 4.1 只读调用

读取文件或查询状态通常可以安全重试，但也要考虑数据在两次读取间发生变化。

### 4.2 有副作用调用

“发送邮件”“扣款”“删除文件”不能盲目重试。

```text
请求发送邮件 → 客户端超时 → 实际服务端已发送
→ Agent 重试 → 用户收到两封邮件
```

解决思路：

- 使用 idempotency key；
- 查询操作状态后再重试；
- 把 prepare 与 commit 分离；
- 高风险动作要求人工确认；
- 提供补偿操作，但不要误以为补偿总能完全回滚。

## 5. MCP 的位置

[MCP 官方规范概览](https://modelcontextprotocol.io/specification/draft/server/index)把服务器能力分成：

- Prompts：用户控制的模板；
- Resources：应用控制的上下文资源；
- Tools：模型可选择调用的动作或查询。

简化架构：

```text
用户
 ↓
Host 应用（管理模型、同意和 UI）
 ↓
MCP Client（协议连接）
 ↓  stdio / Streamable HTTP
MCP Server（暴露 tools/resources/prompts）
 ↓
文件、数据库、Git、外部 API
```

MCP 标准化的是能力发现和调用协议，不自动保证工具安全、结果正确或 Agent 规划合理。

## 6. Function Calling、MCP、Skill、Plugin 的区别

| 概念 | 解决的问题 | 本身是否执行动作 |
|---|---|---|
| Function Calling | 让模型输出满足函数 schema 的调用意图 | 否，控制器执行 |
| Tool | 一项可调用能力 | 由实现决定 |
| MCP | 客户端与能力服务器的标准协议 | 协议本身不做业务动作 |
| Skill | 可复用的任务说明、流程和资源 | 通常指导 Agent 调工具 |
| Plugin | 打包技能、工具、应用或配置的分发单元 | 取决于包含能力 |
| Agent | 根据目标和状态选择动作的执行主体 | 通过工具形成副作用 |

## 7. 教学案例：安全的写报告工具

需求：Agent 只能在 `reports/` 下创建新 Markdown，不能覆盖。

### 输入契约

```json
{
  "path": "reports/run-17.md",
  "content": "# Report\n...",
  "expected_absent": true,
  "idempotency_key": "run-17-report-v1"
}
```

### 执行前

1. 规范化绝对路径；
2. 验证路径仍位于允许根目录；
3. 拒绝符号链接逃逸；
4. 检查文件不存在；
5. 记录 principal、run_id、step_id。

### 执行后

1. 返回内容哈希和字节数；
2. 从文件系统重新读取并核验；
3. 写审计事件；
4. Agent 再验证报告结构。

这将“模型意图、工具执行、环境事实、任务验证”分为四层。

## 8. 工具观测事件

建议一次调用至少生成：

```json
{
  "call_id": "C17",
  "run_id": "R3",
  "agent_id": "writer",
  "step_id": "S5",
  "tool": "write_report",
  "tool_version": "1.2",
  "input_hash": "...",
  "start_time": "...",
  "end_time": "...",
  "status": "success",
  "retry_of": null,
  "side_effects": [{"type":"file_write","path":"reports/run-17.md","hash":"..."}]
}
```

敏感原始输入可单独加密或不保存；哈希只能用于完整性和同一性判断，不能恢复语义。

## 9. 实践与答案要点

### 实践

为“删除临时实验目录”设计工具，但先不要实现：写 schema、权限、预览、审批、幂等、审计、失败和恢复协议。

### 答案要点

- 模型生成的是调用意图，执行由外部系统完成。
- schema 校验不能替代权限和业务校验。
- 静默错误需要独立预期或环境验证。
- 写操作必须考虑超时后实际已成功的情况。
- MCP 解决互操作，不自动解决可靠性与安全。
