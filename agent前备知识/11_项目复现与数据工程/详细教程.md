# 第 11 章详细教程：亲手把运行证据变成可研究数据

## 1. 复现不等于“命令跑通”

一次完整复现至少回答：

```text
运行了什么版本？
在什么环境？
输入与配置是什么？
产生了哪些原始数据？
怎样从原始数据得到报告？
成功判据是什么？
哪些结论仍不能支持？
```

ACM 的 [Artifact Review and Badging](https://prod-www.acm.bloomreach.cloud/publications/policies/artifact-review-badging-current)区分工件可用、可复现结果等层次；不要把“工件可运行”写成“论文主张已验证”。

## 2. 本项目证据层次

```text
原始运行
├─ raw-stream.log
├─ record.log
├─ claude-run.log
└─ session.db / -wal / -shm
      ↓
派生报告
├─ db-rows.txt
├─ report-audit.txt
├─ report-prompts.txt
└─ report-token.txt
      ↓
实验总结
└─ 实验结果.md
      ↓
论文表格/结论
```

每一层都应能追溯到上一层，不能手工复制数字后丢掉来源。

## 3. 先做只读数据库审计

本项目已有：

```text
lab/agentsight/results/upstream/session/session.db
```

查看表：

```powershell
sqlite3 "lab\agentsight\results\upstream\session\session.db" ".tables"
```

当前样例含：

```text
audit_events, llm_calls, network_targets, process_nodes,
resource_samples, token_usage, tool_calls
```

这是 `VERIFIED` 的本地样例事实，但表结构未来可能变化，任何脚本都应先做 schema/version 检查。

## 4. 实际 SQL：进程树

```sql
SELECT
  id, pid, ppid, comm, command,
  start_timestamp_ms, end_timestamp_ms,
  status, exit_code, confidence
FROM process_nodes
ORDER BY start_timestamp_ms;
```

本地样例中 Claude 主进程 PID 为 348，多个 `git`、`reg.exe` 等子进程以它为父进程。不要因此把所有子进程失败都等同任务失败；要看它们是否位于关键路径。

## 5. 实际 SQL：工具调用

```sql
SELECT
  id, timestamp_ms, tool_name, tool_call_id,
  status, related_pid, related_event_id,
  duration_ms, confidence
FROM tool_calls
ORDER BY timestamp_ms;
```

当前样例记录了 Write 与 Read，`related_pid=348`，但置信度约 0.35。教学含义：数据库“有一行”不代表关联高可信；后续分析应传播置信度或设置质量门槛。

## 6. 实际 SQL：LLM 请求和响应质量

```sql
SELECT
  id, pid, comm, provider, model, status,
  CASE WHEN request_body_json IS NULL OR request_body_json = ''
       THEN 0 ELSE 1 END AS has_request,
  CASE WHEN response_body_json IS NULL OR response_body_json = ''
       THEN 0 ELSE 1 END AS has_response,
  confidence
FROM llm_calls
ORDER BY start_timestamp_ms;
```

本地这个数据库的三条 LLM 行在字段层面同时有 request/response，但 ID 仍包含 `orphan`，置信度约 0.35。它非常适合说明：

```text
字段非空 ≠ 请求响应已被可靠证明属于同一次调用
```

配对质量需要独立真值和协议级关联证据。

## 7. Token 与调用关联

```sql
SELECT
  t.llm_call_id,
  l.model,
  t.input_tokens,
  t.output_tokens,
  t.cache_read_tokens,
  t.total_tokens,
  t.confidence
FROM token_usage t
LEFT JOIN llm_calls l ON l.id = t.llm_call_id
ORDER BY t.timestamp_ms;
```

检查：

- 是否有 token 行找不到 LLM call；
- 一个 call 是否出现多个互相矛盾的统计；
- `total_tokens` 是否与分项逻辑一致；
- 来源是网络观测还是 Agent 原生日志。

## 8. 可靠配对怎样建立真值

### 唯一 marker 方法

为每个请求加入随机但不敏感的 `pairing_marker`：

```text
PAIR_20260924_A7F3
```

在受控环境中检查 request、response、原生日志和捕获事件是否都包含可追踪关联。marker 只用于实验，不能进入真实用户数据。

### 标注表

| request_event | response_event | true_pair | evidence | ambiguity |
|---|---|---:|---|---|
| req-1 | resp-3 | 1 | request_id + marker | none |
| req-2 | resp-2 | 0 | different stream | retry present |

然后计算 Precision/Recall，而不是只报告“看起来能配上”。

## 9. 从数据库到统一 schema

映射表示例：

| 原表字段 | 统一字段 | 变换 | 风险 |
|---|---|---|---|
| `process_nodes.pid` | `source_process.pid` | 直接 | PID 仅本次主机有效 |
| `tool_calls.related_pid` | `source_process.pid` | 直接 | confidence 可能低 |
| `llm_calls.start_timestamp_ms` | `timestamp_start` | 单位归一 | 时钟域未必显式 |
| `audit_events.target` | `object_ref` | 路径脱敏 | 可能丢语义 |
| `token_usage.llm_call_id` | `parent_event_id` | 关联 | 需检查悬空键 |

映射表本身是论文工件，应版本化并测试。

## 10. 运行 AgentSight 的学习顺序

1. 阅读 [快速复现指南](../../lab/agentsight/快速复现AgentSight.md)。
2. 只执行 `-PreflightOnly`，不调用模型。
3. 查看历史实验和真实 schema。
4. 明确预算、凭据和归档路径后再运行。
5. 每次生成唯一 experiment_id，禁止覆盖旧结果。
6. 运行验证，并记录失败断言。
7. 写“能证明/不能证明”报告。

## 11. Watson 的正确学习边界

Watson 流程可用于学习旁路重建、候选、judge 和汇总，但：

- FakeClient 实验只验证控制流；
- 两个真实 demo 不代表通用准确率；
- 重建文本不等于模型内部真实思维；
- 不完整 request/response 不应强行进入重建。

## 12. 研究数据的 FAIR 化

[FAIR 原则](https://www.nature.com/articles/sdata201618)强调 Findable、Accessible、Interoperable、Reusable。映射到本项目：

- Findable：唯一 experiment_id、索引和元数据；
- Accessible：明确访问权限和路径；
- Interoperable：统一 schema、单位和枚举；
- Reusable：版本、许可、来源、运行命令和限制。

FAIR 不等于全部公开；敏感数据可以受控访问，但元数据和治理应清晰。

## 13. 最小实验包

```text
experiment_id/
├── README.md              # 目的、环境、命令、结论边界
├── manifest.json          # 文件哈希与大小
├── config/                # 脱敏配置
├── raw/                   # 原始不可变数据
├── derived/               # 清洗/映射结果
├── labels/                # 标签、协议、分歧
├── scripts/               # 可重复处理代码
└── report/                # 表格、图和结果
```

原始数据保持不可变；修正通过新派生版本完成。

## 14. 答案要点

- 可运行只是复现的起点，不是论文有效性结论。
- 原始、派生、标签和报告必须保持数据血缘。
- 数据库行非空不等于关联可靠。
- 配对指标需要独立真值集。
- 每份实验报告都应明确支持和不支持的主张。
