# 练习与验收答案：项目复现与数据工程

> 本章 SQL 依据本项目 `lab/agentsight/results/upstream/session/session.db` 的实际 schema 编写（`VERIFIED`）。查询结果须由学习者在自己的数据库副本上运行后填写；本文不伪造计数。

## 一、完整性与哈希清单

PowerShell 示例：

```powershell
Get-ChildItem -LiteralPath 'lab/agentsight/results/upstream/session' -File |
  Get-FileHash -Algorithm SHA256 |
  Select-Object Path, Algorithm, Hash
```

清单还应记录字节数、修改时间、采集主机/时区、SQLite 版本、生成命令和 Git commit。若数据库仍在 WAL 模式且正在写入，不能分别复制不同瞬间的 `.db/.db-wal/.db-shm`；优先停止写入后调用 backup API，再对备份计算哈希。哈希证明“内容未变化”，不证明“内容真实完整”。

## 二、统一时间线 SQL

```sql
WITH timeline AS (
  SELECT start_timestamp_ms AS ts, 'process_start' AS event_type,
         id AS event_id, pid, comm, status,
         printf('ppid=%s argv=%s', ppid, argv_json) AS detail
  FROM process_nodes
  UNION ALL
  SELECT start_timestamp_ms, 'tool_call', id, related_pid, tool_name, status,
         printf('call_id=%s duration=%s', tool_call_id, duration_ms)
  FROM tool_calls
  UNION ALL
  SELECT start_timestamp_ms, 'llm_call', id, pid, comm, status,
         printf('provider=%s model=%s path=%s', provider, model, path)
  FROM llm_calls
  UNION ALL
  SELECT timestamp_ms, 'audit:' || audit_type, id, pid, comm, status,
         printf('%s %s %s', action, target, summary)
  FROM audit_events
  UNION ALL
  SELECT first_timestamp_ms, 'network', id, pid, comm,
         CASE WHEN error_count > 0 THEN 'has_error' ELSE 'observed' END,
         printf('host=%s path=%s count=%s errors=%s', host, path, count, error_count)
  FROM network_targets
  UNION ALL
  SELECT timestamp_ms, 'token_usage', id, pid, comm, 'observed',
         printf('llm=%s in=%s out=%s total=%s', llm_call_id,
                input_tokens, output_tokens, total_tokens)
  FROM token_usage
)
SELECT * FROM timeline WHERE ts IS NOT NULL ORDER BY ts, event_type, event_id;
```

该时间线是“观测事件总表”，不是因果链。`network_targets` 是聚合记录，`first_timestamp_ms` 不能冒充每一次网络请求的精确时刻。

## 三、数据质量查询

```sql
-- 1. 名称标记为 orphan 或请求/响应缺失的 LLM 记录。
SELECT id, start_timestamp_ms, provider, model,
       request_body_json IS NULL AS missing_request,
       response_body_json IS NULL AS missing_response,
       confidence
FROM llm_calls
WHERE lower(id) LIKE '%orphan%'
   OR request_body_json IS NULL
   OR response_body_json IS NULL;

-- 2. 工具调用缺少关联键/结果。
SELECT id, tool_name, tool_call_id, related_pid, related_event_id,
       output_json, confidence
FROM tool_calls
WHERE tool_call_id IS NULL OR output_json IS NULL
   OR (related_pid IS NULL AND related_event_id IS NULL);

-- 3. 可能重复的工具记录。这里只生成候选，不能直接删除。
SELECT tool_call_id, tool_name, COUNT(*) AS n,
       MIN(start_timestamp_ms) AS first_ms, MAX(start_timestamp_ms) AS last_ms
FROM tool_calls
GROUP BY tool_call_id, tool_name
HAVING COUNT(*) > 1;

-- 4. token 行指向不存在的 LLM 调用。
SELECT t.* FROM token_usage t
LEFT JOIN llm_calls l ON l.id = t.llm_call_id
WHERE t.llm_call_id IS NOT NULL AND l.id IS NULL;

-- 5. PID 找不到有效生命区间内的进程记录。
SELECT t.id, t.related_pid, t.start_timestamp_ms
FROM tool_calls t
LEFT JOIN process_nodes p
  ON p.pid=t.related_pid
 AND p.start_timestamp_ms<=t.start_timestamp_ms
 AND (p.end_timestamp_ms IS NULL OR p.end_timestamp_ms>=t.start_timestamp_ms)
WHERE t.related_pid IS NOT NULL AND p.id IS NULL;
```

项目样本中出现过 `orphan` 标识且请求/响应列同时非空的记录（`VERIFIED`）。这说明“payload 非空”不等于“配对可靠”；应综合 ID、采集来源和 `confidence`。

## 四、原始表到统一 schema

| 目标字段 | 原始来源 | 变换 | 置信度依据 |
|---|---|---|---|
| `event.id` | 各表 `id` | 加来源前缀 | 原生主键高 |
| `event.type` | 表名/audit_type | 枚举映射 | 确定性 |
| `event.time` | `timestamp_ms/start_timestamp_ms` | 保留原值和时钟域 | 原生但可能漂移 |
| `actor.process` | `pid,comm` | 联结进程生命区间 | 显式 PID 中高 |
| `parent.id` | `related_event_id/llm_call_id` | 不存在则留空 | 显式键高、时间推断低 |
| `artifact.ref` | target/path/body | 规范化+哈希 | 内容可核验中高 |
| `provenance` | `view_source/source` | 原样保留 | 必填 |
| `confidence` | 原字段/规则 | 记录方法版本 | 不得凭感觉填写 |

任何推断连接应另存 `link_method`、候选数和分数；不要覆盖原始 ID。统一表采用 append-only，纠错以新版本/补丁表达。

## 五、可证明与不可证明报告

**可证明（在数据完整且 schema 语义成立的前提下）**：某 PID 在某时间段被观测；某工具记录声明了状态；某 token 行显式引用某 `llm_call_id`；某文件快照具有给定哈希。

**不可单凭当前数据证明**：模型内部为何选择动作；未记录的系统调用不存在；最近时间的请求与响应必然配对；某最早异常是根因；`status=success` 代表用户任务成功。

## 六、验收问题参考答案

1. **“13/13”支持什么？** 若定义为 13 个预设样本全部复现，它支持该有限样本上的复现成功率；不自动支持跨版本、跨机器或总体 100% 成功。应给分母、样本选择与置信区间。
2. **两个报告不一致怎么办？** 先冻结原始输入和版本，比较 schema、过滤、时区、去重、联结和缺失处理；生成逐行差分与 lineage。不能用“选看起来合理的数字”解决。
3. **什么是 lineage？** 数据从采集源经清洗、联结、特征和聚合到结论的可追踪链，包含代码版本、参数、输入输出哈希和执行时间。
4. **Precision=.95 的分母和真值？** `TP/(TP+FP)`，分母是算法判为配对的链接；TP 需要独立金标准（协议 request id、人工双标等）。用同一时间匹配规则生成“真值”再评它会循环论证。
