# 总验收清单

## A. Agent 基础

- [ ] 能用自己的话定义 Agent，并与 LLM 调用和固定工作流区分。
- [ ] 能画单 Agent 状态机和 operation tree。
- [ ] 能区分 context、state、memory 和 external knowledge。
- [ ] 能解释停止、重试、反思、回滚和人工介入。

## B. 工具与多 Agent

- [ ] 能写出工具 schema、错误模型、幂等策略和权限边界。
- [ ] 能区分 Function Calling、MCP、Skill、Plugin 和 Agent。
- [ ] 能比较常见 MAS 拓扑的性能、成本和故障模式。
- [ ] 能写出完整 handoff 契约。

## C. 失败与观测

- [ ] 能区分 fault、error、failure、incident。
- [ ] 能为失败标注结果、步骤、Agent、交互和系统层原因。
- [ ] 能区分日志、指标、追踪、Span 和事件。
- [ ] 能解释应用插桩、代理、原生日志和 eBPF 边界追踪。
- [ ] 能设计统一事件 schema，并处理缺失、重复和不确定关联。

## D. 归因与诊断

- [ ] 能区分异常检测、归因、根因诊断和自动修复。
- [ ] 能分别做 Agent、Step、Tool、Message、Edge 级归因。
- [ ] 不会把时序相邻、通信连接或父子 Span 直接当成因果。
- [ ] 能设计可执行反事实或局部重放。
- [ ] 能处理多个原因和责任传播链。

## E. 评价与实验

- [ ] 能选择结果、过程、稳定性、归因、系统和成本指标。
- [ ] 能计算并解释 Top-k、MRR、宏/微 F1、置信区间和效应量。
- [ ] 能设计无方法基线、强基线和关键消融。
- [ ] 能说明真值、分母、排除规则和重复次数。
- [ ] 不把 LLM judge、单次成功或 demo 当作论文级有效性证据。

## F. 项目实践

- [ ] 能解释 AgentSight 13/13 支持和不支持的结论。
- [ ] 能查询 `session.db` 并重建关键时间线。
- [ ] 能识别 `orphan_response` 和不可靠配对。
- [ ] 能说明 Watson 离线流程与真实 demo 的边界。
- [ ] 能保存环境、版本、配置、原始数据、派生数据和报告血缘。
- [ ] 能完成 trace 脱敏与发布检查。

## G. 论文衔接

- [ ] 有明确 RQ/Object/Intervention/Measurement/Baseline/Boundary。
- [ ] 有至少两项互相支撑的方法、基准、实证或系统贡献。
- [ ] 有 30–50 条失败 trace 的最小闭环计划。
- [ ] 有四档证据消融和至少一个反事实复验。
- [ ] 有清晰 Go/No-Go 条件和降级方向。
- [ ] 所有核心主张都标明 VERIFIED/INFERRED/UNVERIFIED。

当 A–F 基本完成后，再进入大规模论文实验；若 G 中真值、配对或稳定增益仍无法满足，应先收缩问题，而不是增加更多模型和框架。
