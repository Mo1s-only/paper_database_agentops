# 生图标准答案与复现说明

## 1. 使用范围

本轮只为 `练习与验收.md` 中明确要求“画图”的题目生成标准图。权限矩阵、实验矩阵、事件表等本质上是精确结构化数据，继续使用 Markdown 表格，避免把可复制、可校验的数据变成难以编辑的位图。

所有图片均由内置 ImageGen 生成，并复制到相应章节的 `assets/`。图片用于展示标准结构和视觉层级；评分应以节点、边、边界、图例和证据语义是否正确为准，而不是要求学习者复刻配色。

## 3. 最终提示词规范

所有提示词均采用 `scientific-educational` 用例，使用以下共同约束：

```text
Asset type: landscape textbook diagram for an Agent/AgentOps exercise answer
Style: flat vector-like technical diagram, publication-quality, white background
Composition: 16:9 landscape, large readable labels, consistent arrowheads, generous whitespace
Constraints: exact labels, no tiny text, no decorative clutter, no logos, no watermark
```

每张图的核心提示分别为：

1. **系统证据链**：`User Task → Agent Process → Model Call / Tool Child Process → File or Network Side Effect → session.db + WAL`，下置 `trace_id / PID-PPID / tool_call_id / artifact hash` 证据带。
2. **状态机比较**：并列 `Sequential Workflow`、`ReAct Loop`、`Planner–Executor`，必须画出验证、回边和预算门禁。
3. **MCP 信任边界**：展示 Host/Client、Transport、Server、Resource/Network 的独立信任域；红色威胁与绿色控制分层。
4. **多 Agent 拓扑**：2×2 展示 Pipeline、Supervisor、Debate、Shared Workspace；蓝色通信、红色错误传播。
5. **级联故障**：从错误论文选择经过证据表和共享复用，最终进入报告；上下分别放证据检查点和恢复措施。
6. **三类图比较**：执行图、错误传播图、候选因果图并列；在因果图标出共同原因和 `do()` 干预。
7. **间接提示注入**：恶意外部内容进入上下文并诱导工具读密与外传；输入隔离、策略决策、执行控制三层阻断。

## 4. 如何评价学习者作图

建议按 20 分评分：节点完整 4 分、边方向与类型 4 分、边界/图例 4 分、证据或控制点 4 分、配套文字能够解释“图能证明什么、不能证明什么”4 分。视觉美观不能替代语义正确；图中如果把通信边直接当作因果边，即使画得漂亮也不能通过。
