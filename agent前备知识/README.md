# Agent 前备知识：从基础到 AgentOps 论文主线

本目录不是通用 AI 百科，而是依据本项目现有说明文档、论文笔记、复现实验和论文方向整理的定向学习体系。目标是让学习者最终能够读懂、实现并评价下面这条研究链路：

```text
LLM 与单 Agent → 工具调用 → 多 Agent 协作
                         ↓
运行时观测 → 结构化执行轨迹 → 故障归因 → 根因诊断 → 可靠性评价
```

## 使用方法

每个正式章节现在包含四份材料：

1. `README.md`：先看本章地图、学习目标和项目内资料；
2. `详细教程.md`：按原理、例子、项目映射和答案要点逐节学习；
3. `练习与验收.md`：脱离教程完成练习并保存自己的作答；
4. `练习与验收答案.md`：最后再对照参考解、证据边界、评分标准与拓展资料。

推荐顺序是“教程 → 闭卷练习 → 自评 → 对照答案 → 修订”。答案是可复核的参考解，不是唯一表述；其中标为教学示例或待验证的数据不能直接写进论文结果。

涉及作图的题目还提供了 ImageGen 生成的标准图，并与文字说明和对照表共同构成答案。图片资产、提示词规范与评分方法见：[生图标准答案与复现说明](99_附录/生图标准答案与复现说明.md)。

不要只阅读。每学完一章，至少保存一份图、表、SQL、实验记录或诊断报告。

## 一、应该学到什么程度

完成本目录后，应能：

1. 用统一术语解释 Agent 的模型、状态、记忆、计划、工具和环境。
2. 画出单 Agent 与多 Agent 的执行图，识别控制流、数据流和依赖边。
3. 区分任务失败、工具失败、推理偏差、通信错误、协调故障和系统故障。
4. 解释日志、指标、追踪、Span、事件 schema、OpenTelemetry 和 eBPF 各自解决什么问题。
5. 根据执行证据定位责任 Agent、责任步骤、责任边和根因类型。
6. 设计包含基线、消融、真值、统计检验与成本报告的 Agent 实验。
7. 明确本项目当前哪些结论是 `VERIFIED`、`INFERRED` 或 `UNVERIFIED`。

## 四、证据纪律

- `VERIFIED`：项目中已有原始文档、代码、日志或结果支持。
- `INFERRED`：由现有材料推导出的合理判断，尚未被统一实验验证。
- `UNVERIFIED`：待实验、待核验或只有二手描述。
- `AUTHOR_INPUT_NEEDED`：需要作者、导师或学校流程作决定。

每次学习不要只写“看完了”，至少留下一个可检查产物：图、表、代码、SQL 查询、实验记录或带证据的判断。

## 五、当前论文主线

项目当前主线是面向 LLM 多智能体系统建立可审计的 AgentOps 故障分析链：

```text
运行时观测 → 结构化执行轨迹 → 故障归因 → 根因诊断与定位
```

`VERIFIED`：已有 AgentSight 与 Watson 的本地复现、文献索引和指标池。

`UNVERIFIED`：尚未证明跨层证据能稳定提高责任 Agent、步骤或边的定位效果，也尚未建立足量、可信的失败真值。

因此学习完成的标志不是“知道很多 Agent 名词”，而是能支持一个最小闭环：可靠采集、统一 schema、明确真值、四档证据消融和反事实复验。
