# 第 9 章详细教程：怎样证明 Agent 方法真的有效

## 1. 为什么最终成功率不够

两个 Agent 都完成 60/100 个任务，但含义可能不同：

- A 在剩余 40 个任务几乎完成，只差最终提交；
- B 在剩余任务第一步就失败；
- A 每次运行稳定在相似任务上成功；
- B 对同一任务时好时坏；
- A 成本是 B 的 10 倍。

因此要同时评价结果、过程、稳定性、归因、系统性能和成本。

## 2. Task Success 与可执行终态

对工具 Agent，优先检查环境终态，而不是文本声明。[τ-bench](https://proceedings.iclr.cc/paper_files/paper/2025/hash/1b126cc38b8638e07bef37e7b2bb72bf-Abstract-Conference.html)通过对比对话结束后的数据库状态与标注目标状态评价任务。

教学例子：取消订单的成功判据应是：

```text
orders[id].status == "cancelled"
refunds contains expected amount
no duplicate refund
policy constraints satisfied
```

不是 Agent 最后说“订单已取消”。

## 3. Progress Rate

[AgentBoard](https://proceedings.neurips.cc/paper_files/paper/2024/hash/877b40688e330a0e2a3fc24084208dfa-Abstract-Datasets_and_Benchmarks_Track.html)强调多轮 Agent 的过程进展。

教学定义：任务有 4 个里程碑，完成 3 个，则 progress=0.75。实际研究必须明确：

- 里程碑是否等权；
- 顺序是否必须；
- 部分完成怎样判；
- 错误完成能否计分；
- 里程碑由规则还是 judge 识别。

## 4. 重复运行与 `pass^k`

一次成功不能证明可靠。假设同一任务独立运行 `n=8` 次，成功 `c=6` 次。若 `pass^k` 定义为随机选取 k 次运行都成功，估计量可写为：

```text
pass^k = C(c, k) / C(n, k)
```

例如 `pass^2 = C(6,2)/C(8,2) = 15/28 ≈ 0.536`。它会随 k 增大而更严格。使用时必须遵循目标论文的具体定义并说明独立性和重复设置。

## 5. 归因排名指标

假设三个样本的真值排名分别在第 1、2、4 位：

```text
MRR = (1/1 + 1/2 + 1/4) / 3 = 0.583
```

- Top-1：首位是否正确；
- Top-k：真值是否出现在前 k；
- MRR：正确候选越靠前分数越高；
- NDCG：存在多级相关性时可用，但需定义增益。

若一个失败有多个共同原因，单一真值 Top-1 会惩罚合理候选，需要集合型或多标签评价。

## 6. Precision、Recall、F1

教学例子：方法报告 10 个责任边，其中 6 个正确；真值共有 8 条。

```text
Precision = 6/10 = 0.60
Recall    = 6/8  = 0.75
F1        = 2PR/(P+R) ≈ 0.667
```

### Macro 与 Micro

- Macro：每类先算指标再平均，少数故障类型权重更高。
- Micro：汇总所有决策，常见类型主导。

论文应同时报告类分布；否则高分可能只是总猜最常见类型。

## 7. 置信区间、显著性与效应量

### 置信区间

给出估计不确定性。小样本二项成功率可考虑 Wilson 或 bootstrap 区间，具体方法需预先确定。

### 显著性

p 值只描述在零假设下观察到当前或更极端数据的相容程度，不等于“方法有效概率”。

### 效应量

同时报告实际差异，例如：

```text
Step Top-1: 0.22 → 0.31，绝对提升 0.09
诊断延迟: 2.1s → 4.8s
日志体积: 1.2MB → 9.7MB
```

这是教学格式，不是项目结果。

## 8. 配对实验优先

对同一任务、同一故障种子，分别运行基线和方法，能减少任务难度差异。记录：

- 相同模型与版本；
- 相同任务输入；
- 相同工具和环境快照；
- 相同故障注入；
- 独立随机种子；
- 执行顺序随机化，避免时间趋势。

Agent 在线服务无法完全复现时，要把模型版本漂移和服务波动列入威胁。

## 9. 四类基线

1. **无方法**：只看最终输出；
2. **简单规则**：最后错误、最早错误、最近时间；
3. **强语义基线**：LLM 读取消息或完整轨迹；
4. **相关工作**：Who&When、图方法或其他可复现方法。

没有简单规则基线，无法判断复杂系统是否真的增加价值。

## 10. 消融实验

假设完整方法包含：系统证据、执行图、候选排序、反事实验证。可设计：

| 设置 | 系统证据 | 图 | 排序 | 反事实 |
|---|---:|---:|---:|---:|
| Full | ✓ | ✓ | ✓ | ✓ |
| -System |  | ✓ | ✓ | ✓ |
| -Graph | ✓ |  | ✓ | ✓ |
| -Replay | ✓ | ✓ | ✓ |  |
| Rules | ✓ |  |  |  |

每次尽量只移除一个机制，否则无法解释差异来源。

## 11. 泄漏与无效比较

常见泄漏：

- trace 中直接保存人工责任标签；
- 故障注入器用独特字符串暴露类型；
- train/test 来自同一模板；
- judge 看见参考答案，而基线看不见；
- 失败样本先由目标方法筛选。

比较公平性还要求证据预算、模型访问和候选空间一致。

## 12. 最小实验表

| 项目 | 预注册内容 |
|---|---|
| RQ | 完整轨迹是否提高 step-level 归因？ |
| 样本 | 30–50 条确认触发的失败 trace |
| 主指标 | Step Top-1、MRR |
| 次指标 | Agent Top-1、证据完整率、延迟、日志字节 |
| 基线 | 输出-only、消息-only、规则、强 LLM |
| 重复 | 每任务/配置多次，固定报告方式 |
| 排除 | 注入未触发、真值争议未解决、trace 严重损坏 |
| 统计 | 配对比较、区间、效应量 |
| 停止 | 达到预定样本量，不按结果好坏提前停止 |

## 13. 答案要点

- 结果、过程和稳定性指标回答不同问题。
- `pass^k` 比单次成功更严格地反映重复可靠性。
- MRR 评价排名，F1 评价集合识别；不能混为一谈。
- p 值不能代替效应量、置信区间和成本。
- 消融要隔离组件贡献，实验前固定规则可减少选择性报告。
