## 2. 实验协议

### 假设

当应用原生流和系统观测同时包含 application session、tool_call ID 与系统 PID 关系时，可以在不读取故障真值的情况下确定工具步骤属于哪个 Agent 会话；任务失败后，可以从实际工具结果中产生一个可审计的失败触发候选。

### 任务与故障

- Agent A 使用 Write 创建 `route.json`，规定 `alpha` 的 `required_available=1`。
- Agent B 使用 Bash 运行 `complete_inventory_tool.py route.json`。该脚本实际读取路由并调用既有受控错误工具 `fake_inventory.py`。
- 错误工具返回格式合法但错误的 `available=0`；合并工具输出实际包含 `observed_available=0, satisfied=false`。
- Agent B 根据该实际 JSON 使用 Write 生成 `decision.json`，提示词没有预填 0 或 false。

运行前创建 `ground_truth.json`，存放在 Agent 工作目录之外，并未进入对齐器输入。它记录责任 Agent 为 agent_b、语义步骤为 `agent_b.inventory_bash_call`。此文件用于事后核对。

### 环境与成本限制

- Ubuntu 24.04 WSL2；Python 3.12.3；Claude Code 2.1.270；AgentSight 1.0.31。
- 模型：现有配置中的 `deepseek-v4-pro`。
- 两个 CLI 会话各设 0.20 USD 报告成本上限，不自动重试；批次预检上限为 0.40 USD，累计硬停止线为 2.00 USD。
- 真实结果目录为 `real_application_runs/real-complete-20261010/`，已被 `.gitignore` 排除，避免原生 prompt、transport 信息和机器元数据默认上传。

## 4. 跨层身份对齐

本轮比较三种规则：

| 模式 | accepted | abstain | 能够支持的结论 |
|---|---:|---:|---|
| process-and-tool | 0 | 3 | 应用 PID/时钟坐标尚不能直接和 AgentSight 对比 |
| shared-tool-id | 3 | 0 | 同一次运行中三个原生工具 ID 均唯一出现在系统工具表 |
| session-and-tool | 3 | 0 | 应用 session 映射到系统 LLM PID，工具 ID 又映射到同一 PID |

`session-and-tool` 是本轮主结果。对每个 tool.start：

1. 应用 session ID 来自实际 Claude 原生流。
2. 同一 session ID 出现在 AgentSight `llm_calls`，得到唯一系统 PID。
3. 原生 tool_call ID 唯一出现在 AgentSight `tool_calls`。
4. 工具记录的 `related_pid` 与该 session 的系统 PID 一致。

3/3 条均满足。这是本次运行的工具身份覆盖率 1.0，不是总体归因准确率。对齐器未读取 ground_truth、旧 trace 或 derived 分析。

## 5. 失败触发候选与真值核对

在不读取 ground_truth 的情况下，程序从实际 tool_result 中找到唯一包含 `satisfied=false` 且同时含要求值和观测值的事件：

- Agent：agent_b；
- 工具：Bash；
- tool_call ID：`call_00_NGarV3zIFU9lSCjffruH0511`；
- 原生证据：`claude-agent-b.log` 第 147 行工具调用和第 151 行工具结果；
- 观测：required=1、observed=0、satisfied=false。

事后读取运行前真值：Agent exact 为 true。Step exact 保持 null，因为真值使用语义步骤名，运行时使用实际 tool_call ID；尚无独立、冻结的步骤 ID 映射协议，不能把工具名称相同直接写成 Step exact。

“失败触发候选”说明该工具结果直接使任务判据失败。它还不能区分真实库存确实为 0 与工具错误返回 0；本实验之所以知道它是静默错误，来自受控错误注入真值。因此不能把本次结果扩写为开放世界根因识别。

## 6. PID 与时间诊断

应用启动器记录的 PID 为 A=81、B=132；通过 session 映射得到的 AgentSight 系统 PID 为 A=341、B=405。应用 `/proc/<pid>/status` 的 NSpid 只暴露本地视图，当前仍不能计算两套 PID 的数值转换。

工具对的“原生流接收时间减 AgentSight 工具开始时间”为 587、590、584 ms，范围 584–590 ms。同一次运行内较集中，但 v0.11 的对应范围是 899–905 ms，证明不能将某个固定偏移跨运行复用。这里仍是诊断量，不是时钟校准。

因此完整身份连接采用 session + tool ID，而不伪造 PID 转换或时间换算。严格模式的 0/3 结果被保留。
