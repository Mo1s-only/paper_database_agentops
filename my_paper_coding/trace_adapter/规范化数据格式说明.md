## 1. 通用外层字段

每条规范化记录都尽量采用相同的外层结构：

```json
{
  "record_type": "agentsight.tool_calls",
  "evidence_status": "observed",
  "event_id": "...",
  "timestamp": 1790673803141,
  "agent_id": null,
  "step_id": null,
  "tool_call_id": "...",
  "pid": null,
  "fields": {},
  "source": {},
  "limitations": []
}
```

| 字段 | 含义 | 当前示例状态 |
|---|---|---|
| `record_type` | 记录来源和语义类型 | 已有应用、LLM、工具、进程、审计等类型 |
| `evidence_status` | 证据可信状态 | 原始观测为 `observed`；已有派生 trace 为 `derived_untrusted` |
| `event_id` | AgentSight 或应用记录的唯一 ID | 大部分 AgentSight 记录有值 |
| `timestamp` | 事件时间；AgentSight 通常为 Unix 毫秒 | 系统观测大多有值，应用最终结果没有值 |
| `agent_id` | 应用层 Agent 身份 | 当前仍为 `null`，需要 Adapter 推断 |
| `step_id` | 应用层步骤身份 | 当前仍为 `null`，需要 Adapter 推断 |
| `tool_call_id` | 工具调用标识 | AgentSight 工具记录有值 |
| `pid` | 进程 ID | 进程、审计和 LLM 记录通常有值 |
| `fields` | 保留原始表字段 | 不同 `record_type` 的具体内容不同 |
| `source` | 原始文件、SQLite 表、行号等来源 | 所有记录都有来源 |
| `limitations` | 当前记录的证据限制 | 用于阻止 Adapter 过度推断 |

## 2. 应用层结果：`application.result`

真实示例来自 `claude-agent-a.log`：

```json
{
  "record_type": "application.result",
  "evidence_status": "observed",
  "event_id": "a0f969b7-38c0-4304-8495-be2453d472be",
  "session_id": "60c54158-e567-4d70-aaec-efac01c2dae5",
  "timestamp": null,
  "agent_id": null,
  "step_id": null,
  "tool_call_id": null,
  "status": "success",
  "cost_usd": 0.094517,
  "usage": {
    "input_tokens": 16360,
    "output_tokens": 181
  },
  "source": {
    "path": ".../claude-agent-a.log",
    "line": 2,
    "role": "app_log"
  },
  "limitations": [
    "final_result_record_only",
    "no_step_or_tool_events_in_source",
    "timestamp_unavailable_in_source"
  ]
}
```

解释：

- `session_id` 是 Claude 应用层会话标识；
- `status=success` 只表示应用调用返回成功；
- `cost_usd`、`usage` 用于成本和 Token 统计；
- `timestamp=null` 表示当前最终结果日志没有可用事件时间；
- `agent_id`、`step_id` 为空，表示应用结果日志没有直接提供 Agent/Step 级事件；
- `limitations` 明确说明它不是完整 Agent 执行链，不能单独用于责任定位。

## 3. 模型调用：`agentsight.llm_calls`

真实示例来自 AgentSight 的 `llm_calls` 表：

```json
{
  "record_type": "agentsight.llm_calls",
  "evidence_status": "observed",
  "event_id": "llm-orphan-canon-event-1790673803141-sse-processor-1849-620",
  "timestamp": 1790673803141,
  "pid": 1849,
  "fields": {
    "conversation_id": "2e10344a-90be-4b19-b8a4-68f69d887380",
    "start_timestamp_ms": 1790673803141,
    "end_timestamp_ms": 1790673803141,
    "model": "deepseek-v4-pro",
    "status": "complete",
    "request_body_json": "null",
    "response_body_json": "..."
  },
  "source": {
    "path": ".../session.db",
    "table": "llm_calls",
    "role": "raw_observation"
  }
}
```

解释：

- `conversation_id` 是 AgentSight 观测到的对话标识；
- `pid=1849` 表示该调用关联到 Claude 进程；
- `model` 和 `status` 可以确认模型及调用状态；
- `request_body_json=null` 表示当前调用的请求体没有被还原；
- `response_body_json` 可能含有响应内容，发布前必须脱敏；
- AgentSight 当前没有直接写入应用层 `session_id`、`agent_id` 或 `step_id`，所以不能直接完成跨层归属。

## 4. 工具调用：`agentsight.tool_calls`

真实示例：

```json
{
  "record_type": "agentsight.tool_calls",
  "evidence_status": "observed",
  "event_id": "tool-llm-orphan-...",
  "timestamp": 1790673803141,
  "tool_call_id": "call_00_MxiNG1j5Mqu59A9LtVsw8173",
  "fields": {
    "conversation_id": "conv-llm-orphan-...",
    "tool_name": "Write",
    "tool_call_id": "call_00_MxiNG1j5Mqu59A9LtVsw8173",
    "status": "observed",
    "related_pid": 1849,
    "related_event_id": "canon-event-...",
    "confidence": 0.349999994
  },
  "source": {
    "path": ".../session.db",
    "table": "tool_calls",
    "role": "raw_observation"
  }
}
```

解释：

- `tool_name=Write` 表示观测到写文件工具；
- `tool_call_id` 可以作为工具事件的候选关联键；
- `related_pid=1849` 可以与 `process_nodes.pid` 对齐；
- `related_event_id` 可以继续追到 AgentSight 的底层事件；
- `confidence` 是 AgentSight 对该观测的置信度，不是本文归因置信度；
- 当前真实工具序列是：`Write → Read → Bash → Write`。

这是当前最适合开发候选对齐器的一类记录，但它仍没有直接给出 `agent_id` 和 `step_id`。

## 5. 进程：`agentsight.process_nodes`

真实示例：

```json
{
  "record_type": "agentsight.process_nodes",
  "evidence_status": "observed",
  "event_id": "process-1849-1790673791374",
  "timestamp": 1790673791374,
  "pid": 1849,
  "fields": {
    "pid": 1849,
    "ppid": 1848,
    "comm": "claude",
    "command": "/usr/local/bin/claude",
    "start_timestamp_ms": 1790673791374,
    "end_timestamp_ms": 1790673804608,
    "exit_code": 0,
    "status": "success"
  },
  "source": {
    "path": ".../session.db",
    "table": "process_nodes",
    "role": "raw_observation"
  }
}
```

解释：

- `pid`、`ppid` 用于构造进程父子关系；
- `start_timestamp_ms`、`end_timestamp_ms` 用于判断事件是否发生在该进程生命周期内；
- `exit_code=0` 只能说明进程正常退出，不能说明任务成功；
- `command` 和 `comm` 可以帮助识别 Agent 主进程、工具进程和辅助进程。

## 6. 审计事件：`agentsight.audit_events`

真实示例：

```json
{
  "record_type": "agentsight.audit_events",
  "evidence_status": "observed",
  "timestamp": 1790673791374,
  "pid": 1849,
  "fields": {
    "audit_type": "process",
    "action": "exec",
    "target": "/usr/local/bin/claude",
    "status": "observed",
    "summary": "exec /usr/local/bin/claude",
    "confidence": 0.75
  },
  "source": {
    "path": ".../session.db",
    "table": "audit_events",
    "role": "raw_observation"
  }
}
```

解释：

- `audit_type` 表示进程、文件或其他审计类别；
- `action` 表示执行、读、写等动作；
- `target` 表示操作目标；
- `pid` 和 `timestamp` 用于和工具、进程、网络事件建立时间关系；
- `confidence` 是 AgentSight 观测置信度；
- 该记录证明“发生了某个系统行为”，不直接证明该行为导致了任务失败。

## 7. Token：`agentsight.token_usage`

真实示例：

```json
{
  "record_type": "agentsight.token_usage",
  "evidence_status": "observed",
  "timestamp": 1790673803141,
  "pid": 1849,
  "fields": {
    "llm_call_id": "llm-orphan-...",
    "model": "deepseek-v4-pro",
    "input_tokens": 16244,
    "output_tokens": 155,
    "total_tokens": 16399,
    "source": "response_usage",
    "confidence": 0.35
  },
  "source": {
    "path": ".../session.db",
    "table": "token_usage",
    "role": "raw_observation"
  }
}
```

解释：

- `llm_call_id` 用于关联对应的模型调用；
- `input_tokens`、`output_tokens`、`total_tokens` 用于上下文和成本分析；
- Token 统计不是服务商最终账单；
- 当前记录可以和模型调用、PID、时间关联，但还不能直接和 Agent/Step 关联。

## 8. 网络目标：`agentsight.network_targets`

该表用于记录访问过的主机和路径，例如本次运行的 DeepSeek endpoint：

```json
{
  "record_type": "agentsight.network_targets",
  "evidence_status": "observed",
  "pid": 1849,
  "fields": {
    "host": "api.deepseek.com",
    "path": "/anthropic/api/hello",
    "count": 1,
    "error_count": 0,
    "first_timestamp_ms": 1790673791791,
    "last_timestamp_ms": 1790673791791
  },
  "source": {
    "path": ".../session.db",
    "table": "network_targets",
    "role": "raw_observation"
  }
}
```

解释：

- `host`、`path` 表示网络依赖；
- `count`、`error_count` 表示访问次数和错误次数；
- `first_timestamp_ms`、`last_timestamp_ms` 可用于判断调用时段；
- 它能说明 Agent 与外部服务交互，但不能单独说明某次请求属于哪个 Agent 步骤。

## 9. 任务工件不是系统事件

本次真实运行的任务文件为：

`workspace/route.json`

```json
{"item":"alpha","required_available":1}
```

`workspace/decision.json`

```json
{
  "item": "alpha",
  "required_available": 1,
  "observed_available": 0,
  "satisfied": false
}
```

它们回答的是任务语义问题：任务要求什么、Agent 最终观察到什么、任务是否满足。它们必须与 AgentSight 系统事件分开保存，再由 Adapter 通过文件路径、时间、PID 或应用日志建立候选关系。

独立判据 `ground_truth.json` 中记录了受控实验真值：

```json
{
  "fault_type": "silent_tool_error",
  "responsible_agent": "agent_b",
  "responsible_step": "agent_b.bash_tool_call",
  "responsible_edge": {
    "from": "agent_b.bash_tool_call",
    "to": "agent_b.decision"
  }
}
```

这个文件只用于离线评分，不能被 Adapter 当作观测输入，否则会造成真值泄漏。

## 10. 当前可以和不可以做什么

当前可以：

```text
tool_call_id
    → related_pid
    → process_nodes.pid
    → audit_events.pid + timestamp
    → 文件/网络/资源证据
```

当前还不能直接做：

```text
application.session_id
    → AgentSight.conversation_id
    → agent_id
    → step_id
    → 确定的责任边
```

因此 Adapter 下一步必须输出候选关系和证据引用，例如：

```json
{
  "candidate_type": "agent_step_alignment",
  "candidate_value": "agent_b.tool_call",
  "confidence": 0.0,
  "evidence_refs": [
    ".../session.db#tool_calls/<row>",
    ".../session.db#process_nodes/<row>"
  ],
  "status": "candidate"
}
```

`confidence` 在没有独立跨层证据时不能被写成确定责任概率；匹配失败时应输出 `uncertain` 或 `abstain`。

## 11. 数据安全与复现实验

规范化记录可能保留 `response_body_json`、命令行和文件路径，可能包含 Prompt、响应内容或本机路径。提交或公开前必须脱敏。真实 API key 只允许存在于本地 `.env`，不能进入结果目录或 Git。

重新生成规范化数据：

```powershell
python .\my_paper_coding\trace_adapter\build_run_index.py
python .\my_paper_coding\trace_adapter\normalize_runs.py
```

本文件解释的是当前真实 canary 的观测数据格式，不代表通用 Trace Adapter 已经完成，也不代表 AgentSight 已经自动完成责任归因。
