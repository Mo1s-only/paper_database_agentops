# 真实跨故障扩展实验报告｜2026-10-10

## 1. 实验结论

本轮用真实 API 完成两个受控双 Agent 场景：错误传播与路由角色错误。每个场景在 API 调用前冻结 Agent、Step、责任边和传播边真值；归因程序先从原生运行证据生成预测文件，写盘后才读取真值评分。

两个场景的故障类型、责任 Agent、责任 Step、责任边和传播边均与预冻结真值精确一致。这个结果是两个 `n=1` 受控场景的确定性规则验证，不能写成总体准确率或跨任务泛化结论。

系统观测仍有明确缺口：每个场景原生流均有 4 次工具调用，AgentSight 均只记录 3 次。因此跨层工具对齐为 3/4，`unified_trace_ready` 仍为 false。错误传播场景漏掉的恰好是责任 Bash 步骤；该场景的 Step 定位由应用原生证据支持，系统侧对此步 abstain。

## 2. 协议与隔离

- 环境：Ubuntu 24.04 WSL2、Python 3.12.3、Claude Code 2.1.270、AgentSight 1.0.31。
- 模型：现有配置中的 `deepseek-v4-pro`。
- 共 4 个真实 CLI 会话，每个会话报告成本上限 0.13 USD，不自动重试。
- `ground_truth.json` 在第一次 API 调用之前创建，并标记 `excluded_from_alignment=true`。
- 语义步骤规则在运行前固定为 `{agent_id}.{lowercase_tool_name}_{one_based_ordinal_within_agent_tool_name}`。
- 对齐程序不读取真值；评分程序以排他创建方式先写 `scenario-prediction.json`，随后才打开 `ground_truth.json`。
- 原生日志、AgentSight SQLite 和机器元数据位于被 Git 忽略的 `real_application_runs/`，机器可读预测和评分也保留在对应运行目录。

## 3. 场景结果

| 场景 | 真实 API 会话 | 费用 USD | 原生工具 | AgentSight 工具 | session-and-tool | 任务结果 |
|---|---:|---:|---:|---:|---:|---|
| error-propagation-v1 | 2/2 成功 | 0.070535 | 4 | 3 | 3 accepted / 1 abstain | down 被报告为 healthy，下游输出 NO_RESTART，失败 |
| routing-error-v1 | 2/2 成功 | 0.069355 | 4 | 3 | 3 accepted / 1 abstain | retrieval 被路由到 generalist，retrieved=false，失败 |
| 合计 | 4/4 成功 | **0.139890** | 8 | 6 | 6 accepted / 2 abstain | 两个受控任务均按注入机制失败 |

错误传播场景的语义路径为：

```text
agent_a.bash_1 产生 inconsistent=false 的观测
→ agent_a.write_1 写入错误 handoff
→ agent_b.bash_1 据此给出 NO_RESTART
→ agent_b.write_1 固化错误决定
```

路由错误场景的语义路径为：

```text
agent_a.bash_1 产生 route_valid=false 的路由
→ agent_a.write_1 写入 route
→ agent_b.bash_1 执行错误角色
→ agent_b.write_1 固化 retrieved=false 的结果
```

## 4. 归因与真值评分

| 字段 | 错误传播 | 路由错误 |
|---|---|---|
| fault_type | exact | exact |
| responsible_agent | agent_a，exact | agent_a，exact |
| responsible_step | agent_a.bash_1，exact | agent_a.bash_1，exact |
| responsible_edge | bash_1 → write_1，exact | bash_1 → write_1，exact |
| propagation_edge | agent_a.write_1 → agent_b.bash_1，exact | agent_a.write_1 → agent_b.bash_1，exact |
| 责任步骤系统对齐 | abstain | accepted |

归因规则只寻找原生工具结果中的唯一显式异常：`consistent=false` 或 `route_valid=false`。它再按运行前固定的步骤命名规则构建本 Agent 后续边和跨 Agent 传播边。该规则适合验证当前受控协议；它还不是开放世界故障分类器。

## 5. 系统观测缺口

两次运行的 `process-and-tool` 模式均为 0/4 accepted，因为 WSL 应用 PID/时钟和 AgentSight 坐标仍未校准。`shared-tool-id` 与 `session-and-tool` 均为 3/4。

- 错误传播漏记 `agent_a.bash_1`，即责任步骤。原生流中的调用与结果完整存在，AgentSight SQLite 和 debug stream 中没有对应工具 ID。
- 路由错误漏记 `agent_a.write_1`。责任 Bash 已被系统侧接受，但责任边中间节点的系统证据不完整。

因此可以确认本轮应用层语义定位和真值评分完成，也必须同时保留“系统层全链路未完成”的结论。当前数据不能支持 8/8 跨层覆盖，也不能把 Edge exact 等同于系统因果边已经全部观测。

## 6. 软件检查与成本

- 原生解析器为两个场景各生成 20 条应用事件，全部会话闭合，来源引用完整。
- AgentSight 分别生成 342 和 351 条规范化系统记录，解析时均无跳过记录。
- 48 项单元测试全部通过，新增测试覆盖 JSON 结果解析、语义 Step 映射、完整 exact 评分和 Step 错配拒绝。
- 本轮报告费用 0.139890 USD；本地成本账本共识别 23 个可计价运行，累计 **1.576492 USD**。该数值来自本地 CLI 日志，不等同于服务商最终账单。

费用证据：[跨场景实验后成本账本](../experiment_control/cost-ledger-20261010-scenarios.md)。

## 7. 证据状态

### VERIFIED

- 4 个真实 API 会话均成功；两个受控任务均产生预期失败结果。
- 两个场景的预测文件在真值读取前生成，真值在 API 调用前冻结且未进入对齐输入。
- 两个 `n=1` 场景的故障类型、Agent、Step、责任边和传播边均 exact。
- 每个场景原生工具 4 次、AgentSight 工具 3 次，缺失 ID 和 abstain 已保留。
- 本轮费用、累计费用、来源哈希和 48 项测试结果。

### INFERRED

- 固定语义 Step 规则足以把当前 Bash/Write 工作流的运行时工具 ID映射到可评分步骤。
- 应用原生事件可以在系统工具漏采时保留语义归因线索；系统证据完整性需要单独作为质量维度。
- 在做 B0–B3 消融前，应先解决或量化 AgentSight 工具漏采，否则消融结果会混入采集缺失。

### UNVERIFIED

- 多次重复下的工具捕获率和归因稳定性。
- 无显式 `consistent`/`route_valid` 标志时的故障发现能力。
- 开放世界合法失败与注入故障的区分、反事实因果结论、跨框架泛化。
- 统计 Precision、Recall、置信区间和独立人工复核一致性。

### AUTHOR_INPUT_NEEDED

- 当前距 2.00 USD 硬停止线剩余 0.423508 USD。若按本轮 4 会话、每会话 0.13 USD 的计划上限重复，计划上界会超过硬停止线。下一批真实重复实验需要先决定提高总预算，或缩小批次/单会话上限。

## 8. 下一研究闸门

先做不调用 API 的采集完整性诊断：比较缺失工具的类型、出现位置、AgentSight record/debug 输出和 SQLite 写入时序，形成可复现的漏采检查。修复或明确漏采机制后，再各重复错误传播和路由错误至少 3 次，并进入 B0–B3 证据消融。重复实验应报告捕获率、归因 exact、abstain 率与成本，不再只报告单次成功案例。
