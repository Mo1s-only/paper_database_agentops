# 数据链扩样实验计划｜2026-10-19

## 研究问题

在受控多 Agent 故障任务中，归因前数据链能否稳定、可追溯地捕获并关联应用层工具事件与 AgentSight 系统观测？本实验首先验证采集/对齐正确性，不把它等同于归因算法准确率。

## 当前数据基线

- **公开数据兼容性：**Who&When 184 条、TRAIL 148 条、AgentTrace 550 条，共 882 条归因前记录；14,697/14,697 个结构关系重建，31,132/31,132 个对象具备证据定位。它们没有配对的本地 AgentSight 运行事件，因此验证 schema/标签适配，不验证跨层采集准确性。
- **真实受控多 Agent 场景：**库存静默工具错误、错误传播、路由角色错误各有真实样例；跨故障扩展中的错误传播和路由场景各为 `n=1`。两个场景各 4 次原生工具调用、3 条系统工具记录。
- **采集诊断汇总：**4 次真实运行共 15 次原生调用、12 次 AgentSight 捕获；3 个缺失 ID 在 SQLite 中未命中。原始运行目录当前不可用，统计尚不能在本工作区重算。
- **软件测试：**当前工作树 107 项测试检查实现行为，不是 107 条独立真实实验样本。

## 分阶段扩样

### 阶段 A：零 API 合成/回放压力集（已完成首版）

已生成 1,000 条确定性合成配对 fixture，文件为 `my_paper_coding/trace_adapter/fixtures/alignment_stress_1000.jsonl`，生成器为 `generate_alignment_stress_fixtures.py`。9 类情形各 111 条，正常唯一配对多 1 条；标签由 fixture 生成器预先确定。当前结果为 accepted 112、abstain 111、uncertain 777，预期状态不匹配 0，API 调用 0。

**解释边界：**本轮只验证合成 fixture oracle 的 fail-closed 规则和数据集可重复生成；脚本明确记录 `production_aligner_exercised=false`。因此不能据此声称生产对齐器准确率、AgentSight 真实捕获率或真实归因效果提升。协议版本边界解决并把 fixture 接入生产对齐器后，才可把阶段 A 升级为生产代码离线回放测试。

### 阶段 B：真实 API 小批量重复

对已有 3 种故障（库存静默工具错误、错误传播、路由角色错误）各追加 3 次，共 9 个双 Agent 场景、最多 18 个 CLI session。每个场景独立冻结真值、独立输出 run ID、禁止自动重试；先跑一个场景试点，只有采集与成本门通过后才继续下一批。若结果稳定，再讨论每类扩到 10 次。

## 单次成本上限

- 每个双 Agent 场景总 API 成本上限：2 CNY。
- 脚本默认每个 CLI session `0.12 USD`，两次 session 上界 `0.24 USD`；用保守规划率 `8 CNY/USD` 估算为 `1.92 CNY/场景`，留有约 4% 余量。
- 这是按 CLI 报告成本做的预算约束，不等同于服务商最终账单。每次运行同时保存实际报告 USD、按该次规划率折算的 CNY 与 cap 状态。
- 9 个新增场景的上界为 `17.28 CNY`。此数仅是计划上界，不是已授权或已发生支出。
- **当前累计硬停止线仍阻止 API 执行：**最新本地成本账本为 `2.183708 USD`，高于原 `2.00 USD` 总上限。按本场景规划上界再加 `0.24 USD`，累计预估为 `2.423708 USD`。执行器现于任何网络/API启动前读取累计计划和账本并硬阻断超限；每次 2 CNY 的新限制不自动提高累计总预算。真实扩样必须先由作者确定新的累计上限并通过预算预检。

## 指标和通过条件

1. 原生工具调用捕获率：AgentSight `tool_calls` / 应用原生 `tool_use`；逐场景报告，不以总量掩盖漏采。
2. 身份链接 Precision/Recall：以冻结的配对 ID 真值计算；重复、冲突、缺失关系必须拒绝或 abstain，不得 false accept。
3. 完整链比例：所有预期工具调用均可链接到对应系统观测的场景占比。
4. Provenance 完整性：来源行、原始哈希和映射规则可复核的比例。
5. 独立报告归因指标：Agent/Step/Edge exact 只能回答归因表现；需与数据链指标分表呈现。

## 本轮执行边界

可先实现并运行阶段 A 和离线校验；不启动新的 API 会话，直到累计预算上限重新获批。现有 `capture_incomplete` 质量门继续生效：部分跨层覆盖时保留应用层预测，但禁止宣称系统层因果边完整。
