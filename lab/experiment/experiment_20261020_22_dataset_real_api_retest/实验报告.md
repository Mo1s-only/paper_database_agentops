# 多数据集真实 API 复测（2026-10-20）

## 目标与范围

复测当前环境下两个此前真实调用过的输入：`error-propagation-v1` 双 Agent 任务，以及 AgentRx Tau Retail `task_id=12` 轨迹诊断。问题拆成两项分别报告：模型 CLI 是否完成真实 API 调用；AgentSight 是否同时写入 LLM／工具语义事件和系统/eBPF 事件。公开 Who&When、TRAIL、AgentTrace 本轮没有逐条调用 API；它们仍是离线归因轨迹数据，既不是可直接启动的 Agent 工具任务，也没有配对的 AgentSight 运行事件。

本轮不自动重试。预设预算上限为 error-propagation 每会话 `$0.05`、AgentRx `$0.08`，合计计划上界 `$0.18`，按规划系数 10 CNY/USD 为 `¥1.80`。费用为 CLI 报告值，不是供应商账单。

## 成本核算

- 本轮两项 CLI 报告费用合计：`$0.1603168`，按规划系数折算约 `¥1.603168`，低于本轮 `¥2` 批次总限额。
- AgentRx 单次实际报告 `$0.108088`，比 `$0.08` 预算值高 `$0.028088`。因此**单次限额未守住**，不可把 `--max-budget-usd` 当作严格的预付费硬停止保证。发现超限后没有再发起请求。
- 加上此前已知增量 `$0.1408592` 与冻结历史账本 `$2.183708`，本地规划累计为 `$2.484884`。冻结历史 30 条原始日志仍未完全复核；所有累计值均为冻结历史基线加 CLI 报告值，不是重新审计后的服务商账单。
- 机器可读基线与新批次上限见 [`cost-ledger-dataset-retest-20261020.json`](../../../my_paper_coding/experiment_control/cost-ledger-dataset-retest-20261020.json) 和 [`real-api-dataset-retest-20261020.json`](../../../my_paper_coding/experiment_control/real-api-dataset-retest-20261020.json)。

## 回答“这些数据集能否真实 API 跑通”

- `error-propagation-v1`：**能调用并完成 CLI 任务**，但当前 Claude/AgentSight 组合没有写出 LLM／工具语义表，不能说完整观测链跑通。
- AgentRx `task_id=12`：**此前 10 月 19 日有一次成功真实诊断调用**；本次复测则因 CLI 报错且预算耗尽，没有产生可用预测。单条样本的调用稳定性因此不能判为可靠。
- Who&When、TRAIL、AgentTrace：目前只验证了 882 条归因前 schema/关系适配；没有真实 API 运行或 AgentSight 捕获实验。若后续以 LLM 对轨迹做预测，那是模型归因评测，不会自动变成 eBPF 运行时采集。

## 下一研究闸门

1. 在不付费条件下定位 Claude Code `2.1.303` 与 AgentSight SSL 观察器的语义记录缺口，并固定 Claude/AgentSight 二进制哈希。
2. 修正真实 API 预算门：出现 CLI 报告费用超过配置 cap 时，记录为 `exceeded_cap` 并立即停止后续付费会话；CLI max-budget 只作软限制看待。
3. 调查 AgentRx `unrecognized_model` 与 `budget_exhausted` 的实际来源；在原因未明且预算未重新核算前不重试。
4. 只有 API 请求返回有效预测，且错误任务同时具备非零语义表和可复核系统记录时，才分别标记“推理完成”和“跨层采集通过”。

当前结论：**error-propagation API 执行通过，AgentSight 语义采集失败；AgentRx 本次 API 诊断失败并发生单次预算超额；三个公开轨迹数据集尚未做 API 预测实验。**

## 追加排查：AgentSight 语义行缺失（2026-10-21）

- **VERIFIED**：对本次 `session.db` 只读检查发现 2 条 `/anthropic/v1/messages?beta=true` 网络目标，PID 1283、1420；这两个 PID 在 `process_nodes` 中均对应 Claude 进程。故本次失败不能归为 CLI/eBPF PID 未关联。
- **VERIFIED**：同一数据库 `llm_calls=0`、`tool_calls=0`，所以失败发生在 adapter 严格的 session/tool ID join 之前。诊断结果见 [`capture-coverage-diagnosis.json`](results/error-propagation-v1/capture-coverage-diagnosis.json)。
- **INFERRED**：首个缺失阶段为“网络目标 → LLM 语义行”。host/path 被保留并不证明 TLS 明文、HTTP 请求体或响应 SSE 已被完整采集。当前源码有一项 body/model 缺失时保留低置信度请求的改动，但无法确认系统安装的 `agentsight 1.0.31` 包含该改动。
- **UNVERIFIED**：具体原因仍可能是 TLS probe 未交付可解析明文、HTTP/SSE 解码不完整、或当前安装二进制缺少上述 bodyless-request 改动。现有数据库没有足够的原始 HTTP 请求/响应事件来区分这些原因。
- **修改与验证（2026-10-21 更新）**：`capture_real_scenarios.py` 现在会在每次捕获结束后写入覆盖诊断 JSON；Python 单测 13 项通过，bodyless-request 定向 Rust 单测 1 项通过。全量 CLI 离线构建最初失败是本地 checkout 缺少 `collector/src/output/{format.rs,tui.rs,mod.rs}`；从同版本源码恢复这三个模块后，release 构建通过。候选二进制的隔离 loopback 回环得到 `llm_calls=1`、`token_usage=1`、`network_targets=1`、`process_nodes=11`。未安装或替换系统版 AgentSight，也没有修改严格跨层关联规则。真实 API canary 预检确认 Claude Code → DeepSeek 所需凭据当前未载入，因此请求前停止，本轮无新增 API 调用或费用。完整追加记录见 [`2026-10-21 候选构建与预检报告`](../experiment/experiment_20261021_24_agentsight_candidate_mock/实验报告.md)。

**下一研究闸门**：安全启用 Claude Code → DeepSeek 兼容 API 凭据后，按单次 `$0.02` 上限重跑预检，再做一次真实 API canary，并核对语义表、eBPF 进程/网络记录和 adapter 严格关联。bodyless-request 保留逻辑的真实 API 效果仍未验证；loopback 只证明候选版能处理此 HTTP/1.1 mock 请求，不证明真实 DeepSeek 链路已修复。

## 追加：真实 DeepSeek canary（2026-10-21）

后续在候选 AgentSight 二进制上完成两次真实 API 会话：第一条 DeepSeek V4 Pro 会话因 Claude Code `$0.02` 软预算停止，实际 `$0.0237776`；第二条 DeepSeek Flash 会话成功，费用 `$0.0181688`。二者都命中 DeepSeek Anthropic-compatible `/messages` endpoint，HTTP 200，且生成 `llm_calls=2`、网络目标和 process/file eBPF 审计。

使用既有 `analyze_ebpf_real_canary.py` 校验 namespace PID：Claude launcher PID 499 对应 eBPF observer PID 734/735 的 BPF 证据为 `bpf.pidns.tgid=<observer>,499`，时钟重建落在 launcher 区间，按既有策略 accepted。因此本轮真实样本不支持“PID 映射失败导致语义漏采”。

但 AgentSight SQLite 的 `tool_calls=0`、`token_usage=0`。第二条 Claude 原生流明确包含一个 Bash `tool_use`/`tool_result`；eBPF 观测到同进程树中的唯一 `python3 scenario_service_observer.py` exec，处于语义事件接收时间窗内。该工具到 exec 关系是 command+time 的唯一候选、`inferred`，没有共享 tool_call_id。两条 LLM response_body_json 均为 JSON `null`，所以 response usage/SSE projection 在 SQLite 中没有可用 body 输入；确切更早的 TLS/SSE 丢失点未验证。

两次真实调用合计 `$0.0419464`；加此前报告中的增量后，按规划汇率的新增累计约 `¥1.567032`，仍低于 `¥2` 批次上限。详细证据及预检历史见[候选构建与真实 API 报告](../experiment_20261021_24_agentsight_candidate_mock/实验报告.md)。本轮第一条 key 曾粘贴在聊天里，未写入实验文件；应在继续实验前轮换。

**当前结论与研究闸门**：真实 API、LLM 语义行、网络目标、eBPF 系统观测和 CLI→eBPF PID namespace 映射均已跑通；AgentSight 自身 tool_calls/token_usage 投影仍未通过。下一步先做 SSE decoder 的零成本 fixture 测试与 CLI stream→eBPF 候选链稳定性验证，不扩大付费样本。
