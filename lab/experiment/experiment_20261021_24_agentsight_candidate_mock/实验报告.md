## 响应体缺失的代码级定位（新增）

- **VERIFIED — 数据在应用层存在**：run 6 的 Claude 原生 `stream-json` 中有 Bash `tool_use` 和对应 `tool_result`；离线 parser 生成 6 个完整应用生命周期事件。该文件由 `capture_real_application.py` 单独保存，AgentSight 不会自动读取它。
- **VERIFIED — 丢失发生在响应投影之前**：run 6 的两条 HTTP 200 `llm_calls` 都有约 14–16 KB 的 `request_body_json`，而 `response_body_json` 是 JSON 字面值 `null`（长度 4），没有 AgentSight tool/token 行。投影只有在响应 CanonicalEvent 带 body 或 `sse_processor` 带 `sse_events` 时才会提取 usage/tool；当前收到的是空响应载荷，因此后续 SQLite 投影无法生成它们。
- **VERIFIED — HTTP/2 解码器有帧重组缺口**：`HTTPParser` 对每条 SSL 事件分别调用 `parse_http2_frames(bytes)`；若帧头或帧 payload 不完整，该函数返回 `None`。解析状态保存了 stream body，却没有保存未完成的 HTTP/2 字节尾片；SSL 读取边界不保证与 HTTP/2 帧边界一致，所以被拆开的 DATA 帧不会被下一条 SSL 事件补齐。现有 HTTP/2 单测只把完整帧集合放在单条 SSL event 中，没有覆盖拆帧。见 [`http_parser.rs`](../../agentsight/source/thesis_adapter/ext/analysis/src/analyzers/http_parser.rs)。
- **VERIFIED — SSE 也缺少跨事件的原始片段缓冲**：SSE parser 每次对当前 event 的字符串按空行切块并解析；accumulator 合并的是已解析 SSE events，不是未完成的 `event:`/`data:` 字节/文本片段。若响应的 SSE event 本身跨 DATA/SSL event 分片，残缺 JSON 不会在下一片补齐。见 [`sse_processor.rs`](../../agentsight/source/thesis_adapter/ext/analysis/src/analyzers/sse_processor.rs)。
- **INFERRED — 最可能的本次触发链**：请求方向数据足够完整，能解析出模型与请求体；响应是流式返回，更容易跨 SSL read 切分。HTTP/2 分帧未重组（以及后续 SSE event 未重组）使响应 body 未形成 `http_parser`/`sse_processor` 结构化事件，于是 projection 保存 `null`，`ingest_sse_tools` 没有 tool_use 可消费。源码缺口与观测结果吻合，但由于本次 `record` 只保留投影后的 SQLite、未保存原始 SSL 明文事件，不能证明 run 6 的具体哪一帧在哪个边界被拆开。
- **排除项**：`record` 配置确实启用了 SSL/HTTP analyzer；`ssl_raw_data=false` 只关闭额外的原始副本，不会主动关闭解析后的 HTTP body 字段，因此不是“设置没开”导致的 body 缺失。请求 body 已被解析也证明请求侧的采集路径工作。

## 代码修复与离线验证（2026-10-21）

- **VERIFIED — 修复分析器顺序**：`add_http_analyzers` 现在先过 HTTP parser、再过解压器、最后过 SSE processor；避免原始 TLS chunk 先被 SSE processor 消费，令 HTTP/2 DATA 帧解析器看不到完整字节。
- **VERIFIED — HTTP/2 读取边界重组**：HTTP/2 parser 现在按 PID/TID/方向缓存不完整 frame，下一次 SSL read/write 到达后续接；stream 状态也纳入 PID，避免不同进程恰好复用 TID/stream ID 时串流。缓存有上限；明确不是 HTTP/2 的已缓存字节会合并后交还下游，不静默丢弃。
- **VERIFIED — 端到端离线回归**：扩展 gzip + SSE 测试，将 HTTP/2 响应逐字节拆成 SSL events，并包含 OpenAI 格式 `lookup(q=x)` 工具调用和 usage。`HTTPParser → HTTPDecompressor → SSEProcessor → MaterializedView` 定向测试通过；投影得到 1 次 LLM 调用、1 个工具调用、input/output tokens 为 2/5（总计 7）。
- **VERIFIED — collector 编译**：`cargo check --offline --manifest-path collector/Cargo.toml` 通过；最终 `cargo build --offline --release --manifest-path collector/Cargo.toml` 通过。release 二进制为 AgentSight `1.0.31`，SHA-256 `7758b46842afa81f4635d86d11f8dac9c72783476345c06b4579a027d2642380`。
- **未全绿测试**：analysis crate 全量 130 项中 128 项通过，2 项失败：`test_openai_compatible_usage_completes_sse_stream` 的 token summary 数值断言，以及 `parses_compressed_websocket_responses_with_context_takeover` 的 LLM 行数断言。修改的 HTTP/2 逐字节端到端测试在全量运行中通过；这两个失败尚未定位，需单独检查，不能记为通过。
- **实验边界**：本修复用离线合成帧验证了解析器对分片边界的正确性，不会回填 run 6 的历史 SQLite，也没有再次调用 DeepSeek。历史 run 6 的具体 SSL chunk 边界没有被持久化，因此真实样本的直接触发过程仍是 **INFERRED**；应使用新 release 在后续获批预算/可控本地回环中重新采集验证。

当前 HTTP/2→HTTP body→SSE 路径已补上帧字节重组，所以上面提出的“按 HTTP/2 DATA/SSL 分片重组”已实现；不应再把它写成待办。SSE 独立收到非 HTTP 封装的原始碎片时仍可能需要单独验证，但本轮的端到端 HTTP/2 流已在 DATA/SSL 跨边界条件下通过。
