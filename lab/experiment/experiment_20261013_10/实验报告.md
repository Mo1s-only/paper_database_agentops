# 归因前可查询证据包实验报告

## 研究问题

目前的事件规范化、单会话身份对齐和时钟统一已经能提供结构化输入，但论文级证据还需要回答两个问题：每条结构关系能否重新查询得到，以及系统能否在证据不足时拒绝升级结论。本实验只验证归因前能力，不运行归因算法。

## 从四项工作吸收的设计

| 来源 | 吸收内容 | 本实验实现 | 明确不做 |
| --- | --- | --- | --- |
| RCACopilot | 多来源、可组合的 incident handlers | 生命周期、进程身份、观测器时钟、模型调用上下文 4 个 handler | 不调用 LLM 生成诊断 |
| OpenRCA | 以程序化查询读取大规模遥测 | 白名单精确查询、结果事件 ID、结果 SHA256 | 不把全部原始日志塞入上下文 |
| Watson | 复现前先固定模型调用条件 | 独立 model invocation context v0.1；缺字段时 `NOT_READY` | 不把重建内容当运行真值 |
| OpenRCA 2.0 | 每一步结论附可执行证据 | 每条观察关系绑定 query ID 与 event ID，并支持独立重放 | 不生成传播边、根因或责任路径 |

## 实际输入

输入来自 `experiment_20261012_14` 的真实 API 会话。事件序列为：

```text
session.start → step.start → tool.start → tool.end → step.end → session.end
```

共享工具标识为 `call_00_Da4rghUlpsbWGEyZMdqF5028`。应用进程视图为 PID 81、namespace `pid:[4026532214]`；观测器进程视图为 PID 1758、`linux-initial-pid-namespace`。该映射的协议状态原本就是 `inferred`，证据包没有提升它。

## 实验结果

### 查询可复现性

生成的 5 个查询分别覆盖完整 session、进程映射、单个 step、单个 tool 生命周期和含 observer clock 的事件。独立验证结果为：

```text
query_count = 5
all_queries_replayed = true
relation_count = 3
relation_receipts_complete = true
identifiers_unique = true
forbidden_claims_absent = true
passed = true
```

### 观察关系

| 关系 | 证据等级 | 结果 |
| --- | --- | --- |
| `session_observed_in_process` | `INFERRED` | 6 条 session 事件均指向同一进程映射，但缺直接 namespace 真值 |
| `session_contains_step` | `VERIFIED/direct` | step 的 4 条生命周期事件可重新查询 |
| `step_invokes_tool` | `VERIFIED/direct` | tool.start 与 tool.end 共享同一 tool ID，生命周期闭合 |

由于严格时钟门未通过，后两条关系只使用协议序列，不声称跨层纳秒时间顺序。观察关系字段同时固定 `causal_claim=false` 和 `responsibility_claim=false`。

### Watson 式镜像条件

为避免事后用默认参数伪造模型行为，本次新增严格 sidecar 协议。它只保存运行元数据和提示词/schema 的 SHA256，不保存敏感正文。历史真实会话没有完整保存这些字段，因此结果为：

```text
mirror_readiness.status = NOT_READY
context_count = 0
default_values_invented = false
reconstruction_attempted = false
```

缺失项包括 model/version、temperature、top_p、system prompt hash、tool schema hash、request/response ID 与配对证据。

## 结论

`VERIFIED`：归因前链条已经从“事件格式正确、单会话可以对齐”深化为“结构关系可查询、可重放、可验哈希、可拒绝越界结论”。这使后续归因算法接收的每一条输入关系都有机器可查的来源。

`VERIFIED`：两个交错 session 复用相同局部 step/tool ID 的合成边界测试已通过，查询与关系 ID 保持隔离。

`UNVERIFIED`：真实数据仍只有一个 session，无法证明查询与关系收据在真实并发、多 Agent、长会话和捕获缺失场景中的稳定性；模型调用上下文协议也尚未在新真实 API 会话中验证。

下一研究闸门是一次新的、调用前冻结配置的真实多 Agent 会话：同时采集直接 `NSpid`、非零时钟分辨率下界和 model invocation context sidecar，再验证并发关系是否仍能逐条回放。该闸门完成前，不进入归因结论生成。
