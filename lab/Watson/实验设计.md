# Watson × AgentSight 实验设计

## 1. 研究目标

在不改变主 Agent 提示词、工具权限、模型调用顺序或关键路径时延的前提下，验证一条可审计的认知观测链：

```text
AgentSight 捕获系统/语义证据
    → 请求—响应配对与调用筛选
    → Watson 镜像替身旁路重建（RepCoT）
    → 输出一致性 + 组件归因 + judge 验证
    → 元推理报告与系统效果对齐
```

研究对象不是“读取模型真实隐藏思维链”。所有生成结果都应称作**受观测输入输出约束、经验证的解释候选**；实验要测量的是其一致性、效用、成本与非干扰性。

## 2. 研究问题与假设

| 编号 | 研究问题 | 可检验假设 |
|---|---|---|
| RQ1 | AgentSight 是否能为 Watson 提供完整、可配对的输入输出证据？ | ≥95% 的入选文本调用可获得 request、response、模型与时间/连接来源。 |
| RQ2 | RepCoT 能否构造与主输出一致且有证据支撑的解释候选？ | 在可重放调用中，候选输出匹配率和 judge 接受率显著高于无约束事后解释基线。 |
| RQ3 | 认知观测是否干扰主 Agent？ | RO-SR 与 WA-SR 的任务成功率无显著差异；WA-SR 的 Watson 只在主任务结束后运行。 |
| RQ4 | 认知解释是否能提升故障调试？ | 开发者在获得“解释 + 系统效果”报告后，根因定位正确率/修复线索质量高于只有普通 trace 的条件。 |
| RQ5 | 该方法的成本—保真权衡是什么？ | 增加候选数会提高覆盖或稳定性，但存在边际收益递减；需报告 1/3/5/10 条的曲线。 |

## 3. 实验对象与分层

### 3.1 三层证据

| 层次 | 来源 | 本实验保留字段 | 回答的问题 |
|---|---|---|---|
| 系统/行为层 | AgentSight eBPF、进程、文件、网络、工具事件 | `pid`、时间、命令、工具、文件/网络效果 | Agent 做了什么？ |
| 语义层 | TLS 请求/响应、模型与解码参数 | request、response、model、temperature、top-p、连接/消息 ID | Agent 在哪次调用作出什么决策？ |
| 认知层 | Watson RepCoT、组件消融、judge、汇总 | 候选解释、匹配结果、组件影响、judge verdict、摘要 | 在已有证据下，为什么可能作此决策？ |

### 3.2 调用纳入与排除

**纳入**：文本型 LLM completion；能够配对的 request / response；已知模型与至少 temperature、top-p（未知值必须显式标记）。  
**排除（v1）**：只有 response 的 orphan 记录；流式工具调用中间轮；含不可脱敏敏感数据且未获得实验授权的调用；无法在相同或近似模型重放的调用。

> 当前 `agentsight/test/out/session.db` 的 3 条记录均缺少 `request_body_json`，只能用于检验 response 导出，不能纳入 RQ2–RQ5。P0 必须先在 AgentSight 中补齐 request-response 配对。

## 4. 两阶段实验

### 阶段 A：观测有效性（P0）

目的：证明 AgentSight 不仅“看到了 prompt”，还将请求与响应以稳定 ID 写入同一可查询证据包。

1. 在 WSL2 中运行已复现的 AgentSight 测试；每个任务使用独立 `session.db`。
2. 选择 30–50 个文本任务，覆盖直接回答、检索/总结、代码解释及失败任务；工具任务仅用于跨层对齐，不进入 v1 生成匹配。
3. 以 `connection_id` / `message_id`、PID、方向（write/read）和时间窗口完成 request-response 配对；禁止仅按最近时间戳猜配。
4. 人工抽查 20% 配对，计算配对 precision、recall 与无法判定率。

**通过门槛**：配对 precision ≥ 0.95；不确定配对必须被标记或舍弃，而不是强行匹配。

### 阶段 B：Watson 旁路重建（P1–P4）

对每条入选调用，主 Agent 先完整结束，再启动替身；替身采用与主 Agent 相同的模型、temperature、top-p。若不能完全镜像，报告 `mirror_level=approximate`，不得与严格镜像结果混合。

```text
原始 request + 原始 response
  → 将原始输出作为受约束终点
  → RepCoT 生成候选 reasoning（最多 4 × k 次尝试）
  → 仅保留 FINAL 与原始文本输出规范化后相同的候选
  → Prompt 组件 leave-one-out 消融，测量目标输出可复现性
  → LLM judge 只判断“是否得到观测组件支撑”，不判断隐藏 CoT 真伪
  → 汇总已接受候选，输出不确定性声明
```

候选数设置 `k ∈ {1, 3, 5, 10}`；每项任务固定随机种子（若提供商支持）并记录每次请求的时间、token 与失败原因。

## 5. 对照组

| 组别 | 做法 | 用途 |
|---|---|---|
| RO-SR | 主 Agent 单独运行，无 Watson | 任务成功率、运行时延的基线 |
| WA-SR | 主 Agent 完成后，再旁路运行 Watson | 检验零关键路径干扰 |
| Post-hoc | 将 I/O 交给模型直接“解释原因”，无输出匹配约束 | 验证受约束重建是否比自由解释可靠 |
| RepCoT-no-judge | 有输出匹配，但不做组件消融/judge | 验证验证层的边际价值 |
| RepCoT-full | 输出匹配 + 消融 + judge + 汇总 | 主方法 |

若本地或 API 模型支持 prefix/suffix FIM，可增加 FIM 组；否则不将“未支持 FIM”算作失败。

## 6. 指标与统计

### 6.1 观测与重建

| 指标 | 定义 |
|---|---|
| 配对覆盖率 | 有完整 request-response 的候选调用数 / 可见调用数 |
| 配对准确率 | 人工抽样确认正确配对数 / 被抽检配对数 |
| 输出匹配率 | `FINAL` 与原始输出（去空白等规范化后）一致的候选数 / 总候选数 |
| judge 接受率 | 通过证据一致性 judge 的匹配候选 / 匹配候选 |
| 有效解释率 | 至少获得 1 条接受候选的调用 / 入选调用 |
| 组件影响 | leave-one-out 后目标输出不能复现的比例；无 logprob API 时标记为 `match_ablation` |

### 6.2 成本与干扰

| 指标 | 定义 |
|---|---|
| 每条有效解释成本 | 重建、消融、judge、汇总的总输入/输出 token 与 API 费用 / 有效解释数 |
| 墙钟时间 | Watson 单独耗时；并与主 Agent 关键路径时延分开报告 |
| 观测者效应 | RO-SR 与 WA-SR 的成功率差、95% CI、χ² 或 Fisher 精确检验 |
| 成本—保真曲线 | 在 k=1/3/5/10 下的有效解释率、人工评分、token、时延 |

### 6.3 人工评估（补足 Watson 原文缺口）

随机抽取至少 30 条有完整证据的调用；两名具有 Agent 调试经验的标注者，在**看不到方法组别**的条件下，分别依据 request、response、工具/系统效果评定：

1. 解释是否被现有证据支撑；
2. 是否指出与后续动作相关的关键信息；
3. 是否含无证据的臆测；
4. 对调试是否有用（1–5）。

报告 Cohen’s κ 或 Krippendorff’s α，并比较 full 与 post-hoc / no-judge 组。这里的人工一致性不是“真实 CoT 标注”，而是对**解释证据性和调试效用**的独立评估。

## 7. 跨层 RCA 案例设计

至少选择 3 个故障或异常案例，固定输出以下报告结构：

```text
调用证据：request → model / config → response
认知候选：受约束解释 + 关键 prompt 组件 + 不确定性
行为证据：紧邻 tool call / process / file / network 事件
因果边界：解释支持“关联与可调试假设”，不直接声称内部因果真相
可操作建议：要复查的 prompt、工具结果、配置或下游边
```

## 8. 数据、隐私与密钥

- 原始 prompt、response、系统命令和文件路径默认只保存在本地；导出前应按项目规则脱敏。
- 任何可共享数据集只保留哈希、长度、任务类别、模型配置和经审核的最小文本片段。
- API 密钥仅通过 `WATSON_API_KEY` 等进程环境变量临时传入；**不得**写入 Markdown、源代码、Git、JSONL、终端日志或报告。
- 提供商端点、模型名与价格会影响可复现性；每轮实验必须在结果 manifest 中记录端点版本、模型版本、日期与采样参数，但不记录凭据。

## 9. 执行顺序与停止条件

1. 先完成 P0 配对并通过 ≥95% 质量门槛；否则停止真实重建实验。
2. 用 `python Watson/test_watson.py` 运行离线回归测试；必须通过。
3. 以 5 条调用进行试运行，先报告成本与接受率，再扩展到 30–50 条。
4. 若有效解释率低于 30%，优先排查镜像配置、输出规范化和配对质量，不直接增加候选数。
5. 仅当主 Agent 已结束后才允许调用替身；任何把 Watson 接入主 Agent prompt 或同步阻塞路径的实验一律判为违反设计。

## 11. 原文核对与本轮勘误（2026-09-20）

- 原文第 4 页：RepCoT 不将目标答案送入候选生成；相同输入附加解释指令后独立采样，再依据输出语义等价性拒绝采样。当前实现修正了答案泄漏，但仍用严格文本匹配近似语义等价判定。
- 原文 Table II 的 RO-SR 是 Response-Only Self-Reflection，WA-SR 是 Watson-Aided Self-Reflection。上文第 5 节将其写成独立运行/旁路运行不准确；若测旁路开销，应另设 primary-only 与 primary-plus-offline-observation 条件，不应混用原文缩写。
- p > 0.05 仅表示未检出差异，不能证明零干扰或等效。非干扰实验需要预先定义可接受差异界限、样本量与等效性检验，并单独测量关键路径延迟。
- 本轮完成 16 组离线故障注入及数据库只读审计，详见 out/offline_experiment/report.md。真实模型实验尚未进行：现有 3 条调用均无 request。
