# 周报（2026-09-30 ~ 2026-10-13）

**一句话总结：**本阶段将上一份周报中的 Trace Adapter 输入准备推进为可运行、可审计的归因前观测链：完成应用事件协议、真实框架事件解析、跨层工具身份对齐、PID namespace 直接映射、时钟统一、质量门和可重放证据收据；共执行 11 个真实 CLI Agent 会话并量化 AgentSight 工具漏采，同时吸收 RCACopilot、OpenRCA、Watson 和 OpenRCA 2.0 的设计，最终形成 101 项测试通过的归因前实现和一个 AgentOps 可视化控制台。当前仍未进入正式归因算法和统计性评测。

**本阶段主工作：**先实现保守的候选对齐和显式应用事件协议，再通过真实双 Agent 任务检查工具身份、故障步骤和责任边；真实实验暴露出 AgentSight 工具漏采、PID namespace 不同和时钟坐标不统一的问题。随后将工作重点转到归因前证据质量，完成直接 PID 映射、非零时钟不确定度、确定性回放、逐关系查询收据和模型调用上下文协议。当前观测链在单进程本地实测中已经获得直接身份真值，但真实多 Agent 联合验证仍受预算门限制。

## 1. 本阶段主要工作：从输入规范化推进到归因前证据链

### 1.1 完成候选对齐、来源审计和显式应用事件协议

承接上一份周报中已经完成的 manifest、SQLite 解析和证据规范化，本阶段新增了系统侧候选对齐器与一致性审计器。对齐过程只消费原始观测和应用日志，校验来源 SHA256，并区分 `accepted`、`uncertain` 和 `abstain`；已有派生 trace 和 validator 不得补造缺失事件。两次真实观测中的 356 项已接受进程关联与原始 SQLite PID/生命周期约束一致，但这项一致性检查不等于独立语义真值或归因准确率。

随后实现应用事件协议及严格 writer/reader，显式保存 run、session、Agent、Step、tool_call、process scope 和 clock scope。协议检查包括连续序号、生命周期闭合、身份不可中途变化、工具 ID 不可重复和异常中断不得伪装为完整流。离线协议夹具完成 20/20 场景验证，历史上只有最终摘要的应用日志被明确拒绝为完整事件输入。

### 1.2 接入真实框架原生事件并建立跨层工具身份

真实 Claude 原生流解析器能够读取 init、tool use、tool result 和 result，并保留原始行号、接收时钟及原生 tool_call ID。跨层对齐实现了三种模式：

| 模式 | 证据条件 | 当前作用 |
|---|---|---|
| `process-and-tool` | PID、进程范围、时间和工具 ID 同时一致 | 最严格，但早期真实运行因 PID/时钟坐标不同而 abstain |
| `shared-tool-id` | 原生工具 ID 与 AgentSight 工具 ID 唯一匹配 | 可建立工具身份，但不声称 PID 或时钟已经统一 |
| `session-and-tool` | session 对应系统 LLM PID，且工具 ID 指向同一 PID | 当前真实受控任务中的最强工具身份依据 |

在一次完整真实受控运行中，3 次应用工具调用与 3 条 AgentSight 工具记录全部对齐，程序在不读取预设真值的情况下产生唯一失败触发候选 `agent_b.Bash_1`；Agent 级候选与调用前冻结的真值一致。该结果只证明一条受控运行的链路可行，不能写成总体归因准确率。

### 1.3 把归因前质量要求变成机器可执行门

事件协议已升级到 v0.2，并形成统一质量门：

- 真实六事件流 `session.start → step.start → tool.start → tool.end → step.end → session.end` 完整闭合；
- 必需字段完整率达到 114/114；
- 同一输入两次回放字节一致；
- 8/8 类无效协议被拒绝；
- 根因、责任和因果路径输出在归因前阶段固定为 `false`；
- 身份门未通过时拒绝构图，时钟门未通过时只允许 sequence order，不允许严格跨层时间边。

目前实现已从“格式正确”推进到“每条观察关系有来源、查询和拒答边界”。Trace Adapter 完整测试由上一阶段的 20 项增长到 101 项，当前全部通过。

| 用 Trace 瀑布、身份图、时钟质量和查询收据可视化实验，而不是只展示成功率 | [OpenTelemetry Traces](https://opentelemetry.io/docs/concepts/signals/traces/)把瀑布图作为常见 Trace 展示方式；OpenRCA 2.0 的边/路径评价要求能检查中间过程 | 当前工作的主要产物是“证据链是否完整”，只有总成功率无法显示哪个 Step、身份映射或时钟门失败。分层页面使失败位置和证据等级可直接检查 | Trace 展示形式有标准实践依据；本地控制台的信息架构是 `INFERRED` 设计，不构成方法效果证据 |

因此，本阶段的关键逻辑不是“为了工程完整而增加字段”，而是先建立可以被复核的观测事实，再允许后续归因算法消费这些事实。若身份、时间、捕获完整性或调用条件任一门未通过，系统只能输出候选或拒答，不能升级为责任和因果结论。

据此新增了四类证据 handler：框架生命周期、进程身份、观测器时钟和模型调用上下文；真实六事件流生成 5 个精确查询和 3 条结构关系，5/5 查询重放一致，3/3 关系具备事件与查询收据。历史真实会话缺少完整模型调用条件，因此 Watson 式重建保持 `NOT_READY`，没有使用默认值补造。

本阶段文献判断也进一步收紧了创新点：论文不能只声称“构建可验证传播图”，而应聚焦于多 Agent 场景中消息、工具、模型调用、进程和系统事件的统一身份，以及产生错误、传播错误、未拦截错误和放大错误等责任语义。

## 3. 本阶段确定和收紧的研究方向

当前主线进一步明确为：

```text
框架原生生命周期 + 模型/工具调用
        + AgentSight/eBPF 进程、文件、网络、资源观测
        + 独立任务判据
        ↓
证据有界的 Trace Adapter
        ↓
可查询、可重放、可验哈希的 identity/tool provenance graph
        ↓
Agent / Step / Edge 责任候选
        ↓
局部重放、消息/工具结果替换、通信边剪除与可拒答归因
```

与上一份周报相比，研究方向有三点实质变化：

1. 观测关系必须附原始事件和可重放查询收据，不能只给自然语言解释；
2. PID 映射、时钟界和捕获缺失必须进入协议状态，不能用启发式结果冒充直接事实；
3. 后续归因需要区分应用层语义定位和系统层观测覆盖，分别报告 Agent/Step/Edge exact、捕获率和 abstain 率。

## 4. 本阶段实验和工程打通内容

### 4.1 真实 API 与跨故障实验

从 9 月 30 日到 10 月 13 日，共执行 11 个真实 CLI Agent 会话，均为最小实验，没有自动批量重试：

- 双 Agent 原生事件 canary：2 个会话，4 次应用工具调用，AgentSight 捕获 3 次；
- 完整真实进度实验：2 个会话，3/3 工具调用以 `session-and-tool` 模式对齐；
- 错误传播与路由错误：各 2 个会话，共 4 个会话；两个单例场景的 fault type、责任 Agent、责任 Step、责任边和传播边均与调用前冻结真值一致，但每个场景的系统工具记录仍为 3/4；
- 框架原生事件、进程和时钟实验：3 个单会话运行，依次验证初版时钟问题、纳秒 boot epoch 修复和 SSE 时钟透传。

两类真实故障场景当前样本量均为 1，只能作为可行性案例，不能形成统计准确率或泛化结论。

### 4.2 AgentSight 工具捕获完整性诊断

对 4 次真实运行进行零 API 聚合检查，共发现 15 次原生工具调用和 12 条 AgentSight 工具记录，小样本捕获覆盖为 80%。缺失工具分别为 Read、Bash 和 Write，3 个缺失 tool_call ID 在 SQLite 任一表中均不存在，说明缺失发生在规范化和对齐之前。

为此新增 `capture_incomplete` 门：原生工具数、系统工具数和 accepted 数不能一一相等时，禁止生成系统层 Edge 完整性结论。80% 是这 4 次运行的诊断统计，不是 AgentSight 的通用捕获率。

### 4.3 PID namespace 与时钟统一

早期真实运行中，应用 PID 81 与 AgentSight PID 341/1758 属于不同 PID namespace；最初只能通过 session、进程名、启动区间和共享 tool ID 间接支持对应关系。时钟方面，首次实测发现 AgentSight 使用整数秒 boot epoch，产生 413.555968 ms 的转换缺口；修复后纳秒 boot epoch 使进程开始时间直接落入 Popen 区间，追加校正量为 0。

随后完成 SSE `_agentsight_clock` 透传，真实工具记录保存了 raw boot time、boot epoch 和转换公式。最新本地原生身份实验进一步使用 `bpf_get_ns_current_pid_tgid`，在同一 EXEC 事件中获得：

```text
initial namespace PID = 1791
collector namespace PID = 34
userspace PID = 34
mapping evidence = bpf.pidns.tgid=1791,34
anchor uncertainty floor = 1 ns
```

这使单进程本地实测的 PID 对齐从 `inferred` 提升为 `accepted`，并证明非零时钟分辨率下界能够写入事件。真实双 Agent 会话中的覆盖率和稳定性仍未验证。

### 4.4 实验记录与可视化

建立 `lab/experiment/` 统一目录，当前登记 40 条 2026-10-10 之前的历史运行和 7 个当前实验目录。历史原文件没有移动；其中 8 条时间由运行名直接验证，32 条按最早存续文件时间推断并标记为 `INFERRED`。

## 6. 本阶段遇到的问题和成本控制

- AgentSight 工具记录存在间歇性漏采。现有 4 次真实运行为 12/15，缺失不固定在单一工具类型；根因仍未定位到 SSE、会话时序、数据库写入或具体版本层。
- 应用与观测器处在不同 PID namespace，早期 PID 数字不能直接比较；目前已在本地进程事件中加入指定 namespace TGID，但缺少真实多 Agent 端到端验证。
- 历史 observer clock 的 uncertainty 为 0 只代表旧实现没有纳入系统分辨率下界，不能解释为真实误差为零；新实现已加入至少 1 ns 下界。
- 真实 CLI 会话在本阶段新增报告费用合计约 **0.330180 USD**。扩大本地日志扫描并按 provider session ID 去重后，发现历史台账漏计 4 个唯一会话、合计 0.5328595 USD；因此全仓累计费用修正为 **2.183708 USD**。这项增加主要是历史账本范围修正，不是本阶段重复调用。
- 现行 2.00 USD 硬停止线已经触发。计划中的两次真实会话最坏增加 0.10 USD，预计累计 2.283708 USD，因此预算预检返回 `BLOCKED`，本阶段最后的 PID/时钟实验没有发起网络调用。
