# 周报（2026-09-16 ~ 2026-09-22）

**一句话总结：**本周主要把上周的论文调研进一步落实到实验和评价体系上，初步跑通了 Watson 的旁路重建流程，整理了 AgentSight 的完整输出证据链，同时围绕多智能体协作、故障传播和边级归因补充论文与指标，进一步将方向收敛为“观测—边级归因—反事实验证—安全干预”的闭环。

**为何要做？：**上周已经找到 AgentSight、Watson 和 Who&When 分别对应系统观测、推理步骤观测和故障归因，但还不确定这些工作能否真正串成一条可运行的实验链路，也缺少一套能够评价观测质量、归因准确性和修复效果的指标。因此本周的重点是验证现有工具的真实数据边界，并把候选方向从论文概念进一步细化为可执行、可评价的实验问题。

**怎么做的？：**首先对 AgentSight 的实验输出进行了逐文件整理，明确了进程、系统调用、网络端点、模型调用、Token、工具调用和文件副作用等数据分别存在哪里，以及后续如何通过时间、PID 和调用记录建立证据链。然后按照 Watson 的 RepCoT 思路实现并检查了“输入读取—候选解释生成—目标输出匹配—组件消融—Judge—汇总”的旁路流程，完成 4 种故障场景、4 种候选数量设置下的 16 组离线流程实验，并使用真实 DeepSeek API 跑了两个小型文本决策任务。论文方面补充分析了信息传播、TraceElephant、MAST、MultiAgentBench 等与多智能体协作、拓扑和故障归因有关的工作；同时在 `my_paper/metric` 中整理了任务效果、负载、Trace 数据质量、Agent/Step/Edge 归因、拓扑修复和统计报告指标，并补充了国家标准、ISO、NIST、OpenTelemetry 和近年顶会论文依据。

**有何结果？：**第一，Watson 的近似旁路流程已经可以运行：离线 16 组实验的断言通过，真实小样例共发起 12 次 API 请求且没有失败，两个任务都生成了能够通过输出匹配和 Judge 的解释候选；但目前采用严格文本匹配和二值消融，还没有复现原论文的概率归因、Top/Bottom-n 验证和大规模基准，因此只能说明流程可行，不能说明解释就是模型真实推理。第二，AgentSight 能够提供跨系统层和 Agent 层的多类运行证据，但现有样例的请求—响应配对仍是主要瓶颈：审计的 3 条历史模型调用都缺少 request，可直接进入 Watson 真实重建的样本为 0。这说明下一步应先解决观测数据的可靠配对，而不是直接扩大 Watson 实验。第三，通过论文和指标整理进一步确认，现有工作大多评价“哪个 Agent、哪一步出错”或整体协作质量，对 Span 之间的错误传播边、边级反事实作用和归因后的安全修复仍缺少统一方法；因此边级归因仍可作为当前方向，但必须用完整 Trace、可 Replay 失败样本和明确的 Edge 真值进行验证。

**下步计划？：**先把 AgentSight 中模型请求和响应的关联补完整，优先使用连接、消息标识、进程和方向信息验证配对 Precision、Recall 和 F1，达到可用门槛后再接入 Watson。随后选择 20～30 条可以 Replay 的失败 Trace，构造工具静默错误、错误信息传播和子 Agent 异常等场景，标注责任 Agent、决定性步骤和失败传播边；先复现 Who&When 的 Agent/Step 级归因作为基线，再尝试加入系统层与语义层 Trace 证据，比较“仅最终输出、完整静态 Trace、完整 Trace 加 Replay”三种条件。只有边级定位和反事实验证稳定后，再进入剪边、重路由或回滚等自治修复实验。
