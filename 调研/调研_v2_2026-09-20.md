## 一、论文总结（七维之一）

| 论文 | 核心问题 / 动机 | 核心方法 | 主要贡献 | 关键结论 |
|---|---|---|---|---|
| **AgentOps** | LLM 智能体的**自主性、非确定性、持续演化**带来 AI 安全担忧；从 DevOps 视角，可观测性是保障 AI 安全的前提，但"该追踪什么"缺乏统一认识 | **系统映射研究**（遵循 Kitchenham + Garousi 灰色文献指南）：GitHub 4 组检索词 + Google Search + 灰色文献 → 17 个工具 | ① 智能体工件**实体关系模型**（Fig.2）<br>② **AgentOps 分类法**（Fig.3）：**9 类 Span** + 7 项通用元数据 + 每类专属元数据 | **本文不建系统，它给领域"命名"** ——把"该追踪什么、到什么粒度"系统化为可共享的模板 |
| **AgentSight** | 智能体的"高层意图"与"底层系统动作"之间存在**语义鸿沟**；应用层插桩脆弱易绕过、系统层监控缺乏语义 | **边界追踪（boundary tracing）**：在应用代码**之外**的稳定边界（内核 + 网络）监控。三大组件：eBPF 统一探测 / 多信号因果关联引擎 / LLM 驱动语义分析 | ① 用**稳定的系统边界**绕开易变的框架实现<br>② 三信号关联（进程谱系 + 时间邻近 + 参数匹配）<br>③ "AI to watch AI" | **观测点的选择比观测手段更重要**；「插桩可以被绕过，边界不能被绕过」 |
| **Watson** | Agentware 采用「快速思考」模式，**推理不可见**；让模型输出 CoT 会**改变行为（准确率最多降 36%）**，事后追问的解释又**不忠实**——"既不能边想边说，也不能事后问" | **认知可观测性**：**旁路替代 agent** 镜像主 agent 的模型与解码参数；用 **FIM** 或 **RepCoT** 重建推理；**PromptExp 归因 + LLM-as-a-judge(n=10)** 验证；汇总成元推理总结 | ① 提出 AgentOps 第三层（认知层）<br>② 旁路重建 + 镜像原则<br>③ **三层可观测性模型**（操作/语义/认知） | **观测不能改变被观测对象**（RQ2 证明零干扰）；推理与答案强耦合但非绑定 |
| **Who&When** | MAS 的**故障归因**长期靠人工，昂贵且依赖专家；已有工作只造更细 benchmark，**未解决"评测结果 → 待改进组件"的映射** | 形式化**自动故障归因**新问题；用**干预式反事实定义「决定性错误」**（修好这一处就成功）；构建 Who&When 基准；设计 3 种 LLM 归因方法 + Hybrid | ① 提出并形式化一个全新研究问题<br>② **Who&When 基准**（127 系统 / 184 任务，84 人时三轮标注）<br>③ 诚实的负面结果报告 | **该问题远未解决**——Agent 级 53.5% / Step 级 14.2%，部分方法甚至低于随机 |
| **AgentMonitor** | MAS 配置难、性能只能事后观察；恶意 Agent 破坏系统安全 | **即插即用非侵入**：一行注册包装 → 采集**两类指标**（LLM 判官分数 + 图属性）→ **XGBoost 回归**预测下游表现；推理链插入 **post-edit** 对齐 LLM | ① 非侵入的性能预测框架<br>② 1,796 点数据集<br>③ 监控能力**顺手转化为安全能力** | **不解释机制，只预测结果**——工程上极其务实；廉价特征 + 少量昂贵采样即可预测 |
| **AgentDropout** | MAS **token 消耗巨大且效率低下**；已有方法（GPTSwarm/AgentPrune）**只剪边、不剪节点**，且**所有轮次用同一套策略** | 把通信图转为**可训练加权图**，用**无偏策略梯度**优化邻接矩阵：**① 节点丢弃**（剔除加权入出度最小者）→ **② 边丢弃**（核范数代替秩做低秩稀疏约束）；推理时 **DAGSample** 采样 | ① 「**节点冗余 vs 边冗余**」的正交分解<br>② 逐轮动态带来**双重收益**（性能 + completion token）<br>③ **40 条样本学拓扑** | **冗余有两种来源**——补上了 AgentPrune 忽视的"节点冗余"；**随机剪枝对照**排除了"链变短"的替代解释 |
| **Beyond NL** | 正面挑战一个普遍默认的假设——**自然语言（NL）是 LLM 推理和多智能体通信的最优格式** | **AutoForm**：在 CoT 提示中追加一句"考虑使用更结构化、更简洁的格式"，让 LLM **自主决定**格式（code/JSON/Markdown 表格/逻辑表达式/数学方程/列表）；两步版从 5 个输入推任务级通用格式 | ① 质疑共识 + 控制变量的范式文章<br>② **AutoForm**<br>③ **自发涌现的 ACL ≈ KQML** | **"格式"是被严重低估的优化维度**；一行 prompt 最高省 72.7% |
| **DistServe** | 现有系统把 **prefill** 和 **decode** 共置同批 GPU 混批以最大化吞吐量；**本文指出在 SLO 约束下这是代价高昂的错误选择**——两阶段干扰、调度失效、资源与并行度耦合 | 把两阶段**物理分离到不同 GPU**（disaggregation），各自独立优化；带宽感知的**放置算法**；**M/D/1 排队论**推导切换条件 | ① **重新定义优化目标**（per-GPU goodput）<br>② DistServe 系统 + 放置算法<br>③ 在线调度（抗气泡 + pull-based + replanning） | **目标函数选错，整个设计方向就错了**——比"分离"这个具体手段更有普适价值 |

## 二、应用场景（七维之二）

| 论文 | 主场景 | 衍生场景 | 适用边界（何时不该用） |
|---|---|---|---|
| **AgentOps** | **智能体全生命周期的可观测性基础设施**：原型→生产过渡、故障排查与根因定位、性能优化、评估与回归测试、提示词治理、人类反馈闭环、安全审计与合规、成本管理 | **三类隐含利益相关者**：智能体所有者 / 基础模型提供方 / 外部工具与智能体提供方（**Shared Accountability 责任共担**） | 分类法是**参考模板**而非强制标准；仅针对 LLM agents（含 agentic systems）；**不含**存储/传输/查询技术选型 |
| **AgentSight** | **安全检测**（首要）：间接提示注入、数据外泄识别、软件供应链攻击、上下文感知威胁判定 | **成本与可靠性**：推理循环/死循环检测、异常资源消耗告警、非确定性行为调试<br>**多智能体运维**：协调瓶颈定位、角色划分优化<br>**泛化**：生产 AgentOps 底座、审计取证、DevSecOps 集成 | 依赖 Linux + eBPF + OpenSSL；需内核 BPF 权限；**只能看不能拦**（无阻断能力） |
| **Watson** | **Agentware 的调试与故障诊断**（论文主场景）：读到推理偏差 → 一句 hint 即修正 | **按需的推理重建服务**（可观测性平台/IDE/CI-CD/生产看板，**零侵入零延迟**）；AI 安全审计；提示工程量化优化；过程监督数据生产 | 只覆盖**文本推理 agent**；成本不透明；重建忠实性缺人类金标准 |
| **Who&When** | **多智能体系统开发与调试**（论文主场景） | **统计视角**的低成本系统性改进（数据集级诊断而非逐条精确定位）；与系统级可观测性互补的根因分析 | ⚠️ **绝对性能远不可用**（Agent 53.5% / Step 14.2%）；长日志（>93 步）准确率趋近 0%；未验证"改后是否变好" |
| **AgentMonitor** | **MAS 架构选型 / A-B 测试前的预筛**——在跑昂贵端到端评测前先预测得分，只把高分配置送入真实评测 | **运行时成本控制**（偷看模式：10% 样本）；**Agent 角色/拓扑调优**（图指标提供可解释的优化方向）；**多智能体安全护栏**（post-edit）；**系统健康监控/异常识别** | **单 Agent 场景**（指标全为多 Agent 拓扑设计）；**冷启动场景**（XGBoost 需域内历史数据）；**架构变化剧烈**（跨架构仅 0.58）；**安全要求极高**（post-edit 只能缓解不能保证） |
| **AgentDropout** | **生产环境 MAS 的 token 成本优化**（论文主场景）：MAS token 消耗可达单智能体的 **30–70 倍** | **少样本新任务快速适配**（同类别拓扑可迁移、**训练样本越难迁移越好**）；**弱模型稳定性补强**；**成本敏感的边缘/端侧 MAS**；**提示工程与角色设计**（节点重要性度量可反向指导人工角色设计）；**多机/多传感器协同决策**（直接迁移） | DAG 约束**不支持循环辩论**；需一次离线拓扑学习；提升幅度随模型变强衰减 |
| **Beyond NL** | **多智能体系统降本**（token 直降 20%–74%，近乎零成本的降本手段）；**单模型推理提效**（+3.3~5.7%，纯 prompt engineering） | **符号/因果推理任务救急**（Coin Flip 提升最显著）；**上下文长度受限场景**（Narrative QA 书籍减 74.6%）；**设计新智能体通信协议**；**长程 Agent 流水线** | ⚠️ **弱模型担任发起方**（GPT-3.5 作 initiator 时常低于基线，甚至幻觉答案）；**信息必要性类任务**；**需 NL 丰富表达的任务**（开放式创作、共情对话）；**格式选择本身也有成本** |
| **DistServe** | **有延迟 SLO 约束的在线 LLM 服务**：Chatbot（重 TPOT）、Code Completion（双 SLO 严格）、Summarization（长输入 + 重 TPOT，**提升最大**） | **大规模分布式部署**（放置算法处理网络带宽约束）；跨节点集群（High/Low 两种算法） | ⚠️ **离线吞吐优先** ❌（chunked-prefill 更好）；**单 GPU / 极少 GPU** ❌；**不实现抢占与容错**（有故障传播风险）；⚠️ 新架构（GQA/MQA）表现更好但未实测 |

## 四、实验平台（七维之四）

| **AgentMonitor** | ① **"可预测性"是与"可观测性"互补的独立技术线**（不解释机制，只预测结果）<br>② **"配置决定型指标"（零成本）与"推理型指标"（高成本）分层**是可复用设计<br>③ **泛化边界要按维度拆开评估**（5 种划分方法论值得迁移）<br>④ **监控能力可顺手转化为安全能力**<br>⑤ **用非线性模型是"发现驱动"的**（先发现非单调，才选 XGBoost） | ⚠️ **跨架构泛化不足**（Cross-Arch/Task 平均约 0.58）<br>⚠️ **需要域内训练数据**（冷启动不可用）<br>⚠️ LLM 判官存在**低估偏差**<br>⚠️ 安全-有用性权衡难两全 | 提升跨架构泛化、降低冷启动门槛、改进 LLM 判官偏差 |
| **AgentDropout** | ① **「冗余的两种来源」是漂亮的分解**——节点冗余 + 边冗余（"看别人漏了什么"式创新）<br>② **「逐轮动态 vs 全局统一」一个改动两个收益**（性能 + completion token）<br>③ **Random Dropout 对照是排他性论证的教科书做法**<br>④ **"40 条样本学拓扑"** ——一次性拓扑学习 + 长期推理省钱的 ROI 极划算<br>⑤ **「丢弃率→性能降得慢、成本降得快」**从反面证明 MAS 通信冗余规模之大 | ⚠️ **提升幅度小且随模型变强急剧衰减（2.19→0.47）**<br>⚠️ **无任何显著性检验**<br>⚠️ **未报告测试集规模、训练步数、拓扑学习开销**（净利润无法核算）<br>⚠️ **Learned Edge Dropout 低于 Random** 这个反例未讨论<br>⚠️ **DAG 约束不支持循环辩论**<br>⚠️ α/β 全局统一与"逐轮动态"的核心论点存在张力<br>⚠️ "domain transferability"实为同域跨数据集 | 扩展到循环拓扑、逐轮自适应 α/β、报告完整开销 |
| **Beyond NL** | ① **"重新审视默认假设"的范式文章**（质疑共识 + 控制变量，低资源高产出）<br>② **"格式"是被严重低估的优化维度**——一行 prompt 省 72.7%<br>③ **"从 5 个输入推任务级通用格式"是高杠杆设计**（一次性决策、全任务复用）<br>④ **"自发涌现的 ACL"是值得深挖的理论线索**——结构化通信可能是自然吸引子<br>⑤ **诚实报告反向结果是分析质量的分水岭** | ⚠️ **无显著性检验**<br>⚠️ **未报告采样参数**<br>⚠️ **样本量小**<br>⚠️ **格式分布靠人工统计**<br>⚠️ **提升幅度普遍小于标准差**<br>⚠️ GPT-3.5 作 initiator 时的下降需专门优化提示词 | 为弱模型优化提示词、扩大样本、增加显著性检验 |
| **DistServe** | ① **"识别系统级反模式"的经典范式**——从"大家都在做"中找错<br>② **目标函数选错，整个设计方向就错了**（比"分离"这个手段更有普适价值）<br>③ **"分离"是可迁移的系统设计模式**——判据：当两个负载的计算特征与优化目标根本不同时，共置必然导致效率损失<br>④ ⚠️ **关于"平行工作"的重要警示**：Splitwise / Tetris-Infer / DéjàVu 三篇同期并行工作 → **该方向已接近饱和** | ⚠️ **SLO 凭经验设定**（无公开 SLO，结论对取值高度敏感）<br>⚠️ **泊松到达假设**（真实负载有突发性，pull-based 机制正是为突发设计但**未实验验证**）<br>⚠️ **未报告采样条数、无统计显著性检验**<br>⚠️ **LongBench 被截断到 2048**（长上下文论证是**理论外推而非实验**）<br>⚠️ **仅 OPT 系列**（未测 GQA/MQA）<br>⚠️ **不含抢占与容错**（分离引入故障传播风险） | **抢占**（FCFS 有"护航效应"）；**容错**（分离引入了新的故障传播风险） |

# 附录 A：实验计划（原 计划1）

# 计划 1：多层 Agent 可观测性实验计划（全论文集对齐版）

> 版本：2026-09-18。以“先完成观测，再验证观测能否支撑诊断与干预”为主线。本文将论文方向下已调研的 **16 篇工作**转化为可执行实验，而非把它们拼成一个无法证伪的大系统。Watson 子实验的实现级细节见 [Watsom/实验设计.md](Watsom/实验设计.md)。

## 1. 总目标、中心问题与边界

### 总目标

构建并评估一条**零/低侵入、可审计、分层按需升级**的 Agent 观测链，使其从系统行为事实逐级走向语义证据、认知解释、故障诊断与可控干预：

```text
AgentOps Span+Edge 契约（定义该观测什么）
                ↓
AgentSight / eInfer 跨层采集（系统事实）
                ↓
完整语义 Trace（请求、响应、工具、配置、系统效果）
                ↓
Watson 旁路认知解释 + Who&When / CDC / AgentTrace 诊断
                ↓
Edge / CAPE 因果验证、性能预测与安全/成本评估
                ↓
AgentDropout / AutoForm / DistServe 的受验证干预（后续阶段）
```

### 中心研究问题

1. **观测完整性**：不修改 Agent 代码时，能否可靠地把 LLM 请求—响应、工具调用与进程/文件/网络/推理系统事件配对为同一条 trace？
2. **观测有效性**：更完整且跨层的证据，能否改善 step/edge 级定位、认知解释与性能预测？
3. **观测经济性**：按需触发 Watson、反事实 replay 等高成本步骤，能否在不影响主任务的条件下控制 token、时延与资源开销？
4. **闭环价值（后续）**：被验证的失败边能否安全地驱动通信、表达或服务资源的局部改动？

### 本计划的阶段边界

**阶段 I（当前）只宣称“观测”。** 交付可配对的、可重放的 span+edge 证据包，完成 Watson 的旁路复现和对照。诊断、预测、优化作为观测价值的下游实验；它们必须在证据质量通过门槛后启动。

| **Beyond Natural Language / AutoForm** | 格式是独立优化维度；3 次重复；格式消融 | M6 后续干预：同拓扑下表达格式消融、token/准确率/可解析性 |
| **DistServe** | TTFT/TPOT 与 goodput；消融和模拟/真实系统对照 | M1b/M6：推理服务证据与 SLO，不能只报告平均吞吐 |

> **定位**：本研究不以“重新实现所有论文”为目标。每篇论文贡献的是一个必要对照、指标或实验纪律；核心创新验证是“系统事实 + 语义 + 认知证据如何提高 span/edge 级可诊断性，并为受验证干预提供输入”。

## 3. 实验对象、数据与证据契约（M0）

### 3.1 统一 Span+Edge 数据模型

以 AgentOps 的 9 类 Span 为骨架，补充可观测的边；每条记录都必须包含 `trace_id`、`span_id`、来源、时间、证据等级与脱敏状态。

| 对象 | 最少字段 | 初始来源 | 完成判据 |
|---|---|---|---|
| Agent / Task / LLM Span | 角色、任务、模型、解码参数、输入/输出引用、开始/结束时间 | AgentSight TLS / session | 主调用的模型和 I/O 可审计 |
| Tool / Evaluation / Guardrail Span | 工具名、参数/结果引用、状态、验证规则 | AgentSight / Agent 原生日志 | 工具结果能关联上下游调用 |
| System Span | PID、父子关系、命令、文件、网络、资源、GPU（可选） | AgentSight eBPF / eInfer | 原始系统事件可回溯 |
| Sequential Edge | 同 Agent 的因果时序、时间置信度 | 调用/事件时间线 | 不产生时间倒置 |
| Communication Edge | 发送—接收、消息/连接 ID、角色 | TLS / Agent 消息 | request-response 不是只靠时间猜配 |
| Data Edge | 输出字段→下游输入字段、匹配证据 | 请求/响应/工具结果 | 有内容哈希或显式变量证据 |
| Responsibility Edge | 委派、验证/恢复机会、责任角色 | 任务配置 + TraceElephant 规则 | 能标记“上游错”与“下游失责” |
| Causal-propagation Edge | 候选原因→后果、观测/反事实置信度 | M4 | 未反事实验证时只能标“候选” |

### 3.1.1 语义层的论文依据与字段来源

“TLS 请求/响应、模型与解码参数”这一语义层不是由单篇论文完整给出的，而是四项工作互补后的设计：**AgentSight 解决零侵入采集，TraceElephant 定义完整 trace，AgentOps 规范 Span 元数据，Watson 规定镜像必须保留的解码配置。** 必须分开这四种职责，避免把“能截获 TLS”误说成“已得到完整、可重放的语义 trace”。

| 论文 | 对语义层的直接依据 | 本计划继承的字段 / 规则 | 不能外推的结论 |
|---|---|---|---|
| **AgentSight** | 在 SSL/TLS 调用与系统边界零插桩获取 LLM 交互；以进程谱系、时间邻近、参数匹配关联意图流与动作流 | `request`、`response`、开始/结束时间、PID/TID、连接/消息关联证据、紧邻工具/文件/网络事实 | 当前 AgentSight 案例不保证每条 request 与 response 都已经配对落库；P0 必须测配对 precision/recall |
| **TraceElephant** | 完整 trace schema：`input_context`、`output_content`、`tool_logs`、`agent_configuration`、`system_architecture`；full trace 与可 replay 配置有助于归因 | 请求/响应外，还保存工具输入输出、角色、任务/架构上下文、配置、可 replay 引用 | 它依赖 API/中间件日志，并不证明 eBPF 天然可恢复全部字段；缺失字段必须显式记录 |
| **AgentOps** | 9 类 Span 与通用/专属元数据规定可追踪工件的组织方式 | 将 LLM、Agent、Task、Tool、Evaluation 等统一为 Span；每条语义记录携带来源、时间、ID、配置、脱敏状态 | AgentOps 未形式化 Span 间边；连接/消息 ID、数据/责任边是本计划扩展，需独立评测 |
| **Watson** | 镜像原则：surrogate 应匹配 primary 的基础模型与解码配置，否则不在同一生成分布 | `model`、`temperature`、`top_p`、`top_k`（如有）、max tokens、seed（如支持）、系统提示与工具定义版本；未知值必须为 `unknown`，禁止默认填补 | 配置相同不等于可得到真实隐藏 CoT；它只是旁路解释的必要镜像条件 |

因此语义层的最小记录单位定义为：

```text
SemanticCall = {
  trace_id, span_id, request_id, response_id, connection/message evidence,
  timestamp_start/end, pid/tid, agent/role/task context,
  model + decoding configuration, request payload, response payload,
  tool-call / tool-result references, source, confidence, redaction status
}
```

其中，`connection/message evidence` 来自 AgentSight，完整上下文和工具结构参考 TraceElephant，Span 的字段组织参考 AgentOps，镜像所需参数参考 Watson。只有这些字段同时满足时，调用才能进入 Watson 严格镜像实验；缺少 request 或关键参数的调用只能用于系统观测，不能用于认知重建或因果验证。

### 3.2 当前观测硬缺口与 P0

已有 AgentSight 复现确认 eBPF 可捕获 LLM 响应、工具、文件、网络和进程；但现存 `agentsight/test/out/session.db` 的 3 个 `llm_calls` 缺少 `request_body_json`。因此当前不能把“看见 prompt 的片段”误称为完整的 request-response trace。

**P0：请求—响应配对落库。** 以连接/消息 ID、流方向、PID/TID、时间与协议事件做可审计配对；禁止只以最近时间戳配对。输出一个 manifest，给出配对来源和置信度。

| P0 指标 | 门槛 | 验证方式 |
|---|---:|---|
| 请求—响应配对 precision | ≥ 95% | 双人抽检 20% 样本 |
| 入选文本调用的完整率 | ≥ 90% | 有 request、response、模型、时间、来源 ID |
| orphan 透明度 | 100% | 所有不完整记录显式标记，不强配 |
| 可重放率 | ≥ 80% | 脱敏后仍可构建符合原配置的调用 |

## 4. 分阶段实验设计与验收（M1–M6）

### M1：系统与语义观测正确性、侵入性和覆盖

**目的**：复现并扩展 AgentSight 的核心主张，建立后续所有实验的地面事实。

- 工作负载：现有 Claude Code + DeepSeek 最小文件任务；另加文本问答、工具失败、重试/循环、两 Agent 委派各至少 10 次。
- 对照：AgentSight-off、AgentSight-on；若可用，再与 Agent 原生日志 / OpenTelemetry 导出对齐。
- 指标：事件 recall/precision、request-response 完整率、跨层关联正确率、CPU/内存、主任务时延、token、事件压缩比、原始证据保留率。
- 重复：每个工作负载至少 3 次；报告均值、标准差、95% CI，而非只报单次平均。
- 安全子集：以 InjecAgent 风格的间接注入、数据外传、推理循环为场景；报告 precision、recall、F1、FPR，而不只展示案例。

**通过条件**：P0 合格；观测开启不改变主 Agent prompt/工具权限；性能指标与 off 组的差异及置信区间完整报告。

### M1b：推理服务与跨层执行图（可选硬件模块）

若有 Linux + GPU + 分布式推理环境，补充 eInfer 风格事件：prefill/decode、KV-cache、CPU-GPU 切换、NCCL/PCIe 传输。评测不用“吞吐量”单指标，而记录 **TTFT、TPOT、SLO attainment、per-GPU goodput**（DistServe）。

无该环境时，保持 schema 和 mock event，不将其视为系统层证据，更不以缺失的 GPU 信号作因果结论。

### M2：Watson 认知可观测性复现

实现已置于 `Watsom/`，具体流程、代码和指标见 [Watsom/实验设计.md](Watsom/实验设计.md)。本计划中只规定其与其他模块的接口：

1. 主 Agent 结束后才调用替身；模型/temperature/top-p 一致为 strict mirror，不一致显式标注 approximate mirror。
2. 对每条 P0 合格的**文本型调用**做 RepCoT；FIM 仅在模型明确支持 prefix/suffix 时加入。
3. 比较 Post-hoc 自由解释、RepCoT-no-judge、RepCoT-full；候选数 `k={1,3,5,10}`。
4. 报告输出匹配率、judge 接受率、有效解释率、token/费用/时延及人工盲评；不能将任何候选称为“真实隐藏 CoT”。
5. RQ2 沿用 Watson：RO-SR vs WA-SR，WA-SR 的解释器不在主任务关键路径，使用 χ²/Fisher 与 95% CI。

### M3：从完整可观测性到故障定位

**目的**：验证观测增量是否真实提升定位，而非只增加日志量。

| 证据条件 | 对应工作 | 任务 |
|---|---|---|
| Output-only | Who&When 的低信息设置 | Agent/step 归因下界 |
| 语义 full trace | TraceElephant 静态设置 | 输入、输出、工具、配置的贡献 |
| 语义 + 可 replay | TraceElephant 动态设置 | 反事实/恢复机会贡献 |
| 语义 + 系统证据 | AgentSight | 系统事件对 step/edge 定位的增益 |
| 语义 + 系统 + 认知候选 | Watson | 按需解释对人工调试与定位的附加价值 |

- 数据：先用 TraceElephant 220 条失败 trace 与 MAST 1,642 条 trace；与 Who&When / TRAIL 结果只作可比分析，不能混淆不同真值定义。
- 标签：使用 MAST 14 类失败模式分层；采用 TraceElephant 的 role-aware / recoverability-aware 原则。
- 基线：Who&When 的 All-at-Once、Step-by-Step、Binary Search、Hybrid；AgentTrace 的反向 BFS + 节点级 Hit@k/MRR；CDC-MAS 的 step 级因果对照（能运行时）。
- 指标：Agent Acc、Step Acc、Hit@1/3、MRR、失败模式 Macro-F1、人工标注 κ/α、按 trace 长度（≤10、11–30、31–60、61–90、>90）分桶。

**核心判据**：完整系统证据至少不劣于 full semantic trace；认知候选只能在其有独立人工收益时视作增益，不能用 LLM judge 自证。

### M4：边级观测与因果验证（观测完成后的核心研究实验）

1. 按 AgentTrace 的 sequential / communication / data edge 建初始图；增加 responsibility 与 causal-propagation edge，但两者必须标明证据等级。
2. 对观测候选边执行 EDGE 的 **Suppes 筛选 → CAPRI 稀疏化 → 反事实 replay 验证**；注意 EDGE 的节点是错误类别，本实验的节点是 span，二者不能直接比较为同一任务。
3. 以 CDC-MAS 的“性能因果方向可与数据流相反”作为方向性对照；以 Understanding Information Propagation 的 CAPE 度量传播影响。
4. 以 TraceElephant 的角色恢复机会决定责任归属，避免把可被 verifier 修复的上游异常一律列为根因。

| 指标 | 定义 |
|---|---|
| Edge Precision / Recall / F1 | 被标注的失败传播边是否被识别 |
| Edge Hit@k / MRR | 真值边在候选排序中的位置 |
| 反事实下游消除效应 | 修复 / 屏蔽源边后目标失败是否消失 |
| CAPE 风险与洞察贡献 | 边对错误传播与正向任务增益的双向影响 |
| 多错误 Macro-F1 | 以 MAST 类型或 EDGE 对齐标注评估，不能只报单根因 |
| 边图可解释性 | 专家对“证据→边→结论”链的可接受率 |

**必须的排他对照**：随机边、时间邻近边、只用日志重建边、错误类别级 EDGE 式图、仅节点级 AgentTrace 式排名。否则不能证明边级方法优于“图更复杂”或“执行更短”的替代解释。

### M5：性能预测与观测经济性

复用 AgentMonitor 的“廉价 vs 昂贵特征”设计，衡量观测产物是否在完整端到端评测前预测失败/性能：

- 廉价特征：图规模、边类型比例、度/中心性、通信量、token、TTFT/TPOT、工具失败率、系统资源。
- 昂贵特征：Watson judge/人工评分、CAPE、反事实结果、LLM 语义分数。
- 模型：先做相关/非单调性诊断，再用 XGBoost 等非线性回归；不能直接假定线性。
- 划分：In-task、In-architecture、In-domain、Cross-architecture、Cross-task，5 折 CV；报告 Spearman、MAE、校准误差。
- 偷看消融：只使用 10% / 20% / 50% 已完成样本估计昂贵特征，绘制“预测质量—费用”曲线。

成功不是只追求域内高相关；必须定位跨架构失效边界，并将其作为结论的一部分。

### M6：受验证的干预闭环（在 M4 合格后启动）

| 干预维度 | 借鉴工作 | 本实验动作 | 主指标 | 必须对照 |
|---|---|---|---|---|
| 通信拓扑 | AgentDropout、信息传播 | 对已验证高风险边降权、隔离、重路由、冗余校验或恢复 | 成功率、边 F1、错误抑制、洞察保留、prompt/completion token | 无干预、随机边、静态剪枝、只节点剪枝 |
| 表达格式 | Beyond NL | 同一通信图下比较 NL、JSON、表格/代码、AutoForm | 准确率、token、可解析率、边重建完整率 | 固定格式、无 AutoForm、至少 3 次重复 |
| 推理服务资源 | DistServe | 在适用 GPU 环境按 prefill/decode 与通信压力调整调度 | TTFT、TPOT、SLO、goodput、能耗（若可测） | 共置、并行度调优、模拟/真实系统 |
| Prompt 修复 | CDC-MAS | 只作为拓扑干预的平行基线 | 成功率提升、成本、回归率 | 随机修复、拓扑修复、二者组合 |

干预必须通过 shadow/replay 验证后才写回；报告回滚率、误修复率与恢复时间。**不因成功率提升就声称因果有效**，随机干预和任务难度控制是必需的。

## 6. 统一实验纪律、统计与可复现性

1. **重复与统计**：随机性任务至少 3 次独立运行；给均值、标准差、95% CI。二值任务使用 χ² 或 Fisher，排序/回归用置信区间与效应量。
2. **样本量**：MMLU 参考 Watson 的 95% 置信/5% 误差思路；代码/真实 MAS 数据报告有效样本和剔除原因，不能只报原始数据集规模。
3. **人工真值**：边/责任/解释效用标签至少双人盲标；报告 κ 或 α、争议解决协议。LLM judge 只能是辅助标签，不能充当唯一 ground truth。
4. **成本账本**：每次实验记录模型版本、endpoint、temperature/top-p、seed、输入/输出 token、API 费用、墙钟时间、CPU/GPU、内存与失败/重试次数。
5. **分层消融**：每次只增加一个证据层或一个动作层；特别比较 output-only、full semantic、+system、+cognitive，避免把所有收益归给单一组件。
6. **安全与隐私**：API 密钥只用临时环境变量，绝不写入代码/文档/JSON/日志；prompt、文件路径、命令与工具参数默认敏感，导出前脱敏。
7. **负面结果**：配对失败、镜像不成立、judge 与人工冲突、长 trace 退化、跨架构退化、成本失控均为正式结果，不予过滤。

# 可投稿 / 可专利的 Agent 闭环选题（2026-09-18）

> 基于《调研_补充_2026-09-18.md》。这些选题都以“观测 → 诊断 → 干预 → 复验 → 记忆”为完整 Agent 链路；当前只定义研究框架，不预设具体算法。

## 推荐结论

首选是 **CERA：因果边级自治修复 Agent**。其创新不在于再次提出边级归因，而在于把“真实 trace 中的 span 间因果边”变成同时可观测、可干预、可验证、可回滚的最小修复单元。它与 EDGE（错误类别边）、CDC-MAS（提示词闭环）、AgentTrace（用边找节点）形成清晰差异，最适合同步做论文和专利。

| 优先级 | 选题 | 核心新颖性 | 近期可行性 |
|---|---|---|---|
| 1 | CERA：因果边级自治修复 | 以具体 span 边为诊断、修复与评测对象 | 高 |
| 2 | X-Evidence：跨层证据诊断 | 应用、网络、推理证据共同判定因果边 | 高 |
| 3 | RAGent：责任合约委派治理 | 责任边变为可验证、可重协商的运行时合约 | 中高 |
| 4 | TopoImmune：传播免疫拓扑 | 对边实施隔离—校验—恢复，而非静态剪枝 | 中高 |
| 5 | FedEdge：联邦故障知识 | 不共享 trace 内容而学习跨部署失败边模式 | 中 |

## 共同的 Agent 完整链路

```text
运行中的 MAS
  → 观测 Agent：收集 Span、工具调用、网络与运行时事件，构建统一事件图
  → 诊断 Agent：输出失败边 / 风险边及其证据、置信度和因果假设
  → 策略 Agent：提出重路由、降权、隔离、重试、补偿或重协商等候选动作
  → 验证 Agent：在 replay、shadow 或小流量环境反事实复验，决定提交或回滚
  → 记忆 Agent：沉淀“边—症状—动作—结果”，更新下一轮决策先验
```

原则：只有被验证有效的动作才能写回生产拓扑；这使“自治修复”可控且可审计。

## 1. CERA：因果边级自治修复 Agent

**建议题目**：面向多智能体系统的因果边级故障归因与自治拓扑修复闭环  
**英文**：CERA: Causal Edge-level Attribution and Autonomous Topology Repair for Multi-Agent Systems

### 核心问题

现有工作大多回答“哪个 agent / step 出错”，但开发者实际要修的是“哪一次信息交接传错、断掉或被污染，以及怎样安全地改这条路径”。

### Agent 链路

```text
eBPF / OTel / Agent 日志
  → Span+Edge 统一图
  → 诊断 Agent 定位失败传播边 e=(span_i, span_j)
  → 策略 Agent 产生 {删边、降权、重路由、插入校验、冗余委派}
  → 验证 Agent 进行局部 replay / shadow test
  → 有效则更新局部拓扑，无效则回滚并记为负例
```

### 创新主张

1. 从节点、step 或错误类别，提升到一次真实执行中的 **span 间因果边**。
2. 观测对象和干预对象相同：同一条边既有系统级证据，也可被直接重写。
3. 用验证门控与回滚实现安全的拓扑级闭环，区别于 CDC-MAS 的提示词优化。
4. 建立边级经验记忆，使修复能力跨运行累积。

### 论文 / 专利切口

- 论文指标：边级定位准确率、修复成功率、回归率、干预代价、恢复时间。
- 评测基础：MAST、TraceElephant 与小型可 replay 的 MAS 原型。
- 专利表述：一种基于跨 span 因果边的多智能体故障定位、拓扑调整、反事实验证及回滚方法、装置、设备和介质。
- 控制范围：首版先实现“边级归因 + 局部拓扑修复”，不同时承诺完整跨层追踪与全局拓扑学习。

## 2. X-Evidence：跨层证据驱动的故障诊断 Agent

**建议题目**：面向 LLM Agent 的跨层证据融合与可验证因果诊断 Agent  
**英文**：X-Evidence: Cross-layer Evidence Fusion for Verifiable Agent Failure Diagnosis

### 核心问题

应用 trace 可显示结果错误，却难以区分根因是提示词交接、工具调用、网络重试、资源争用，还是 GPU / KV-cache 抖动。完整日志不等于能做跨层因果判断。

### Agent 链路

```text
应用 Span + 工具日志 + eBPF 进程/网络事件 + 推理执行图
  → 证据 Agent 对齐事件，为每条边计算支持、冲突与缺失证据
  → 诊断 Agent 输出“故障边 + 证据链 + 不确定性”
  → 处置 Agent 选择应用层、网络层或推理层动作
  → 验证 Agent 比较干预前后的任务结果与系统证据
  → 记忆 Agent 形成跨层故障签名库
```

### 创新主张与产出

- 提出 **Span+Edge+System Evidence** 表示：系统指标不再是旁路监控，而是因果边的证据投影。
- 诊断结果显式带“证据充分 / 冲突 / 缺失”，支持请求补观测而非盲目修复。
- 论文可评估跨层归因、置信度校准、误修复率；专利覆盖多层证据关联与分层处置。
- 与 AgentSight / eInfer 的差异：不是重复采集，而是用二者的证据决定因果解释和修复层级。

## 3. RAGent：带责任合约的多 Agent 委派治理

**建议题目**：基于责任边合约的多智能体委派验证与动态重协商机制  
**英文**：RAGent: Runtime Accountability Contracts for Multi-Agent Delegation

### 核心问题

“因果造成失败”不等于“应对失败负责”。规划者的约束遗漏、执行者的工具失效、审核者的放行可能共同造成事故；现有图缺少运行时可检查的责任语义。

### Agent 链路

```text
任务分解 Agent
  → 为每次委派创建责任合约 {前置条件、输出承诺、验证器、升级路径}
  → 执行 / 审核 Agent 留下履约证据
  → 合约审计 Agent 判定责任边违约及责任转移
  → 重协商 Agent 换执行者、插入审计或提高权限门槛
  → 复验 Agent 验证恢复，并更新合约模板
```

### 创新主张与产出

- 将“责任边”由静态归因标签变为可验证的运行时委派合约。
- 区分因果根因与责任违约，适合高风险企业工作流。
- 论文指标：责任定位 F1、违规拦截率、冤责率、协作开销；专利覆盖责任关系构建、履约校验、迁移与重配置。
- 建议首版限定“任务委派—工具执行—审核放行”三类边，避免语义范围过宽。

## 4. TopoImmune：风险感知的信息传播免疫 Agent

**建议题目**：面向多智能体协作的边级风险免疫与自适应通信拓扑 Agent  
**英文**：TopoImmune: Edge-level Risk Immunization for Adaptive Multi-Agent Communication

### 核心问题

稀疏拓扑抑制错误也会损失洞察，密集拓扑促进协作也会放大污染。现有拓扑优化多为静态剪枝或成本优化，缺少对已验证失败边的动态隔离与恢复。

### Agent 链路

```text
通信观测 Agent 监测消息边及 CAPE 风险 / 洞察收益
  → 风险 Agent 将边置为 {正常、观察、隔离、冗余校验}
  → 拓扑控制 Agent 执行限流、降权、双路复核、临时断连或重路由
  → 验证 Agent 衡量错误抑制与洞察损失
  → 恢复 Agent 在风险解除后逐步恢复该边，并更新边免疫记忆
```

### 创新主张与产出

- 用边生命周期状态机而非永久删边，平衡错误传播和有益洞察传播。
- 动作包含冗余验证与隔离恢复，超出 AgentDropout 式静态剪枝。
- 论文指标：错误抑制率、洞察保留率、切换次数、通信成本、适应速度；专利覆盖动态隔离、校验路由和恢复。

## 5. FedEdge：隐私保持的联邦 Agent 故障知识

**建议题目**：隐私保持的跨部署多智能体故障传播边联邦学习与本地自治修复  
**英文**：FedEdge: Federated Failure-edge Learning for Private AgentOps

### 核心问题

企业 trace 包含提示词、业务数据与工具参数，无法集中汇总；单一部署又缺少失败样本。需要在不上传原始 trace 的情况下共享失败传播知识。

### Agent 链路

```text
本地观测 / 诊断 Agent
  → 生成脱敏边特征、失败签名和局部干预结果
  → 联邦知识 Agent 聚合边风险先验（不含原始 trace）
  → 本地策略 Agent 结合本地上下文选择动作
  → 本地验证 Agent 复验，仅上报统计结果
  → 聚合先验回流至各部署
```

### 创新主张与产出

- 联邦的对象是可解释的“失败边—干预效果”知识，而非普通模型参数。
- 全局先验与本地反事实验证分离，云端不会替本地做高风险决策。
- 适合成为 CERA / X-Evidence 的第二阶段：研究面较宽，不建议单独作为首个开题。

## 与近期工作的非重合边界

| 工作 | 本组选题必须明确写出的区别 |
|---|---|
| EDGE | EDGE 处理错误类别间依赖；这里处理单条真实 trace 的 span 间因果边，并能据此执行干预。 |
| CDC-MAS | 它由 agent / step 归因驱动提示词优化；这里以边归因驱动可回滚的结构与通信调整。 |
| AgentTrace | 它用边辅助节点根因排名；这里把边本身作为诊断、修复与评测对象。 |
| TraceElephant | 它强调完整可观测性与 replay 基准；这里把系统证据、决策与拓扑干预闭环连接起来。 |
| AgentDropout / 信息传播工作 | 它们分析或优化拓扑；这里以反事实验证过的失败因果边驱动动态修改。 |

## 建议的成果路线

```text
Paper / Patent 1：CERA（边级归因 + 验证门控的局部拓扑修复）
        ↓
Paper 2：X-Evidence（跨层证据，解决“边如何可靠观测”）
        ↓
Paper 3：TopoImmune（隔离—校验—恢复，解决“长期如何稳定干预”）
        ↓
Paper 4：FedEdge 或 RAGent（隐私协同或责任治理）
```

## 选题 1 的最小开题边界

1. 固化问题定义、边类型、干预动作空间、验证准则四件事。
2. 搭建 2–3 Agent 的可 replay 原型，覆盖三类通信边与两类故障注入。
3. 基于 MAST / TraceElephant 建立或半自动构造失败传播边标注，并新增边级指标。
4. 论文强调可证伪的问题定义和实验；专利强调采集、构边、判定、干预、验证、回滚、记忆的端到端流程。
