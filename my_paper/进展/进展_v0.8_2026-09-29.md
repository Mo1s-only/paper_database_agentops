用一次真实 API canary 验证“Claude Agent 应用日志 → AgentSight 原始观测 → Trace Adapter 输入规范化”的数据链路，并检查现有数据是否足以开始 Adapter 开发。

## 3. VERIFIED：Trace Adapter 输入规范化

新增 `my_paper_coding/trace_adapter/`：

- `build_run_index.py`：索引 34 个实验目录，记录文件类别、大小、SHA256、模型、session 和费用元数据。
- `normalize_runs.py`：把 Claude 结果日志、AgentSight SQLite 表和已有派生 trace 转成带来源定位的 `evidence-events.jsonl`。
- `smoke_check.py`：检查真实运行是否同时具备应用层、系统观测、任务工件和独立判据。
- `run-metadata.template.json`：规定下一次运行必须保存的版本、命令、时钟、session、PID 和 artifact 信息。

成功 canary 的规范化输出包含 222 条证据记录：220 条 AgentSight 原始记录和 2 条应用结果记录。所有记录都有原始来源；已有 `trace.jsonl` 被标记为 `derived_untrusted`，不能作为 ground truth。

## 4. 当前研究判断

- **VERIFIED**：原始 AgentSight 数据、应用结果、任务工件、独立判据和证据来源链已经足够开始开发 Trace Adapter 的输入层和候选对齐器。
- **VERIFIED**：可以通过 `tool_call_id`、`related_pid`、进程节点和时间戳建立系统侧候选链路。
- **UNVERIFIED**：应用 `session_id` 与 AgentSight `conversation_id` 的自动映射；自动生成 `agent_id`、`step_id` 和统一 trace；自动构建责任边和责任图。
- **不能推出**：单个真实 canary 不能证明通用性、归因准确率、跨任务泛化或论文级效果。

当前下一步是实现保守的跨层候选匹配器：匹配失败时输出 `unknown/uncertain`，不得把 PID 和时间启发式结果直接写成确定责任。

今天新增真实 API 成本 `0.3766092 USD`（失败观测运行 `0.1588632 USD`，成功 canary `0.217746 USD`）。累计成本账本已更新到约 `1.3206682 USD`。后续停止继续调用真实 API，优先使用本次真实 canary 和已有 P0 数据开发、测试和审计 Adapter。
