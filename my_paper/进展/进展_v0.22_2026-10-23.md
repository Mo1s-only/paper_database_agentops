# 研究进展 v0.22（2026-10-20 至 2026-10-23）

**阶段定位：**从“采集与 Adapter 是否能跑通”转向“跨层证据是否改善多 Agent 责任动作归因”的研究设计阶段。本文件汇总本阶段可追溯进展；计划、单次 pilot 和合成协议检查不等同于论文主实验结论。

**一句话总结：**在 10 月 22 日的三类公开数据派生 probe 中，Claude Code + DeepSeek + AgentSight/eBPF 的受控运行均采到语义与系统记录；通用 session/tool Adapter 对齐 3/3，另一个显式 hook→eBPF 进程谱系 profile 也为 3/3。与此同时，合成盲测与 repair/control 协议可运行；但跨层证据能否提高责任归因效果，仍未验证。

## 本阶段主要工作

### 1. 公开数据输入上的真实运行采集与关联检查

从 AgentTrace、Who&When、TRAIL 三个数据集家族各选取 1 个不含 gold 标签的样本，构造成短任务输入，在同一受控 Bash probe 下运行 Claude Code + DeepSeek，并启动 AgentSight recorder 与 eBPF process observer。

| 来源样本 | Claude 原生工具事件 | AgentSight LLM/tool/token 结构化行 | Adapter session+tool | hook ID→eBPF 谱系 | CLI 费用 |
|---|---:|---:|---:|---:|---:|
| AgentTrace `cod_034b23` | 1 | 2 / 1 / 2 | 1/1 accepted | 1/1 accepted | $0.0196464 |
| Who&When `99da66d8…de09` | 1 | 2 / 1 / 2 | 1/1 accepted | 1/1 accepted | $0.0239176 |
| TRAIL GAIA `0035f455…d34` | 1 | 2 / 1 / 2 | 1/1 accepted | 1/1 accepted | $0.0202904 |
| **合计** | **3** | **6 / 3 / 6** | **3/3 accepted** | **3/3 accepted** | **$0.0638544，按规划汇率约 ¥0.638544** |

**解释边界：**session+tool 对齐依据原生语义工具 ID 与 AgentSight 工具 ID 的匹配；hook→进程谱系则是显式受控插桩，把 tool ID 标记到 Bash wrapper 后再沿 eBPF PID/PPID 谱系追踪。后者不代表被动 AgentSight/eBPF 自然携带 Claude tool ID。三条运行验证的是采集/Adapter smoke test，不是原 benchmark 完整复现、归因准确率或跨框架泛化。

一条 AgentTrace 请求首次运行后的离线 finalize 曾因重复创建空 `parsed/` 目录失败；修复 finalize 后复用了原始工件完成后处理，没有重发 API 请求。

证据：[`跨层数据链真实 API 验证报告`](../../lab/experiment/public_dataset_cross_layer_20261022/跨层数据链真实API验证报告.md)。报告记录新增 API 费用低于本批次授权上限；历史累计账目仍需另行核销。

### 2. 盲测预测与 repair/control 协议检查

- **VERIFIED（合成协议范围）：**标签盲预测协议对三类确定性合成轨迹、共 9 条运行执行了预测与后评分隔离；Agent/Step/Action/Edge 均为 9/9。另有 6 项单测通过。
- **VERIFIED（合成协议范围）：**独立 repair/control 协议同样检查 9 条合成运行；预测冻结后按候选执行预登记修复和无关控制，repair 判据成功 9/9、无关控制仍失败 9/9；9 个 unittest 方法通过。
- **重要限制：**这些夹具很小、由规则明显的场景构成，不能当作真实盲测准确率、统计泛化、eBPF 增益或真实因果效应。旧的标签条件 harness 结果继续降级，不引用为方法效果。
- **发现的协议问题：**旧 `cross_task_counterfactual.py` 仍让预测、任务判据或干预读取 `task_name/spec`；旧结果不具备严格真值隔离。新协议提供了更清楚的预测—干预—评分分离接口，但真实任务还需用独立 oracle 验证。

证据：[`盲测归因协议检查`](../../lab/experiment/blind_attribution_protocol_20261022/protocol-report.md)；[`盲化 repair/control 协议检查`](../../lab/experiment/blind_counterfactual_protocol_20261022/protocol-report.md)。

### 3. 论文主线根据近邻工作进一步收窄

对本地新增的多 Agent 归因、反事实诊断、telemetry sufficiency、Agent eBPF provenance 和跨层威胁归因工作进行了对照整理。包括 DCFA、AgentLocate、VerifyMAS、CausalFlow、TelemetrySuffBench、Agent-Warden、AgentTelemetry 与 ALTEDA 等。综述结果提示：仅仅“建执行图”“做 Agent/Step 归因”“加反事实”或“用 eBPF 采进程/文件 provenance”都不足以单独作为创新主张。

当前建议的研究问题收敛为：**在多 Agent 故障中，带来源与关联状态的系统副作用证据，相较语义-only 能否改善决定性责任动作/步骤定位？当跨层关联缺失或不确定时，provenance-aware abstention 能否降低错误归因风险？对可重放案例，独立修复与无关控制能否验证候选责任动作的决定性？**

方向边界已明确：

- AgentSight/eBPF 是系统观测来源，不主张 eBPF 本身发现因果；时间相邻、PID 候选或进程父子关系不自动等于责任边。
- 受控故障注入/重放作为主归因实验；公开数据用于 schema/标签兼容性及补充案例，不把历史 gold 标签拼到新运行时 PID/eBPF 记录上。
- 主故障优先为工具/环境副作用错误和跨 Agent 错误传播；纯路由/角色错误作语义层对照，不预设所有故障都有跨层收益。
- 真值以决定性责任动作/步骤为主，Agent 定位聚合得到；传播边仅在独立标注及干预充分时评估。允许多原因和 abstain。
- 单一 Claude Code + AgentSight/eBPF 栈为核心；第二框架以及 ARM/AMD 平台作为主结果成立后的外部有效性门槛。

证据与文献边界：[`归因方向新增文献与论文增量点`](../../Reference%20paper/99_cross_cutting/归因方向新增文献与论文增量点_2026-10-22.md)；[`论文方向与全文框架综合稿`](../方向框架/论文方向与全文框架_文献-工作综合_2026-10-22.md)。新文献记录注明部分来源 PDF 尚未下载，本地笔记不能替代逐篇全文复核；“存在研究缺口”目前仍为候选推断，不写成已证明 novelty。

### 4. 下一阶段优先级、实验硬件与代码状态

形成了按 P0/P1/P2 分阶段的实验工作规划：先审计盲测/真值泄漏并盘点历史真实运行是否可以从**同一次运行**重建 B1（语义-only）与 B3（语义+系统/provenance）；再做小规模 pilot 和成对消融；主实验成立后才扩展第二框架和跨硬件。

硬件规划把用户提供的 x86_64 Intel 6326 双路节点作为候选主平台，把 Ampere Altra ARM64 作为次级兼容/复现平台；AMD9555 节点信息尚不完整。硬件规格尚需在实验节点现场核验。Claude API 运行不消耗本机 GPU 推理资源，因此 8×RTX 3090/AMD 卡仅在后续冻结本地模型并回答吞吐、开销等问题时使用，不为使用硬件而扩大主实验矩阵。

代码方面，当前本地改动已提交并推送到 `paper_database_agentops` 的 `main`：commit `51212e3c25f1287a660fec7b944811bfdc62471c`，180 个代码、测试、文档与实验摘要文件。费用 JSON、API 密钥库、原始采集日志/数据库、依赖缓存和第三方 AgentRx 快照未纳入该提交。

验证限制：本阶段推送前的当前执行环境没有 `pytest`；`pnpm` 测试依赖安装因网络访问 npm registry 失败，故这些命令未在本机完成。10 月 22 日公开数据实验报告另行记录了当时 trace_adapter 回归 137/137 通过；该结果属于那次环境与测试运行，不代表本次所有 180 个文件都完成全量测试。

证据：[`下一阶段工作规划`](../方向框架/01_跨层因果边归因与可验证诊断/06_下一阶段工作规划_2026-10-23.md)；[`实验与统计计划`](../方向框架/01_跨层因果边归因与可验证诊断/03_实验与统计计划.md)；[`代码目录说明`](../../my_paper_coding/README.md)。

## 下一阶段计划与研究闸门

1. **P0（最高）：盲测信息流审计。** 输出预测阶段字段白名单、禁止读取的标签/注入信息、自动泄漏检查；确保预测冻结后才评分，反事实候选选择不读真值。
2. **P0（最高）：真实 run inventory。** 按来源和哈希登记语义日志、AgentSight/eBPF、任务判据与版本；只纳入能从同一原始运行重建 B1/B3 的记录，标出 direct/inferred/uncertain/abstain/missing。
3. **P1（高）：受控 pilot。** 从已有 `inventory-silent-tool` 案例起步，先验证注入、任务 oracle、可复位 repair 与无关控制；不先扩大付费 API 样本。
4. **P1（高）：成对主实验。** 对同一运行比较 semantic-only、system-only、semantic+provenance 与加入 repair/control 的条件；评估责任动作/步骤命中、错误率、coverage/abstention、干预翻转和开销。
5. **P2（中）：外部有效性。** 只有单栈主结论成立后，再考虑 LangGraph、ARM64/AMD 复现以及本地模型/GPU 吞吐实验。

**Go/No-Go：**若 B3 稳定改善目标故障的责任动作定位，或在相同 coverage 下明显控制高置信错误，且 repair 与无关控制可区分，才支持相应的限定主张。若无增益但证据质量能预测错误风险，就收窄到观测充分性/诊断风险研究；若链接或 oracle 不可靠，先修测量协议，不扩大样本。任何一种情况都不允许把关联关系直接写成因果边。

## 本阶段结论

已从多数据集 schema 兼容与运行时数据链工程，迈到责任归因主实验的设计准备阶段。10 月 22 日的新受控运行说明“某些早先为 0 的语义表缺失，在特定版本/配置/工作负载下可以不再出现”；它没有证明所有数据集、所有工具和所有 AgentSight 运行都已解决漏采。下一阶段的核心不再是追求“每张表都有数据”，而是用来源清楚、同运行配对、标签盲、可复验的实验回答：**增加的系统层证据究竟改变了什么归因决策，是否更正确，以及证据不足时系统是否能克制地拒答。**
