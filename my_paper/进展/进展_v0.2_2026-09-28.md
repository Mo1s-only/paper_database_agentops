### 2.2 受控失败归因 pilot

构造了一个无网络、无随机数的两 Agent 工作流：Agent B 调用一个返回格式合法但数值错误的库存工具，最终任务失败。轨迹和真值分别保存：

- `trace.jsonl`：8 个统一事件；
- `ground_truth.json`：责任 Agent、Step、Edge 和证据区间；
- `analysis.json`：离线推断与真值比对。

本次合成 pilot 中，Agent、Step、Edge 精确匹配，证据区间召回率为 1.0。这个结果只证明 schema 和评测闭环可执行，不能作为真实系统效果或统计结论。

证据：`my_paper_coding/failure_pilot/pilot-report.md`。

### 2.3 AgentSight 真实观测探针

之前的 Python 直接运行得到 0 事件，问题定位为当前 WSL2 环境的 launch 模式 `agentsight record -- <cmd>` 会丢失目标进程归因。按照已有 AgentSight 测试脚本改为 attach 模式：先 `record -c claude`，再启动 Claude。

本次真实运行结果：

| 证据表 | 数量 |
|---|---:|
| `process_nodes` | 43 |
| `audit_events` | 97 |
| `llm_calls` | 2 |
| `token_usage` | 2 |
| `tool_calls` | 1 |
| `network_targets` | 2 |
| `resource_samples` | 27 |
| 文件事件涉及文件数 | 6 |

Agent 退出码为 0，原始流中可以找到 Claude、Bash、`python3 fake_inventory.py alpha`、Python 进程和文件事件；最终输出正确识别了 `available=0` 不满足 `available=1`。

证据：`my_paper_coding/failure_pilot/agentsight-attach-report.md` 以及对应的本地结果目录。

### 2.4 最小两 Agent 观测

在同一 attach session 中顺序运行 Agent A 和 Agent B：A 写入 `route.json`，B 读取路由、调用静默错误工具并写入 `decision.json`。两个 Agent 退出码均为 0，AgentSight 捕获 53 个进程节点、119 条审计事件、6 次 LLM 调用、4 次工具调用和 4 个网络端点。

这证明真实多 Agent 运行可以进入同一个 AgentSight session；但此处的计数仍是观测结果，不是责任归因准确率。

随后用 `normalize_two_agent_probe.py` 将原始流、工作区文件和真值清单转换为 7 个统一事件，并调用归因分析器。该次试跑的 Agent、Step、Edge 均精确匹配，证据区间召回率为 1.0。结论仍限定为 `VERIFIED_FOR_THIS_SYNTHETIC_PILOT`。

### 2.5 三类故障矩阵

为避免只依赖一个成功案例，新增 `run_fault_matrix.py`，对静默工具错误、错误传播、路由/角色错误各重复 3 次，共 9 次确定性运行。规则归因器在 9/9 次运行中 Agent、Step、Edge 均精确匹配。

该结果只验证故障本体、统一 schema 和离线评分接口稳定，仍不是 AgentSight 真实运行上的泛化结果。

下一步不再扩展单 Agent demo，而是建立一个可捕获的最小多 Agent 工作流：

1. Agent A 规划，Agent B 调用本地工具，Agent A 汇总；
