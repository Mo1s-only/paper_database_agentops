# 进展 v0.19｜2026-10-13

## 本阶段目标

吸收 RCACopilot、OpenRCA、Watson 和 OpenRCA 2.0 中适合当前课题的设计，把归因前观测链深化为可审计、可执行查询、能主动拒绝证据越界的输入层。本阶段没有运行归因算法。

## 已完成

### `VERIFIED`：可组合证据通道

当前证据包统一登记四类 handler：框架生命周期、进程身份、观测器时钟和模型调用上下文。每类通道独立报告 `available`、`available_with_inference`、`available_without_strict_bound` 或 `unavailable`，避免用一个总分掩盖证据缺口。

### `VERIFIED`：可执行证据查询与逐关系收据

新增白名单精确查询引擎。每次查询保存 selector、命中的 event ID 和完整查询结果 SHA256；每条观察关系再绑定 query ID 与 event ID。真实六事件流生成 5 个查询和 3 条结构关系，5/5 查询重放一致，3/3 关系收据完整。

### `VERIFIED`：结论边界自动执行

证据包明确区分 `direct`、`inferred` 和 `abstain`。历史 PID 对齐仍为 `inferred`；时钟门关闭时只允许 sequence order；根因、责任和因果路径输出全部固定为 `false`。篡改查询哈希会被验证器拒绝。

### `VERIFIED`：Watson 式调用上下文协议

新增 model invocation context v0.1，要求模型标识与版本、temperature、top_p、system prompt SHA256、tool schema SHA256、请求/响应 ID、单调时钟和配对证据。它不保存提示词或工具 schema 正文。严格校验和覆盖率测试已经通过。

### `VERIFIED`：工程检查

Python 完整测试集由 77 项增至 89 项并全部通过；其中包括两个交错 session 复用相同局部 step/tool ID 的隔离检查。实验记录位于 `lab/experiment/experiment_20261013_10/`；输入沿用已有真实 API 会话，本次新增网络调用为 0。

## 仍未完成

- `UNVERIFIED`：model invocation context 尚未在新的真实 API 会话中采集和验证；历史会话因此保持 `NOT_READY`，没有进行 Watson 式重建。
- `INFERRED`：真实 session 到 observer process 的 PID 对齐仍缺直接 `NSpid` 真值。
- `UNVERIFIED`：历史 observer clock 的 0 ns uncertainty 未包含系统时钟分辨率，严格跨层时间关系仍关闭。
- `UNVERIFIED`：只有一个真实 session，尚未覆盖多 Agent 并发、长会话、重复工具 ID 域和部分捕获场景。

## 当前可以做出的决定

归因前输入接口现在可以冻结为三层：协议事件、可查询证据包、严格就绪门。后续归因模型只能消费通过这些检查的观察关系，不能直接消费无收据的自由文本结论。

## 下一研究闸门

在新的真实多 Agent 会话中联合采集三类目前缺失的证据：直接 PID namespace 真值、带系统分辨率下界的 observer clock、完整 model invocation context sidecar。验收标准是并发 session 的每条结构关系都能重放，且不存在由默认值生成的镜像条件。完成这一闸门后，才进入归因算法与评估设计。
