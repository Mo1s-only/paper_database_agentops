# AgentOps 研究进展 v0.10｜2026-10-10

## 1. 本次目标

承接 v0.9 的系统侧候选对齐，定义并实现显式应用事件与共享标识解析，在不调用 API 的情况下验证最小 Agent/Step 工具身份对齐协议。

## 2. VERIFIED：本轮实现与验证

- 新增 `application_events.py`：严格事件字段、session/step/tool 生命周期检查、连续序号与稳定身份验证、排他创建的日志 writer。异常中断日志保留，但不能被当作完整流通过。
- 新增事件 JSON Schema 和 `observation-scope.template.json`；显式记录 Agent、session、step、tool_call，以及 host/boot/PID namespace/PID/start 和时钟域、不确定度。
- 新增 `align_application.py`：校验输入类别与来源哈希，结合共享工具 ID、范围一致性、唯一进程与时间区间建立身份关联；处理重复 ID、PID 冲突和多重应用所有者。
- 新增离线协议运行器，经过现有 SQLite 规范化管线验证两个合成 Agent 的 12 条应用事件与 4 条合成系统记录；两个工具步骤按夹具规定关联成功。
- 最终 34 项测试全部通过；20/20 协议场景符合预期。测试场景为合成软件验证，不能视为真实故障样本或归因准确率。
- CLI 基线通过；篡改来源哈希被拒绝且未创建输出。四份历史真实最终结果日志被明确拒绝为完整事件输入，原文件哈希不变。

主要代码与结果位于 `my_paper_coding/trace_adapter/`。证据：[应用事件协议与对齐说明](../../my_paper_coding/trace_adapter/应用事件协议与对齐说明.md)、[应用身份对齐实验报告](../../my_paper_coding/trace_adapter/应用身份对齐实验报告_2026-10-10.md)、`application_runs/20261010-v010-r2/`。

## 3. 保留的失败记录

首次落盘协议测试为 17/20，通过实际 SQLite 规范化输出发现扰动脚本依赖记录顺序。已改为来源行标识定位并新增回归检查，在新目录重跑达到 20/20。初次失败记录保留在 `application_runs/20261010-v010/`，未被覆盖。

## 4. INFERRED：研究判断

本轮把“需要补充哪些应用字段”转成了可执行契约，并验证具备显式字段时，工具步骤身份可以在受控条件下关联到系统观测。下一瓶颈是从真实框架事件中可靠提取这些字段，而不是继续增加只保留最终结果的样本。

来源关系和执行身份不等同于因果责任。当前 `tool_identity_gate_passed` 只覆盖工具开始事件；`unified_trace_ready` 仍为 false。
