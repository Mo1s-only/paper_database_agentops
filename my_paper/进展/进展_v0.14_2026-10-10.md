# AgentOps 研究进展 v0.14｜2026-10-10

## 1. 本次完成

在不调用 API 的情况下，聚合检查 2026-10-10 的 4 次真实运行，比较 Claude 原生工具事件、AgentSight `tool_calls`、debug stream 与 SQLite 全表内容，并把采集完整性变成显式门控。

诊断报告：[工具捕获完整性诊断](../../my_paper_coding/trace_adapter/capture_diagnostics/20261010/工具捕获完整性诊断_2026-10-10.md)。

## 2. VERIFIED

- 4 次真实运行共 15 次原生工具调用，AgentSight 捕获 12 次，缺失 3 次；当前小样本诊断覆盖率为 80%。
- 三个缺失工具分别是 Read、Bash、Write，不支持“只漏某一种工具”的解释。
- 缺失发生在 Agent A 两次、Agent B 一次；批次全局位置为第 1 或第 2 个工具。当前第 3、4 个位置均被捕获，但样本不足以确认位置规律。
- 3 个缺失 tool_call ID 在 SQLite 任一表中均未出现，说明缺失早于规范化和对齐阶段。
- debug stream 对 15 个工具 ID 均不可搜索，包括已被 `tool_calls` 捕获的 12 个，因此它不能作为工具完整性的旁路证据。
- 新增采集完整性诊断器；未来运行若原生工具数、系统工具数和 accepted 数不能一一相等，将标记 `capture_incomplete`，禁止生成系统层 Edge 完整性结论。
- 全部 50 项测试通过。本轮没有 API 调用，累计费用仍为 1.576492 USD。

## 3. INFERRED

- 漏采发生在 AgentSight 记录进入 SQLite 之前或之中，后续规范化器和对齐器不是这 3 个 ID 消失的原因。
- 当前表现更接近间歇性或时序相关漏采，不能归因到固定工具类型。
- 论文评测需要同时报告应用层归因 exact、系统捕获率与 abstain 率；单一 exact 指标会掩盖底层观测缺口。

## 4. UNVERIFIED

- SSE 解析、首会话启动时序、数据库写入或版本组合中哪一层导致漏采。
- 全局位置 1/2 是否真的更易漏采。
- 增加 AgentSight 上游网络/SSE 原始帧后能否恢复缺失工具证据。
