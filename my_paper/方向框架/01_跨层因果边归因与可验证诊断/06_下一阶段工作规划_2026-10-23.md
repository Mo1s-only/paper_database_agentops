# 下一阶段工作规划（2026-10-23）

状态：执行路线建议；不是已完成实验，也不是投稿承诺。优先级定义：**P0 = 论文主张成立的前置闸门；P1 = 主实验与核心证据；P2 = 外部有效性/投稿增强；P3 = 可选工程或展示项。**

## 结论先行

下一阶段不再把“多数据集能否采集、Adapter 能否对齐”当主目标。现有工作已证明若干受控场景能采到语义与系统事件、完成指定关联，但还没有证明跨层证据提高了责任归因准确率。

当前唯一主问题是：**在同一次多 Agent 故障运行中，带来源与关联置信状态的语义+系统证据，相较语义证据单独使用，能否更准确地定位决定性责任动作/步骤；对可重放候选，独立 repair 与无关 control 是否能降低错误归因？**

建议按“有效性闸门 → 主效果 pilot → 配对主实验 → 外部有效性 → 写作投稿”的顺序推进。任何阶段失败都应收窄论文主张，而不是通过加数据或增加硬件掩盖失败。

## 分阶段计划

### P0｜先把评测变成可信的“盲测”

**重要程度：最高。** 若这一步不通过，后续分数没有解释力。

目标：确保预测器只看运行轨迹和指定证据视图；标签、注入配置、故障类别与答案不进入 Adapter、预测、候选排序或干预选择。

工作项：

1. 审计 `my_paper_coding/evaluation_gate/`、`failure_pilot/` 和新 blind harness 的全部入口，列出预测阶段可读文件及字段；做 fault label / task name / manifest 泄漏扫描。
2. 固定一份不可变的案例协议：运行输入、独立 task oracle、故障源、责任动作真值、允许多原因/abstain 的规则、排除标准与随机种子。真值单独存放，预测落盘并哈希后才能评分。
3. 每例先冻结 B1（语义-only）与 B3（语义+系统/provenance）两种输入视图；二者共享同一原始 run、相同归因预算和评估器，不得各跑不同任务来比较。
4. 修复反事实选择隔离：干预只能由已冻结的候选预测决定；评分 oracle 只依据独立任务契约判断修复与控制后的结果，不能读取故障标签来挑操作。
5. 为 `direct / inferred / uncertain / abstain` 加来源记录引用和关系依据；在 PID 置换、时间扰动、重复候选、删除一个来源等变形下，系统不得悄悄把推断边升级成 direct。

交付物：盲测协议 v1、字段/信息流审计表、泄漏回归测试、每条预测与评分分离的可复跑 artifact。

**通过门：**标签泄漏测试全通过；同一 run 可生成 B1/B3；来源缺失或冲突有明确状态；预测文件冻结后才能评分；反事实 repair/control 不依赖真值选候选。任一失败，停止效果实验，先修协议。

### P0｜盘点已有真实运行，确认能否构成成对证据

**重要程度：最高；与上项并行。** 先从已有记录挖掘，避免为重复的信息付 API 成本。

工作项：

1. 对现存真实 run 逐个登记原始语义日志、AgentSight/eBPF 数据、任务输入/输出、事件来源、代码/配置版本和缺失项。
2. 为每个 run 标记是否能在不补造的情况下构造 B1、B2、B3；区分共享 ID 直接关联、进程/时钟推断关联、受控 hook 桥接、无法判断。
3. 只把 B1 与 B3 均可由同一次 run 得到的记录纳入配对归因候选；公开数据集适配报告只作为兼容性证据，不混作新运行真值。
4. 把 AgentSight `tool_calls`、`token_usage` 或响应体缺失保留为缺失证据；不因其缺失就丢弃 Claude 原生日志，也不把原生日志伪装成 AgentSight 记录。

交付物：`run_inventory.csv/json`、纳入/排除原因、B1/B2/B3 覆盖矩阵和缺失模式摘要。

**通过门：**至少有一批可复现 run 能同时生成同源 B1 与 B3，并能追到原始记录。若历史运行不满足，说明原因后再设计新 pilot；不把不同 run 拼接成“同一条链”。

### P1｜做小规模主实验 pilot，验证“有无增量”

**重要程度：高。** 这是论文方向的 go/no-go，不是先追求大样本。

主场景保持 Claude Code + AgentSight/eBPF 单栈。优先三类：

- 工具/环境副作用错误（优先静默错误）；
- 错误跨 Agent 传播；
- 纯路由/角色错误作为语义层对照。

每个场景定义可机器判定的 task oracle、注入点和责任动作；明确 `fault_origin` 与 `responsibility_action` 的区别。先做可重放、低副作用、可复位的本地任务。真实 LLM/API 调用不是本阶段默认前提；先用已有 artifacts、确定性 harness 或本地冻结模型验证实验设计。需要新增付费调用时，另做预算与密钥预检，不把本规划视为 API 预算授权。

比较条件：

| 条件 | 输入 | 要回答的问题 |
|---|---|---|
| B1 | Agent 消息、工具生命周期和语义日志 | 语义层单独能定位到什么程度？ |
| B2 | AgentSight/eBPF 系统事件 | 系统侧单独提供哪些责任线索？ |
| B3 | B1 + B2 + provenance 关系状态 | 跨层证据相较 B1 是否有增量？ |
| B4 | B3 + 预测冻结后的 repair 与 unrelated control | 可执行验证是否排除仅相关而非决定性的候选？ |
| B5（诊断上界） | hook 明确携带 tool ID 的关联 | 显式插桩的关联上界如何；不代表被动 AgentSight 能力。 |

主指标先锁定：责任动作/步骤 Hit@1、Macro-F1 或 exact match、错误归因率；必须同时报告 coverage/abstention。次指标包括边关系 precision/recall、repair/control 判别结果、耗时与成本。样本单位是任务运行，不是同一运行中的事件。

交付物：pilot 报告、案例级盲测输入/预测/真值/评分、失败案例、B1 对 B3 的配对结果和方差估计。

**通过门：**注入能稳定触发；真值独立于预测；B1/B3 来自同一 run；统计与排除规则预先锁定。只有 pilot 显示可测的、可解释的差异且采集质量合格，才根据方差、成功率和成本制定正式样本量。不要预先承诺“每类 10 条”或“总计 30–50 条”。

### P1｜正式成对消融与稳健性实验

**重要程度：高；须在 P0、pilot 通过后。**

1. 在冻结案例集上对 B1/B2/B3/B4 做同运行配对比较，报告总体与故障类别分层结果、效应量、置信区间和适当的配对检验。
2. 做缺失/错配扰动：删语义层、删系统层、制造时间冲突/多候选、改变关联强度，测归因 risk–coverage；不能只报 coverage 上升或准确率而忽略另一项。
3. 比较至少一个强语义基线（Who&When/TraceElephant 风格的步骤归因）和一个图/错误依赖基线（AgentTrace/EDGE 风格，依可复现性选择）。优先复用公开实现或写清楚无法复现原因，不要求把所有论文重写一遍。
4. 反事实评价要求：候选责任动作修复后任务判据恢复、无关动作控制后任务仍失败；不满足时只称 observational localization/candidate attribution。
5. 保存每次实验的原始日志哈希、Adapter 版本、运行配置、硬件清单、预测冻结件、评分和资源开销。

**主结果 go/no-go：**

- 若 B3 相比 B1 在目标故障类别稳定改善且拒答/覆盖代价可接受，支持“跨层证据在特定故障下有增量”的限定主张。
- 若总体无增益、但 provenance/缺失状态能减少高置信错误，则将贡献转向“证据缺失/关联质量与诊断风险校准”，不声称普遍提高准确率。
- 若 B3 更差或 repair/control 无法区分决定性动作，报告负结果并进一步收窄；不能靠只挑成功案例挽救主张。

### P2｜跨框架和跨硬件外部有效性

**重要程度：中；主实验完成后升级。** 先把单栈核心结论做扎实，再拓展。

- **框架：**第二框架优先选 LangGraph（若 Adapter 可复用、任务语义与日志接口可控），只验证核心信号与主要结论能否复现；不提前宣称跨框架泛化。公开数据适配不是第二框架运行时复现。
- **平台：**Intel 双路 x86_64 为候选主平台，需远程核验实际硬件/内核和 AgentSight 可用性。Ampere Altra ARM64 用作次平台观测栈兼容性与小规模复现；AMD9555/4 张 AMD 卡待型号、驱动、内核和 AgentSight/eBPF 支持信息齐全后再决定。
- **GPU：**若主实验通过 Claude API 运行，8×3090/AMD 卡不参与 Claude 推理，不必为了“用满硬件”把它们塞入主矩阵。它们更适合后续冻结本地模型（如 DeepSeek）做归因器成本/吞吐或敏感性实验；必须把本地模型结果与 API/Claude 运行分组报告，固定模型 hash、推理设置和资源分配。
- **系统开销：**测 AgentSight/eBPF 事件丢失、CPU/RAM、延迟、存储与负载；硬件平台分别做配对比较，不跨机器拼进程树或直接拼接未经校准的单调时钟。

**通过门：**主平台结论成立、次平台采集质量合格、同一任务/模型/配置可复现后，才把外部有效性写入论文主结果；否则作为边界或未来工作。
