# 归因方法文献对比与适配器方案

更新时间：2026-09-28

## 1. 先区分三个层次

本方向应明确拆成三层：

```text
AgentSight / OpenTelemetry / 框架中间件
    = 观测层：记录发生了什么

统一 trace adapter
    = 证据层：把异构原始事件对齐为 Agent / Step / Edge

归因与诊断方法
    = 推理层：判断哪个事件、步骤或 Agent 对任务失败负责
```

因此，不能把 AgentSight 的观测能力写成根因定位能力。当前实验中的 `normalize_two_agent_probe.py` 和 `analyze_failure_pilot.py` 属于第二、第三层，是本课题新增的方法代码。

## 2. 参考论文如何做归因

| **Who&When**（ICML 2025） | 责任 Agent + 决定性错误步骤 | All-at-Once、Step-by-Step、Binary Search 的 LLM 轨迹判断 | 用“修正该动作后任务是否成功”定义 decisive error；三轮专家标注 | 先形式化责任粒度，再统一评价 Agent/Step；可作为 LLM baseline | 主要是日志语义判断；长 trace 和细粒度 Step 准确率明显下降 |

## 3. 对当前课题最重要的共同点

### 3.1 先定义责任，再选择算法

Who&When 把责任定义为“修正该步骤后任务成功”；TraceElephant 的动态配置通过重放验证候选；CDC-MAS 和 EDGE 也把反事实干预作为因果证据。由此，本课题不能只问“哪个事件与失败同时出现”，而要区分：

- **症状事件**：最终错误输出、失败状态或下游错误；
- **候选原因**：上游产生错误输入、工具返回异常值或路由选择错误；
- **决定性原因**：修正该候选后任务成功，且修正无关事件不会成功。

### 3.2 需要同时保留数据流边和责任边

CDC-MAS 的关键提醒是：数据通常从上游流向下游，但性能责任应从下游失败反向追溯到上游缺陷。适配器至少应保留：

```text
temporal_edge       前后执行顺序
message_edge        Agent 之间的消息传递
data_edge           输出字段进入后续输入
process_edge        Agent 进程与工具进程的父子关系
resource_edge       文件、网络、外部服务依赖
```

归因器从失败节点反向搜索候选，不能直接把最后一个报错节点当作根因。

### 3.3 单根因和多错误必须分开报告

当前 `inventory-silent-tool` 是单个受控错误，适合验证接口。EDGE 提醒真实失败可能包含：

```text
上游触发错误 → 中间传播错误 → 下游表现错误
```

因此最终输出应支持：

```json
{
  "primary_candidates": [],
  "propagated_errors": [],
  "parallel_symptoms": [],
  "confidence": {},
  "validation": {}
}
```

## 4. 建议的下一版适配器和归因器

### 4.1 Adapter：从原始观测自动生成统一事件

每个事件至少包含：

```json
{
  "event_id": "stable-id",
  "run_id": "run-id",
  "agent_id": "framework-agent-or-inferred-agent",
  "step_id": "framework-step-or-derived-step",
  "event_type": "llm.call|tool.call|tool.result|message|file|process|task.finish",
  "timestamp": "monotonic-and-wall-clock",
  "parent_event_id": "optional",
  "input_summary": {},
  "output_summary": {},
  "provenance": {
    "source": "agentsight|framework-log|workspace|validator",
    "source_record_ids": [],
    "confidence": 0.0
  }
}
```

关键要求：

1. `agent_id` 优先使用框架原生标识；只有不存在时才用 PID、命令行和时间窗推断。
2. `tool.result` 必须保留原始 stdout/stderr、退出码和结构化解析结果，不能只保存 `available=0`。
3. 每条派生边保存证据来源和推断置信度，禁止把推断字段伪装成 AgentSight 原始字段。
4. 将 task oracle、工具契约和最终任务评估器作为独立输入，不写进观测器或 Agent prompt。
5. 对不能对齐的事件输出 `unknown` 和缺失原因，不强行补全。

### 4.2 Candidate：先生成候选，再做归因

第一版可采用 AgentTrace 风格的可解释候选生成：

1. 找到任务失败节点或违反任务 oracle 的节点；
2. 沿时间、消息、数据、进程和资源边反向 BFS；
3. 剔除没有进入失败传播路径的节点；
4. 保留多个候选，不在没有干预证据时强制选一个。

### 4.3 Rank：规则、图模型和 LLM 分层比较

至少实现以下对照：

- `B0`：最终输出/错误节点；
- `B1`：消息与 Agent 日志；
- `B2`：消息 + 工具/环境证据；
- `B3`：完整依赖图 + 规则排序；
- `B4`：完整依赖图 + 反事实验证；
- `LLM baseline`：Who&When 的 All-at-Once、Step-by-Step、Binary Search。

排序特征可以先采用结构、时间位置、工具契约违背、上下游一致性和证据完整度；不要一开始就把 LLM judge 当作唯一方法。

### 4.4 Validate：把定位升级为可验证归因

对每个候选节点 `v` 执行最小干预：

```text
replay(trace, intervene=v, repair=oracle_or_valid_output)
```

保留候选需要同时满足：

```text
baseline_failed = True
repaired_run_succeeded = True
unrelated_control_remained_failed = True
```

不能重放时，结果只能标为 `observational_localization`；可以重放并翻转时，才标为 `counterfactually_validated_attribution`。

## 5. 针对当前项目的实施顺序

1. **先改 adapter**：从 AgentSight SQLite、raw stream、Claude/framework JSON 和工作区 artifact 自动抽取事件；移除对固定 `ground_truth.json` 生成 trace 的依赖。
2. **再做三类故障**：静默工具错误、错误传播、路由/角色错误，每类至少保留一条可执行 oracle 和一条可重放修复操作。
3. **再做框架复验**：先在当前 Claude Code + AgentSight attach 模式完成，再接入第二个 Agent 框架；框架差异通过 adapter 处理，不改归因核心。
4. **最后做方法比较**：规则图排序、LLM baseline、动态重放三组，报告 Agent/Step/Edge、Hit@k、MRR、反事实翻转率、误干预率和成本。
5. **真实样本扩展前冻结质量门**：事件对齐率、独立真值覆盖率、干预成功率和 provenance 完整率任何一项不达标，都不能扩大 API 实验。

## 6. Claim–Evidence–Gap

| Claim | Evidence | 状态 | 缺口 |
|---|---|---|---|
| AgentSight 可提供跨进程、工具、LLM 和网络观测 | 当前 AgentSight `session.db`、`report-summary.txt`、`report-audit.txt` | VERIFIED | 需要更多 Agent 框架和并发场景 |
| 观测本身不等于责任定位 | AgentSight 原始报告不输出责任 Agent/Step/Edge；这些字段由本地 adapter/analyzer 生成 | VERIFIED | 需要将原始记录与派生字段分离存档 |
| 统一 trace 可以支持受控单根因定位 | 当前 `trace.jsonl` 和 `analysis.json` | VERIFIED（单条受控运行） | 当前 trace 仍部分依赖受控 workspace artifact |
| 反事实干预能提高归因可信度 | 当前 `counterfactual.json` 的离线任务判据翻转 | VERIFIED（离线回放） | 需要真实可重放运行和无关控制干预 |
| 方法能跨故障、任务和 Agent 框架泛化 | 尚无真实多框架结果 | UNVERIFIED | 需要 adapter 复验和统计样本 |

## 7. 当前方法选择

建议把本课题的主方法暂时定义为：

> **证据来源可审计的跨层执行图 + 反向候选搜索 + 最小反事实验证。**

其中 AgentSight 是系统观测后端，适配器负责证据对齐，归因器负责候选排序和责任判定，Watson 类方法只作为后续认知解释层。这个分工最符合本地文献中 AgentSight、Who&When、TraceElephant、CDC-MAS、EDGE 和 Watson 的互补关系。
