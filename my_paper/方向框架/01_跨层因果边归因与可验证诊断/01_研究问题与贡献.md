# 研究问题与贡献

## Research Question Gate

- `RQ`：在多智能体任务失败时，跨层执行证据能否比最终输出或消息日志更准确地定位责任 Agent、决定性步骤和错误传播边，并由反事实复验支持该归因？
- `Object`：包含多 Agent 消息传递、LLM 调用、工具调用和环境副作用的任务执行。
- `Intervention`：统一证据图、候选责任边排序、局部重放/删除/替换验证。
- `Measurement`：Agent/Step/Edge Top-k、MRR、Macro-F1、证据链完整率、反事实修复增益、时延和成本。
- `Baseline`：最终输出 LLM judge、消息日志 judge、时间邻近规则、AgentTrace/EDGE 类图方法、完整 trace 无反事实版本。
- `Boundary`：不声称读取真实隐藏思维链；不覆盖完全黑盒且无可重放环境的系统；诊断不等同于自动修复。

## 子问题

- RQ1：哪些跨层事件能够稳定映射到 `task-agent-step-message-tool-effect`？
- RQ2：系统证据在消息日志之外提供多少增量信息？
- RQ3：哪些边类型最影响 Agent/Step/Edge 归因？
- RQ4：反事实验证能否降低伪相关归因和过度自信？
- RQ5：完整性、精度与观测/重放成本之间的 Pareto 前沿是什么？

## 可证伪假设

- H1：完整证据图的 Edge-F1 高于仅消息日志组。
- H2：移除系统行为证据对工具/环境故障的影响大于对纯语义错误的影响。
- H3：反事实验证提高归因精确率，但增加诊断时延和 API 成本。
- H4：当 request-response 配对错误率上升时，Step/Edge 归因呈单调退化。

## 最小贡献包

学位论文至少完成 C1+C2+C3。若算法创新不足，可把重点改为“证据完整度如何改变归因结论”的实证贡献；若数据规模不足，不应同时声称通用归因和自治修复。
