# 方法与系统框架

## 1. 统一事件 schema

```text
Run
├── AgentStep
│   ├── MessageEvent
│   ├── LLMCall
│   ├── ToolCall
│   └── SystemEffect(process/file/network/resource)
└── Outcome(task/progress/constraint/SLO)
```

每个事件至少包含 `run_id`、`agent_id`、`step_id`、单调时钟、来源、输入/输出摘要、状态、父事件和证据完整度。原始敏感内容与分析特征分离保存。

## 2. 边类型

- `sequential`：同一执行实体内的先后关系；
- `communication`：Agent/组件之间的消息传递；
- `data_dependency`：下游输入使用上游产物；
- `control_dependency`：规划、路由或判定改变后续执行；
- `effect`：语义决策对应到文件、进程、网络或工具副作用；
- `candidate_responsibility`：待验证的失败责任边。

`candidate_responsibility` 不能因时间相邻直接升级为因果边，必须附带复验状态。

## 3. 诊断管线

1. 采集并规范化 AgentSight、Agent 原生日志与任务判据。
2. 通过稳定 ID、进程血缘、消息 ID 和受控时间窗对齐事件。
3. 按异常、依赖距离和失败可达性生成候选子图。
4. 用结构特征、规则或学习模型排序 Agent/Step/Edge。
5. 对 Top-k 候选执行删除、替换、重放或屏蔽干预。
6. 输出 `prediction + evidence set + validation result + confidence + limitation`。

## 4. 反事实层级

- L0：仅解释，不复验；
- L1：离线删除/遮蔽证据，检查模型结论变化；
- L2：重放局部消息或工具结果；
- L3：重新执行任务并干预候选边；
- L4：多次随机运行估计平均干预效应。

正文必须分别报告，不能把 L1 的提示词敏感性称作系统因果效应。

## 5. 实现边界

第一版只支持 2–3 个可复现框架、3–5 类故障和文本/工具任务。跨 GPU 内核的推理服务 RCA 不在范围内，以避免与 TELLER/eInfer 重叠。

## 6. 当前原型连接

当前已实现的最小连接为：

```text
Claude Agent A/B
      ↓
AgentSight attach session
      ↓
raw-stream.log + SQLite
      ↓
normalize_two_agent_probe.py
      ↓
统一 trace.jsonl + ground_truth.json
      ↓
Agent/Step/Edge 归因分析
```

本连接已经在一次两 Agent 受控错误运行中验证。需要明确区分：AgentSight 的原始观测事件是运行证据，`ground_truth.json` 是由受控任务和故障注入产生的责任标签；二者不能互相替代。

跨任务验证门目前覆盖库存、服务重启和文档检索三种任务，采用相同的 `infer → intervene → evaluate` 接口。正确责任事件的修复应使任务成功，无关事件的修改应保持失败；真实 AgentSight 版本还需要独立真值和可重放环境。
