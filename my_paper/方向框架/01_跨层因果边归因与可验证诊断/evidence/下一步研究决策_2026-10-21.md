# 下一步研究决策｜2026-10-21

## 决策

继续以方向 01“跨层因果边归因与可验证诊断”为主线，但当前阶段先收窄为：**面向多智能体故障的、证据来源可审计的跨层执行图与责任边候选定位**。暂不扩充真实 API 样本，不宣称已经实现跨层因果归因，也不把 AgentSight 的缺失记录用应用日志伪装补齐。

下一闸门定为 **零 API 的分源采集—适配—关系审计**：语义层和系统层各自保留原始来源，再由 Adapter 生成带关系类型、证据引用、置信状态和缺失说明的 provenance graph。只有通过该闸门，才讨论下一次有预算约束的真实双 Agent pilot。

## 为什么这样决定

方向总览建议方向 01 为最完整主线，同时明确其最大风险是被认为只是 AgentSight、归因论文和 Watson 的拼接；差异必须落在多 Agent 责任边、证据区间和可执行反事实验证上。方向 01 的实验计划也要求在扩大样本前验证配对、独立真值和干预质量。

最近的真实 run 9 进一步暴露了优先级：Claude 原生日志与 AgentSight/eBPF 的确能分别提供互补信号，但当前 AgentSight 结构化 `tool_calls`、`token_usage` 为空，3 条 HTTP 200 LLM 记录的响应体为 `null`，而 Claude 原生工具事件仍在。此时再扩大 API 样本，主要会重复观测相同缺口，不能证明 adapter 或责任边归因有效。

因此研究对象不是“强迫所有信号都进入 AgentSight”，而是“在异构采集源不完整、关联强度不同的情况下，如何保真地构造并审计跨层执行证据图”。AgentSight 保持为系统级观测后端；Claude Code 原生日志提供应用语义；任务 oracle 提供独立结果判据。三者分源保存，Adapter 负责生成可追溯的关系，不篡改原始事实。

| 完整跨层责任边能提高归因效果 | UNVERIFIED | 当前缺少足量、独立真值、适当对照与真实反事实复验 | 不得作为论文结果或既成优势 |

“完整数据链”在下一阶段拆成两个检查项，不混成一个通过结论：

1. **来源完整性**：每种数据源自身记录了什么、漏了什么，均有原始文件、行/记录 ID 和缺失标记。
2. **关系完整性**：语义事件到进程/系统事件的边有直接或推断依据、证据引用和状态；无法唯一确定时 `unknown/abstain`，不强制补边。

某个来源缺少 body/tool/token 记录，不应抹掉另一来源已有的原生语义记录；反过来，分源保存也不自动意味着跨层关联已经成立。

## 下一步工作包：零 API Adapter 资格验证

1. 以 run 9 为冻结输入，不改写原始日志、SQLite、真值或既有实验报告。将 Claude 原生 stream、CLI final result、AgentSight SQLite/raw stream、进程/eBPF 记录、任务工件和 validator 明确分源。
2. 复用并检查 `my_paper_coding/trace_adapter/parse_claude_native.py`、`normalize_runs.py`、`align_candidates.py` 和 `audit_alignment.py`；若现有入口无法读取 run 9 目录，则新增只读输入 manifest/适配入口，不改旧格式的语义。
3. 生成新的规范化事件和 provenance graph：原始事件使用 `observed`；跨源边分别标记 `direct/accepted`、`inferred`、`uncertain` 或 `abstain`。每条派生边必须带来源记录引用、匹配依据和限制。
4. 运行已有单元测试与离线扰动测试：交换 PID、扰动时间、删除一个来源、制造重复候选时，适配器必须降低关系状态或 abstain；不能因时间接近就产出因果/责任边。
5. 以独立任务判据校验任务结果，但确保 validator/`ground_truth.json` 不进入观测事件或归因输入，防止真值泄漏。输出应能在没有 validator 的条件下重建观测图，再由离线评分步骤读取真值。
6. 将结果记录到新的 run-specific 目录与本方向 evidence 台账；保留原始输入哈希、代码版本、运行命令、关系覆盖率及缺失统计。

## 通过条件与后续门

本闸门只有同时满足以下条件才算通过：

- 原始语义事件、AgentSight 事件、任务判据和真值边界清楚，记录可追溯到来源文件/记录；
- 每个事件和派生关系都保留 provenance；缺失 body 或系统 tool/token 行被如实表示，而不是合成补齐；
- 直接证据与推断关系分开统计；无唯一证据的映射会 abstain；
- 真值不参与事件构造/候选生成；离线测试可检出来源缺失、冲突和扰动；
- 现有 Adapter 回归测试全通过，新增质量门有专门测试。

通过后才进行**一次**新的真实双 Agent 小样本 pilot 申请，优先选择能产生明确工具副作用和可执行 oracle 的故障。启动前重新核对供应商账单、密钥状态和硬预算；当前已批准的 run 9 单次授权已使用，不构成后续 API 调用授权。若零 API 资格验证仍无法产生可审计关系，暂停方向 01 的真实扩样，先修复适配/采集协议；若修复后仍没有足够证据增益，则按总览转向方向 05（观测信号实证与指标校准），保留现有工具作为研究测量平台。

## 研究问题门（当前工作阶段）

- `RQ`：在应用语义日志与系统级观测分源且不完整时，能否以可审计的来源证据构造多智能体执行图，并可靠地区分直接关联、推断关联和不可判定关系？
- `Object`：Claude Code 多 Agent 执行中的工具/消息语义事件及 AgentSight 观察到的进程、网络、文件和 LLM 元数据。
- `Intervention`：来源保真的 Adapter、关系级 provenance 和 fail-closed 对齐审计。
- `Measurement`：事件保真率、关系直接/推断/abstain 覆盖分布、来源引用完整率、扰动下拒绝率、运行开销；本阶段不以归因准确率为主指标。
- `Baseline`：原始分源日志并列查看；现有时间/PID 候选对齐；带 provenance 的新 Adapter。
- `Boundary`：Adapter 资格验证不证明根因归因有效；观察关系不等于因果责任边；单一 Claude Code/AgentSight 组合不支持跨框架泛化结论。
