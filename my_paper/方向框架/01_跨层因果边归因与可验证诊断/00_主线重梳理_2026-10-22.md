# 论文主线重梳理（2026-10-22）

状态：初步方向讨论稿，现由 [`论文方向与全文框架_文献-工作综合_2026-10-22.md`](../论文方向与全文框架_文献-工作综合_2026-10-22.md) 取代为当前综合建议。此稿记录作者在方向访谈中确认的范围边界；因完整对齐 Reference paper 后发现方法新颖性重叠风险更高，主贡献应优先按实证证据效用研究来界定。

## 一句话定位

**面向不完整异构观测的多智能体责任归因与可验证诊断：**把 Agent 语义日志与 AgentSight/eBPF 系统证据以来源可审计、关联强度显式、歧义可拒答的方式构造成跨层执行图，评估其对责任动作/步骤定位的增量价值，并在可重放场景中用反事实干预验证候选责任。

## 研究问题门

- **RQ**：在多智能体故障的应用语义日志与系统观测异构且部分缺失时，来源可审计、允许拒答的跨层执行证据图，能否相较语义日志单独提升决定性责任动作/步骤定位？对于可重放场景，最小反事实干预能否进一步降低错误归因？
- **Object**：多 Agent 消息、LLM/工具调用、文件/进程/网络副作用及任务失败结果组成的运行轨迹。
- **Intervention**：来源保真的事件 Adapter → 具有 `direct / inferred / uncertain / abstain` 状态和来源记录引用的 provenance graph → 从失败/任务判据违例处反向搜索责任候选 → 基于关系/证据强度排序并在证据不足时拒答 → 对可执行候选做修复干预及无关事件控制干预。
- **Measurement**：主指标为责任动作/步骤 exact match 或 Macro-F1、错误归因率；同时报告 coverage/abstention。Agent 定位作为步骤结果聚合。传播边为次级结果，只在具有独立标签和足够干预证据时评估。前置门报告采集完整度、跨层匹配 precision/recall、provenance 完整率和扰动下拒答率；另报告反事实修复率、误干预率、时延与成本。
- **Baseline**：最终结果-only；语义日志/原生工具事件-only（主要基线）；AgentSight/eBPF system-only（诊断基线）；语义+系统但无 provenance/反事实的消融；完整 provenance 图；完整图+反事实验证；LLM 归因作为辅助基线。所有归因器不可读 `fault_type`、注入 manifest 和真值。
- **Boundary**：不声称 AgentSight 单独完成归因；普通执行/时间关系不等于因果边；未干预验证的结果称为 observational localization/candidate attribution；只对已测 Claude Code + AgentSight 栈及受控任务作结论，不预先宣称跨框架/开放世界泛化。

## 研究假设（均待验证）

- **H1**：语义+系统/eBPF+provenance 在工具/环境副作用错误和跨 Agent 错误传播上，相较语义-only 降低责任动作/步骤错误归因率或提高正确定位率。
- **H2**：增益依故障类别而变；纯路由/角色错误可能主要由语义日志揭示，系统层可能无明显增益。该类别作为对照，不预设完整方法全面胜出。
- **H3**：反事实验证相较不验证的完整图方法，降低伪归因/过度确信，但增加诊断时延与成本。
- **H4**：在跨层关系缺失或扰动时，显式 relation status + abstain 能降低错误归因率，代价是覆盖率下降。

## 核心实验范围

### 数据与故障

- 主数据：可重复的多 Agent 受控故障注入/重放；注入配置、任务判据和真值分开保存，归因器盲测。
- 主故障：工具/环境副作用错误（含静默错误）；错误跨 Agent 传播。
- 对照故障：纯路由/角色错误，用于判断跨层系统证据是否只对部分故障有边际价值。
- 公开数据：AgentTrace、Who&When、TRAIL 已完成的结构/标签适配用于兼容性及补充离线评估；其历史 gold label 不得直接与新 replay 的 PID/eBPF 事件拼接为同次运行真值。自然失败若能独立标注，另作为外部案例报告。
- 运行栈：当前以 Claude Code + AgentSight/eBPF 为核心。第二框架仅在主结果成立、Adapter 可复用且时间/环境允许时，作为外部有效性升级门。

### 成对比较

对同一运行使用相同归因预算和评估器，只改变可见证据：

| 条件 | 输入证据 | 作用 |
|---|---|---|
| B0 | 最终结果/错误提示 | 弱基线 |
| B1 | Agent 语义日志、原生消息/工具生命周期 | 主基线 |
| B2 | AgentSight/eBPF 系统证据 | 分离系统层能力 |
| B3 | 语义+系统证据，保留 provenance 和匹配状态 | 测跨层证据增量（主比较 B3 vs B1） |
| B4 | B3 + 候选反事实验证 | 测验证步骤增量（B4 vs B3） |
| B5（可选） | hook 显式携带 tool ID 的受控关联 | 仅作插桩上界，不代表被动观测能力 |

### 真值与因果用语

- 主真值粒度为决定性责任动作/步骤；Agent 由其聚合。
- 区分 `fault_origin`（外部/工具故障从何处产生）与 `responsibility_action`（Agent 哪个动作造成或未能阻断任务失败）。例如工具超时可以是故障源，Agent 未重试/错误传播可以是责任动作；不得混为一个标签。
- 对每个注入样本保存隐藏的 injection manifest、独立 task oracle 和预先定义的 repair/control 操作。方法完成预测并落盘后，评分程序才读真值。
- 验证责任候选至少需要 baseline 失败、修复候选后成功、无关候选控制仍失败。否则只报告定位或观察性证据。
- 多原因样本允许多标签；不充分时允许 abstain。无法执行反事实的自然案例不冒称因果验证。

## 现有五方向的重新定位

- **方向 01**：收敛为唯一主线；聚焦责任动作定位与可验证诊断，收回过宽的“通用因果归因”主张。
- **方向 05**：吸收为评价设计（信号消融、指标稳健性、拒答/覆盖率分析），不先作为平行论文主线。
- **方向 02**：暂缓；当前没有自适应采样策略及预算—诊断效用曲线。
- **方向 03**：暂缓独立 benchmark 论文；保留统一 schema 与数据适配器作为实验基础。
- **方向 04**：暂缓在线预测/干预；需要足量时序预警与误干预数据。

## 与相关工作的创新边界和风险

本地对比材料显示，AgentTrace 已做图上根因候选，EDGE 涉及错误依赖与反事实 rollout，Who&When/TraceElephant 已研究 Agent/步骤责任定位或动态复验，TELLER 覆盖跨层 LLM RCA。因此不能把“用了 AgentSight/eBPF”“建了一张执行图”或“加了反事实”单独说成创新。

可能的差异假设是：聚焦**多 Agent 责任动作**，把语义日志与 OS 进程/副作用作为来源不同、缺失模式不同的证据；每条跨层关系保留 provenance 和 direct/inferred/abstain 状态；实证检验不同观测条件对责任定位的增量影响，并以可执行控制干预限定因果表述。该差异仍需逐篇核查完整原文、基准和方法后才能确认为文献空缺。

## 下一步执行顺序

1. 实现盲测评估入口：预测器只读观测输入；评分器独立读取真值；禁止 fault_type 进入候选或排序逻辑；加入标签泄漏测试。
2. 用现有本地 9 条矩阵和真实捕获 artifacts 做零 API 管线验证，结果仅标为协议/实现检查，不能重新包装旧 9/9。
3. 先对每种故障做最小真实采集 pilot，检查注入是否触发、证据是否完整、ground truth 与 repair/control 是否可执行；通过后再根据 pilot 方差和资源做样本量/统计功效计划。
4. 对同一批 run 执行 B0–B4 成对消融，报告故障分层结果、效应量/区间、abstention 与成本；运行级/任务级作为独立单位，不能把同 run 内事件当独立样本。
5. 达到预注册质量门后再考虑第二框架；费用授权、历史账核销和密钥状态在真实 API 前重新预检，本方向确认不构成新 API 预算授权。

## 决策记录

2026-10-22 用户逐项确认：

1. 主张为“责任归因 + 可验证诊断”，AgentSight/eBPF 是观测来源，不宣称 eBPF 本身发现因果。
2. 主归因实验以受控故障注入/重放为主，公开数据集作兼容性/补充验证，不把历史标签和新运行时数据拼接为真值。
3. 工具/环境副作用错误、跨 Agent 错误传播为重点故障，纯路由/角色错误作对照。
4. 主真值以决定性责任动作/步骤为主，Agent 为汇总；传播边需独立真值/干预证据；允许多原因或 abstain。
5. 采用同一运行的成对证据消融，区分跨层证据与反事实步骤的增量。
6. 主方法为可解释图搜索/证据排序/拒答/可执行验证；LLM 只作基线或辅助。
7. 单个 Claude Code + AgentSight 栈为核心，第二框架是结果成立后的升级项。
