## 1. 结论先行：选一条主线

### 推荐题目

**多智能体故障归因中的跨层证据效用与责任验证**
英文工作标题：*Evaluating Cross-Layer Evidence for Multi-Agent Failure Attribution*

### 方向定位

建议把论文主线从“我实现了一套 eBPF 数据链/新的因果归因算法”改成一项**AgentOps/实证软件工程研究**：

> 系统地研究 Agent 语义日志与操作系统级运行时证据（进程、文件、网络等）的可用性、关联可靠性和互补性，评估跨层证据在不同多智能体故障中是否、何时、以多大程度改善决定性责任动作/步骤的定位；对可重放案例，用修复干预和无关控制验证责任判断。

AgentSight/eBPF 与 Adapter 是研究测量平台和证据获取机制；主学术问题是**证据条件如何影响多智能体责任归因的有效性与可信度**。图、候选搜索、拒答和反事实验证服务于这个问题，不单独把常见的“图 + backward tracing + counterfactual”宣称为算法创新。

这比单纯做新归因算法更贴合当前材料：AgentTrace、TraceElephant、EDGE、ErrorProbe、OpenRCA 2.0 已分别覆盖图上根因搜索、完整轨迹/动态重放、多错误依赖图/反事实、症状反向诊断/执行验证、过程级节点边路径监督；AgentSight 官方能力也已覆盖 eBPF 观测、LLM—系统行为关联和辅助 RCA。需要回答的不是“能否再造一张图”，而是**跨层系统证据能否为多 Agent 任务层的责任定位带来可重复的增量，以及关联失败/不确定时结论如何变化**。

## 2. 研究问题与核心模型

### 主研究问题

**RQ：**在多智能体任务失败中，Agent 语义日志与 AgentSight/eBPF 系统证据的融合，以及语义事件—系统副作用关联的可靠程度，如何影响决定性责任动作/步骤的定位准确性、错误归因率和拒答覆盖率？可执行反事实验证能否进一步提高责任结论的可信度？

### 子问题

- **RQ1（观测/关联）**：在不同故障和工具场景下，语义事件、AgentSight 记录与 eBPF 进程/文件/网络事件各自捕获到什么？哪些关系是共享 ID 等直接证据，哪些只是基于进程谱系/时间的推断，哪些必须 abstain？
- **RQ2（增量效用，主问题）**：同一运行上，跨层证据相较语义-only 是否提高责任动作/步骤定位质量？这种增益是否随故障类型变化？
- **RQ3（缺失与错误关联）**：当某层缺失、工具调用未落库或关联候选冲突/扰动时，系统的错误风险和 coverage 如何变化？显式来源状态与拒答能否避免自信的错误归因？
- **RQ4（验证）**：对可重放候选，修复责任动作是否恢复任务，无关动作控制是否仍失败？反事实步骤能否减少纯观察关联造成的伪责任判断？
- **RQ5（平台稳定性，次要/升级门）**：同一任务、Agent 栈、模型条件与 Adapter 在 x86_64 主平台及 AArch64/可选 AMD 平台复现时，跨层证据捕获、关联质量和归因 coverage/risk 是否稳定？仅在主结果成立、次平台通过采集准入后执行，不预设跨硬件泛化。

### 研究对象及术语边界

每次运行分为四类事实，不能合并成一个“根因”：

1. **故障源 `fault_origin`**：例如工具自身返回错误值、外部服务超时或错误配置；
2. **责任动作 `responsibility_action`**：Agent 的哪一个动作导致失败，或本应验证/恢复却未能阻断失败；
3. **传播事件 `propagation_event`**：错误如何被消息、工具输入或下游动作传递/放大；
4. **失败症状 `failure_symptom`**：最终错误输出、任务 oracle 失败或 SLO 违例。

观测到的调用次序、父子进程或时间邻近只构成执行关系/候选关系。只有在明确的干预协议下通过修复与控制复验，才称为“反事实验证的责任关系”；本论文不把一次运行上的相关性等同于因果发现。

## 5. 整体方法框架

```text
受控多 Agent 任务 + 独立注入清单 + 任务 oracle
                    │（真值对归因器隐藏）
        ┌───────────┴───────────┐
        │                       │
Agent 语义源                OS 系统源
Claude 原生事件/消息/工具    AgentSight/eBPF 进程/文件/网络
        │                       │
        └── 来源保真的 Adapter ─┘
           事件 + source pointer + 缺失状态
                    │
       关系候选：direct / inferred / uncertain / abstain
                    │
          多层执行/依赖证据图（不是自动因果图）
                    │
       失败表现 → 反向责任动作候选 → 证据排序/拒答
                    │
       输出候选、证据集、状态、置信度与限制
                    │
        事后评分与修复/无关控制反事实复验
```

Adapter 和归因器不得读取注入类型、真值标签或依据标签顺序生成轨迹；评分器在预测结果冻结后再读真值。hook 明示写入 tool ID 的 runs 与被动观测 runs 分开，不混在一个主要结果组里。

## 6. 实验框架

### 6.1 任务和故障

- **主故障 A：工具/环境副作用错误**，优先包括静默错误（工具返回看似成功但违反工具契约/任务 oracle）和可在文件/进程/网络层观察的错误效果。
- **主故障 B：跨 Agent 错误传播**，分开记录触发源、负责传播/未能恢复的 Agent 动作、下游症状。
- **对照故障 C：纯路由/角色错误**，验证系统层证据并非对所有错误都有额外收益。
- 优先重用现有 `error-propagation-v1`、`routing-error-v1` 与 inventory/silent-tool harness，但须重新审计 task oracle、注入可验证性和 fault label leakage；旧 9 次不能直接纳入盲测准确率统计。
- 主栈暂定 Claude Code + AgentSight/eBPF；公开数据适配结果用作外部标签协议能力，不将历史对话与新进程数据拼成同一次实验。

### 6.2 证据条件（同一运行成对消融）

| 条件 | 归因输入 | 主要用途 |
|---|---|---|
| B0 | 最终结果/失败提示 | 输出-only 基线 |
| B1 | Claude 原生语义、消息和工具事件 | 主基线；对齐 Who&When 类日志归因 |
| B2 | AgentSight/eBPF 进程、文件、网络及系统观察 | 系统侧单独可归因程度 |
| B3 | 语义 + 系统证据 + provenance 关系状态 | 主比较：B3 vs B1，估计跨层证据增量 |
| B4 | B3 + 候选动作最小修复/无关控制复验 | 比较 B4 vs B3，估计验证机制增量 |
| B5 | hook 显式传递 tool ID 的受控插桩 | 仅作关联上界/诊断组，不能作为被动观测结论 |

强方法基线至少包括：Who&When 风格 LLM step attribution、AgentTrace 风格 graph backward search；若工作量和代码许可允许，纳入 EDGE/ErrorProbe 类多错误/执行验证基线。AgentSight 官方根因输出需先实际导出审计，若在目标任务上可比较，就列为产品/系统基线。不要把所有论文方法都重写一遍才开始实验。

### 6.3 真值和反事实协议

1. 运行前生成并哈希封存 `injection_manifest` 与 `ground_truth`；不送入 Agent prompt、Adapter 的 trace 构建输入或预测器。
2. 每例定义任务 oracle（机器可判定成功/失败）和故障源；标明责任动作/步骤。多责任标签允许并存；证据不足则标 `partial/abstain`。
3. 至少做“修复候选责任动作”的干预；另做一个与候选相关但非决定性的无关控制干预。
4. 若修复后未成功或控制也成功，不能确认候选是决定性责任；结果降为未验证候选/观察性定位。
5. 至少抽样独立人工复核责任标签；若只有注入规则真值，应明示它衡量的是受控责任，不等于自然生产事故的唯一真值。

### 6.4 指标

**前置观测/关联门：**各源捕获完整率；原生工具事件与 AgentSight 记录匹配 precision/recall；系统事件映射状态分布；provenance/source-pointer 完整率；缺失/冲突/扰动时 abstain 行为；运行开销。

**主归因指标：**责任动作/步骤 Top-1、Macro-F1、错误归因率；覆盖率与 selective risk / risk–coverage；Agent 级命中作为聚合指标。Edge/path 指标为次级结果，仅限有足够独立关系真值的案例。

**反事实指标：**候选修复成功率、无关控制仍失败率、反事实责任确认精度；不得只报告“修复后成功”的命中数而忽略 control。

**成本与运行影响：**额外 API/Token、时延、存储、eBPF/CPU；报告每个正确定位的成本。每个 run/task 是独立统计单位，不能把同一 run 内事件数当成独立样本。

### 6.5 假设

- **H1：故障类别异质性。**在工具/环境副作用与跨 Agent 传播中，B3 相较 B1 能提高正确责任动作/步骤定位或降低错误归因；在纯路由故障中增益较小/不存在。
- **H2：关联不确定性的代价。**缺失、冲突或错误的语义—系统关系会降低融合归因可靠性；显式 relation status 和 abstain 可降低错误归因率，但牺牲 coverage。
- **H3：验证增量。**在可重放场景中，B4 相较 B3 降低伪责任判断，代价是时延和成本上升。

以上为可证伪假设，不是预设结论。样本数应在小规模 pilot 得到运行间方差后做功效/精度规划，不把早期 3×3 或 9/9 直接当正式统计规模。

### 6.6 硬件平台与分阶段实验

作者于 2026-10-22 提供三类设备：Intel 6326 双路、32 核/64 线程、503 GB RAM、8×RTX 3090、Ubuntu 22.04、`5.15.0-131-generic`；双路 Ampere Altra、160 核、249 GB RAM、Ubuntu 22.04、`5.15.104`；AMD9555 实验节点及 4 张 AMD 卡。完整待确认台账和准入门见 `research_notes/2026-10-22-实验硬件与跨架构计划.md`。信息目前来自作者描述，未现场核验。

- **主结果**：配置最完整的 Intel/x86_64 节点为候选主平台，通过 H0 环境盘点及 H1 AgentSight/eBPF attach/事件质量检查后冻结；单机同一次运行捕获语义与系统源，做 B1/B3 成对消融。
- **ARM64 次平台**：主实验通过后，在 Ampere Altra 复现相同任务、故障注入和 Adapter，作为可移植性/外部有效性结果单独分层。用户所称“一张 Ampere ARM 架构卡”与表格中的 Ampere Altra CPU 节点关系、是否另有加速卡仍待确认。
- **AMD 平台**：AMD9555 的具体含义，以及 4 张 AMD 卡的型号、显存、节点映射、OS/kernel、driver/ROCm 待确认并通过 H0/H1 后再纳入；不作为核心实验前置条件。
- **GPU 边界**：若主运行使用 Claude Code/API，RTX/AMD 卡不计作 Claude 推理算力；可供本地工具/服务或后续独立本地模型实验使用。若切到本地模型，锁定 checkpoint/hash、引擎、量化、采样和卡分配，单独分组。没有经验证的 GPU 遥测，不从 eBPF 系统事件推断 GPU kernel 级因果。
- **平台控制**：固定/记录 CPU/GPU 分配、并发、功耗/温度、驱动、内核和 collector 版本；跨平台分别计算语义-only 与 fusion 的配对差值。机器间 monotonic clock 不直接共享；每节点独立校准并保留误差界。有限的三类节点只支持平台级复现，不自动构成硬件总体统计泛化。

### 6.7 样本量与停止门更新

不沿用历史文档中“每类故障 10 次”或“先跑 30–50 条”的固定承诺。先通过硬件/观测栈准入和小型重复 pilot，获取注入成功率、事件丢失、运行间方差和配对差异，再决定正式样本量和 API/本地推理预算。主平台 H1 不通过则不扩样；次平台不通过只缩小外推边界，不阻塞主平台研究。

## 7. 论文贡献的建议写法

1. **评价问题/协议（核心）**：定义并操作化跨层证据条件对多 Agent 决定性责任动作定位的影响问题，区分故障源、Agent 责任动作、错误传播和最终症状。
2. **可审计测量流程（支撑）**：构建分源采集、provenance 关系、缺失状态与匹配质量审计的执行图 Adapter，使不同证据条件可重复构造。
3. **系统性实证（核心）**：在受控多 Agent 故障上做同运行成对模态消融，按故障类型测量跨层证据增量、失败模式、coverage 和成本。
4. **责任验证（条件贡献）**：对可重放案例用修复与无关控制区分可验证责任与仅相关联候选；只在真实实验支持时报告其效果。

不建议提前承诺：新 eBPF 观测工具、通用因果发现算法、通用基准、自治修复、对所有数据集/框架泛化、或跨层方法一定优于语义-only。

## 8. 全文结构

### 第 1 章 绪论

AgentOps 调试场景；多 Agent 失败的传播性；语义日志与系统副作用之间的证据缺口；主 RQ、贡献和范围边界。

### 第 2 章 背景与相关工作

AgentOps/AgentSight 运行观测；多 Agent failure attribution（Who&When、TraceElephant、MAST）；图/多错误诊断（AgentTrace、EDGE、ErrorProbe、CDC-MAS）；系统 RCA/过程监督（TELLER、OpenRCA 2.0 等）。按“对象、可见证据、真值、干预”比较，不逐篇堆摘要。

### 第 3 章 问题定义与研究设计

形式化运行、失败症状、fault origin、responsible action、传播关系；直接/推断/未知关系；盲测隔离；评测假设与有效性威胁。

### 第 4 章 跨层证据构造与质量门

Claude 语义源和 AgentSight/eBPF 系统源；Adapter/provenance schema；共享 ID、进程身份、时钟等关联方式；direct/inferred/abstain；缺失和冲突审计。强调这是实验系统，不将其本身冒充 RCA 结果。

### 第 5 章 责任归因与验证流程

从失败点生成候选、证据约束排序、拒答；与语义-only、AgentTrace-style 和 LLM baseline 比较；反事实修复与无关控制。明确可复用既有方法和本研究具体改动。

### 第 6 章 实验设置

任务、受控故障、单 Agent 栈、主/次硬件环境、真值生成、证据视图消融、指标、统计、成本和排除规则；主实验与跨架构复现分开报告。

### 第 7 章 结果

先观测/关联门，再归因增量，再按故障类型和缺失程度分层，最后报告反事实、开销与失败案例。正/负结果均按 RQ 报告。

### 第 8 章 案例与讨论

展示一例跨层证据改变归因、一例语义层已足够、一例错误/不足关系触发拒答或误导；讨论什么时候 eBPF 有用、何时无增益、哪些系统不可重放。

### 第 9 章 威胁、伦理与结论

受控故障外部效度、AgentSight 版本/配置、模型随机性、注入真值偏差、标签泄漏、成本、隐私和发布限制；结论严格匹配证据。

## 9. 决策矩阵与最大风险

| 候选定位 | 新颖潜力 | 可行性 | 已有证据适配 | 最大风险 | 判断 |
|---|---:|---:|---:|---|---|
| 新的通用跨层因果归因算法 | 中 | 低 | 中 | 与 AgentTrace/EDGE/ErrorProbe/OpenRCA 2.0 重叠，真值和方法创新不足 | 不作为首选主张 |
| 新的 AgentSight/eBPF 观测工具 | 低 | 低 | 高 | AgentSight 官方能力已覆盖大部分系统采集/关联/RCA | 不选 |

## 11. 执行路线与停止门

1. **文献差异核验（零 API）**：初轮矩阵已写入 `research_notes/2026-10-22-近邻工作差异审计.md`；下一步逐篇核对近邻原文的实验对象、输入、真值与干预。
2. **协议去泄漏（零 API）**：trace-only 预测器、独立后评分、盲化 repair/control、generic task-contract oracle、标签扫描及拒答单测已实现；9 条合成协议通过，但不当论文结果。旧 gate 保留并明确降级。
3. **硬件准入（零 API）**：按 H0/H1 核验 Intel 候选主机和 Ampere Altra；AMD 节点补全清单后再决定。硬件台账见 `research_notes/2026-10-22-实验硬件与跨架构计划.md`。
4. **真实工件盘点（零 API）**：检查历史运行能否构造同运行、来源可追溯的 B1/B3 输入；缺失不补造。
5. **最小受控试验**：主平台少量真实运行验证注入、AgentSight/eBPF 捕获、Adapter provenance 和 repair/control；API 预算另行预检，本地模型则单独冻结模型条件。
6. **主效果实验**：按 pilot 方差、失败率、成本和平台状态制定样本量，开展 B1/B3 与必要的 B4；跨硬件复现为次级阶段。
7. **Go/no-go**：若主平台不能稳定配对或 B3 对 B1 无可解释的稳定增益，不宣称跨层提升归因；转而报告观测缺失/关联不确定性对诊断风险的实证影响。次平台不兼容则限定外推范围，不补拼数据。
