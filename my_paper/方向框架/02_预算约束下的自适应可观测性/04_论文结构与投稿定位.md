# 论文结构与投稿定位

## 建议章节

1. Introduction：完整观测的价值与不可承受成本。
2. Motivation Study：现有 AgentSight trace 的信号冗余、缺失和故障案例。
3. Problem Formulation：多预算约束下的证据选择问题。
4. Design：档位、触发、缺失感知和隐私策略。
5. Implementation：AgentSight 接入、缓冲、采样和数据模型。
6. Evaluation：RQ 驱动的质量—成本、泛化与压力实验。
7. Discussion：阈值、隐私、观测者效应和部署边界。
8. Related Work / Conclusion。

该结构接近系统论文常见的“动机—设计—实现—评测”路径，并吸收 AgentSight/eInfer/DistServe 的开销与 SLO 评测方式。

## 投稿定位

- Middleware / ISSRE（CCF B）：最自然，强调运行时系统、可靠性和成本权衡。
- ASE（CCF A）：需要把策略自动化与诊断增益写成核心方法，且对 TELLER/AgentSight 有明确超越点。
- JSS / IST / STVR（CCF B 期刊）：适合加入长时间运行、更多配置和部署经验。
- Workshop：适合只完成档位设计、初始 trace 分析和原型时。

## 升档条件

- 有稳定的 Pareto 支配结果，而不是只调一个阈值；
- 跨框架迁移或可解释的适配机制；
- 有隐私/开销/质量三者的系统性消融；
- 原型可重复运行并发布清晰制品。

## 主要审稿风险

- “自适应采样”是否只是工程启发式？
- 全量 trace 是否真的是可靠上界？
- 诊断模型和采样策略是否共同过拟合？
- 隐私风险如何量化，是否只是少存日志？
- 触发升档是否错过故障发生前的关键证据？
