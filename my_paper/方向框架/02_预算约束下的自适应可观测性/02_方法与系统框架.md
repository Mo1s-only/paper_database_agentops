# 方法与系统框架

## 1. 三档观测模式

| 档位 | 默认信号 | 适用状态 |
|---|---|---|
| L0 常态 | 进程、状态码、时延、token、事件计数 | 低风险常态运行 |
| L1 增强 | 消息摘要、工具输入输出摘要、依赖边 | 异常分数上升 |
| L2 取证 | 脱敏后的完整请求响应、系统副作用、可重放上下文 | 明确故障或人工授权 |

档位定义必须结合隐私策略；L2 不等于无条件保存原文。

## 2. 证据价值模型

对信号集合 `S` 定义：

```text
Utility(S) = DiagnosticGain(S) - λ1·Latency - λ2·Storage
             - λ3·TokenCost - λ4·PrivacyRisk
```

各项需分别报告，综合权重只用于策略选择，不替代原始指标。权重属于 `AUTHOR_INPUT_NEEDED`，应通过场景或敏感性分析说明。

## 3. 在线策略

1. 用 L0 信号计算风险或不确定性；
2. 达到预注册阈值后升到 L1/L2；
3. 会话结束后按诊断价值和数据政策决定压缩/保留；
4. 诊断器同时接收 `missingness mask`，避免把“没看到”解释为“没发生”；
5. 对升档失败、事件丢失和配对不确定性进行显式标记。

## 4. 策略候选

- 规则：错误码、重试、循环、长尾时延、工具异常触发；
- 监督学习：预测后续故障或诊断价值；
- 上下文 bandit：在预算约束下选择采集信号；
- 离线策略：先完成规则与监督基线，再决定是否引入强化学习。

## 5. 安全设计

- 触发器不得改变 Agent 决策路径；
- 原文采集需有最小化和脱敏策略；
- 升档失败时保留明确缺失标记；
- 采集线程与主任务资源隔离，报告最坏开销和尾延迟。
