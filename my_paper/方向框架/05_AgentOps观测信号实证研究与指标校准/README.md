# 方向 05：AgentOps 观测信号实证研究与指标校准

## 一句话定位

通过系统性实证研究回答：哪些 AgentOps 观测信号在什么故障、框架和任务条件下真正有诊断价值，现有 Agent 评价指标与故障归因指标是否一致、稳定、可复现。

## 为什么是风险最低的路线

- 不要求先发明一个复杂新模型，可以直接利用现有 AgentSight、Watson、文献分类和指标库。
- 即使新方法未超过强基线，严谨的负结果、评价审计和信号价值分析仍可形成贡献。
- 能把当前较散的 metric 工作转化为有 RQ、样本、统计和威胁分析的论文，而不是指标大全。

## 核心差异化

本方向不是继续列指标，而是实证检验指标的可靠性：

- 任务成功、Progress Rate、`pass^k` 与归因准确率是否一致；
- 消息、工具、系统和认知候选各自提供多少诊断增量；
- LLM judge 的结论对模型、提示词和证据缺失有多敏感；
- 归因指标能否预测开发者调试效用。

## 预期贡献

- C1：AgentOps 诊断信号与失败类型的实证地图。
- C2：评价指标的收敛效度、区分效度、稳定性和成本分析。
- C3：可复现的实验协议、数据提取与统计工具。
- C4：基于证据的最小报告清单和研究建议。

## 对标类型与层次

- 主攻会议：ESEM、SANER、ICSME（CCF B 类），适合实证软件工程研究。
- 主攻期刊：Empirical Software Engineering、IST、JSS（CCF B 类）。
- 范围较窄：MSR、EASE（CCF C 类），适合数据分析和评价研究。
- 中文路线：若与导师/学院要求一致，可对标《软件学报》等高质量中文期刊，但需另核投稿范围与格式。

## 当前成熟度

`INFERRED / 最容易启动`。指标定义和部分 trace 已有，但尚缺预注册样本、标注和统计结果。

## Go / No-Go

- Go：能形成跨任务/故障的稳定结论或有价值的结论翻转，并提供可复现协议。
- No-Go：只有少量案例和描述性统计，无法支持推广；此时作为学位论文章节而非独立投稿。
