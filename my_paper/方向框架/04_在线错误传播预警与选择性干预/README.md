# 方向 04：在线错误传播预警与选择性干预

## 一句话定位

在多智能体错误尚未到达最终输出前，根据执行图、风险状态和传播迹象预测失败，并选择“继续观察、校验、隔离、重路由或停止”等最小干预动作。

## 为什么值得做

- AgentMonitor 提供预测式监控思路，AgentDropout 展示动态拓扑调整，信息传播论文提供错误/洞察传播视角。
- Breaking Agents 和 AgentChaos 说明错误可能被放大并沿协作链传播。
- 现有指标体系已经包含任务成功、过程进展、干预安全、成本和 SLO，可支持闭环评价。

## 竞争边界

ProbGuard 已在 ASE 2026 对 LLM Agent 的长程安全违规做概率式主动监控。新工作必须聚焦多 Agent 的传播结构和干预决策，而不是重复“从 trace 预测风险”。建议的差异：

- 预测对象是责任边/传播路径，而非单体安全状态；
- 干预需要比较“不干预、错误干预、正确干预”的净效用；
- 保留有益信息传播，避免简单删除高风险 Agent；
- 以任务成功、误干预和成本共同评价。

## 预期贡献

- C1：多智能体错误传播状态和早期预警任务定义。
- C2：结合结构、语义和系统信号的风险估计。
- C3：带拒绝/观察动作的选择性干预策略。
- C4：故障注入和自然失败上的在线闭环评测。

## 对标类型与层次

- 冲刺：ASE、ISSTA（软件工程 CCF A 类），需要新任务/方法和强测试实证。
- 主攻：ISSRE（CCF B 类），强调运行时可靠性、误报和恢复。
- 备选：QRS（CCF C 类）或 Agent safety Workshop，适合范围较窄原型。
- 期刊：STVR/JSS/IST（CCF B 类），适合扩展策略、安全性与长时间实验。

## 当前成熟度

`UNVERIFIED / 后续方向`。本仓库尚未有足量时序标签和在线干预实验，不宜直接作为近期主线。

## Go / No-Go

- Go：能在足够提前量下获得有意义的风险校准，并使净任务效用优于不干预和规则干预。
- No-Go：预警只在失败已不可逆时触发，或误干预抵消全部收益；此时保留离线预测分析，不声称在线保障。
