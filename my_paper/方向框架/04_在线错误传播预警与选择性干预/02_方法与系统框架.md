# 方法与系统框架

## 1. 状态表示

在时间 `t` 构建仅使用历史证据的状态：

```text
X_t = {agent states, message/tool events, graph position,
       progress, retries, latency/resource signals, missingness}
```

严格禁止使用 `t` 之后的信息，避免未来泄漏。

## 2. 预测目标

- `P(final_failure | X_t)`；
- `P(fault_type | X_t)`；
- `P(edge e propagates error | X_t)`；
- 剩余失败时间或最早可干预窗口；
- 预测不确定性和拒绝标记。

## 3. 动作集合

- `observe`：不干预，提升观测档位；
- `verify`：要求下游校验或冗余执行；
- `isolate_edge`：暂时屏蔽特定消息/依赖边；
- `reroute`：切换验证 Agent 或工具；
- `rollback_retry`：回滚局部状态并重试；
- `stop/escalate`：停止高风险动作并转人工。

动作必须受到白名单、预算和可逆性约束。

## 4. 策略设计

第一阶段使用校准风险 + 成本敏感决策：

```text
a* = argmin_a E[FailureCost + InterventionCost + DelayCost | X_t, a]
```

先实现规则、阈值和监督策略。只有具有足量交互数据时才考虑 bandit/RL，避免在小数据上制造复杂性。

## 5. 审计输出

每次动作记录触发证据、预测、置信度、备选动作、实际结果和反事实不可得性。自动干预日志本身应可被方向 01 的诊断链审计。
