# 官方标准与规范依据

> 核验截止日期：2026-09-22。
>
> 目的：区分现行国家标准、国际标准、政府框架、在研标准和行业语义规范，并说明它们能为 CERA 的哪些指标提供依据。本文档不把在研项目、草案或行业约定误写成已经生效的强制标准。

## 1. 结论

目前不存在一份能够完整覆盖“大模型能力—Agent 运行—多智能体协作—故障传播—边级归因—自治修复”的统一官方指标标准。

已形成的权威依据呈分层状态：

1. **大模型能力层已有正式国标**：GB/T 45288.2—2025 给出了理解、生成及准确率、召回率、F1、BLEU 等评测方法；
2. **AI 系统质量、数据质量和风险管理已有国际标准/官方框架**：可作为指标维度和评测流程的上位依据；
3. **Agent 运行遥测已有行业语义规范**：OpenTelemetry 已定义 Agent、工作流、模型和工具调用的观测字段，但相关 GenAI 约定仍可能变化；
4. **国内智能体评测和安全标准正在形成**：2026 年已经出现专门的智能体评测、工具调用、互联、日志监测和安全标准项目；
5. **多智能体边级故障归因仍缺少正式标准**：Agent/Step/Edge 归因及反事实修复指标仍需以顶会论文为证据，由本文明确给出操作化定义。

因此，CERA 宜采用“**官方标准确定评价维度和数据规范，正式论文确定可复现实验方法，本文定义边级指标**”的三层证据结构。

## 2. 文件状态标记

| 标记 | 含义 | 论文中允许的表述 |
|---|---|---|
| `STD-CURRENT` | 已发布且现行的国家/国际标准 | “依据/参照某标准定义或测量……” |
| `OFFICIAL-FRAMEWORK` | 政府部门或国家研究机构发布的框架、指南 | “参照其评价维度或 TEVV 流程……” |
| `STD-DRAFT` | 在研标准、国家标准计划或公开草案 | “该项目表明标准化正在关注……”，不能写成现行要求 |
| `INDUSTRY-CONVENTION` | 行业联盟或开源标准组织的语义/基准规范 | “采用其字段名、单位或测试协议……”，需注明成熟度 |
| `PAPER-EVIDENCE` | 正式发表论文中的指标和实验方法 | “沿用/改造论文定义……” |
| `THESIS-DEFINED` | 本文根据研究问题定义的指标 | “本文定义……”，不得声称为官方标准 |

上述“文件状态”与 [论文依据与指标定义.md](论文依据与指标定义.md) 中的 A/B/C 定义来源相互独立。例如，`gen_ai.invoke_agent.duration` 可同时标为 `INDUSTRY-CONVENTION` 和“直接采用”；ECPE 则标为 `THESIS-DEFINED` 和“论文改造 B”。

## 3. 国内官方标准与标准计划

### 3.1 GB/T 45288.2—2025《人工智能 大模型 第2部分：评测指标与方法》

- **状态**：`STD-CURRENT`，2025-02-28 发布并实施；
- **官方来源**：[全国标准信息公共服务平台](https://std.samr.gov.cn/gb/search/gbDetailedCNF?id=2FF37940EB13D753E06397BE0A0A413F)、[国家标准全文公开系统](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=96F5EFDEB471C204455462EAF0C235E6)；
- **直接覆盖**：文本分类、信息抽取、数学/因果/常识推理、任务分解、问答、多轮对话、代码理解与生成、多模态理解与生成；
- **计算方法**：准确率、精确率、召回率、micro-F1、macro-F1、BLEU，以及主观评价方法；
- **论文用途**：作为模型能力层和部分任务质量指标的国内官方基础；
- **边界**：该标准评估的是大模型能力，不直接定义多智能体协作、Trace 完整率、根因 Agent 或失败传播边。

**Agent 例子**：在 100 个带标准答案的工具选择问题中，Agent 底层模型正确选择工具 84 次，则该分类任务准确率为 `84/100=84%`。这能评价模型的选择能力，但不能说明工具是否成功执行、错误是否沿 Agent 边传播。

### 3.2 GB/T 45654—2025《网络安全技术 生成式人工智能服务安全基本要求》

- **状态**：`STD-CURRENT`，2025-11-01 实施；
- **官方来源**：[国家标准全文公开系统](https://openstd.samr.gov.cn/bzgk/std/newGbInfo?hcno=F67D3F376E0A0A0FF5317FB36B32A30A)；
- **直接覆盖**：训练数据安全、模型安全、安全措施和安全评估；
- **可直接继承概念**：抽样合格率及安全风险样本检查；
- **论文用途**：为安全输出合格率、违规输出类型分布和安全防护测试提供依据；
- **边界**：安全内容合格不等于 Agent 任务正确，也不等于工具调用被正确授权。

**Agent 例子**：安全评测从客服 Agent 的 1,000 条输出中抽样，985 条不包含规定的风险内容，则抽样合格率为 `98.5%`。论文还需另报任务成功率，因为“安全但没有完成任务”的输出仍可能很多。

### 3.3 《国家人工智能产业综合标准化体系建设指南（2024版）》

- **状态**：`OFFICIAL-FRAMEWORK`；
- **官方来源**：[工业和信息化部等四部门通知](https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2024/art_e8ebf5600ec24d3db644150873712c5f.html)；
- **相关内容**：将测试评估列入基础共性标准，提出大模型评测指标与方法、生成内容评价、智能体数据接口、人机协作、自主操作和多智能体分布式一致性等标准方向；
- **论文用途**：证明 CERA 位于国家标准化路线覆盖的智能体、测试评估和安全治理交叉区域；
- **边界**：它是标准体系建设路线图，不提供可直接计算的指标公式。

**Agent 例子**：论文可用该指南论证“多 Agent 分布式一致性和自主操作需要规范化评价”，但不能据此宣称 Edge F1 的计算公式来自国家标准。

### 3.4 《人工智能 智能体 评测指标与方法》20262604-Z-469

- **状态**：`STD-DRAFT`，2026-05-07 登记，正在起草；
- **官方来源**：[全国标准信息公共服务平台](https://std.samr.gov.cn/gb/search/gbDetailed?id=5130AD37F61318C7E06397BE0A0AB484)；
- **论文用途**：证明国内已开始针对智能体本身制定专门评测指标；
- **边界**：公开页面尚未给出最终指标体系和计算方法，不能预先替它定义“官方指标”。

**Agent 例子**：论文可以把它列为标准化趋势，并持续追踪是否纳入任务规划、工具使用、协作或可靠性评价；现阶段不能写“该标准要求 Agent 成功率达到某个数值”。

### 3.5 《智能体应用安全基本要求》20263116-Q-252

- **状态**：`STD-DRAFT`，强制性国家标准计划，2026-06-27 下达；
- **官方来源**：[全国标准信息公共服务平台](https://std.samr.gov.cn/gb/search/gbDetailedCNF?id=4C5277928DA2411EE06397BE0A0AE436)；
- **公开技术范围**：身份标识、系统权限调用、工具调用、数据收集使用、高风险操作人工介入、输入输出安全防护、日志留存与动态监测、异常阻断和紧急关停；
- **论文用途**：为 CERA 的可审计性、工具权限、人工接管、异常阻断与回滚指标提供官方问题域依据；
- **边界**：目前只有计划和技术范围，下面的比例指标是本文操作化建议，不是标准原文公式。

可据此设计但必须标为 `THESIS-DEFINED` 的指标包括：

- 日志覆盖率：应记录的关键操作中，实际形成完整日志的比例；
- 高风险操作人工介入覆盖率：需要人工确认的操作中，实际获得确认的比例；
- 未授权工具调用阻断率：测试集中被系统成功拦截的未授权调用比例；
- 紧急关停成功率与关停时延：触发关停后系统进入安全状态的比例和耗时。

**Agent 例子**：故障注入产生 50 次越权文件删除调用，安全层阻断 48 次，则未授权工具调用阻断率为 `96%`。这是依据标准问题域建立的实验指标，但公式由本文定义。

### 3.6 智能体互联系列指导性技术文件

- **状态**：部分已发布为国家标准化指导性技术文件；
- **代表文件**：[GB/Z 185.4—2026《人工智能 智能体互联 第4部分：智能体描述》](https://std.samr.gov.cn/gb/search/gbDetailed?id=52A05F8113473761E06397BE0A0AFEB5)，相近文件包括智能体发现、交互和工具调用；
- **论文用途**：作为 Agent 身份、能力、交互和工具调用 Trace schema 的标准化背景；
- **边界**：互联描述解决“记录什么、如何互操作”，不自动解决“哪个 Agent/边导致失败”。

**Agent 例子**：若 Trace 能稳定记录发送方 Agent、接收方 Agent、工具标识、调用参数和结果，CERA 才能重建调用边；Edge F1 和因果验证仍由本文实验协议定义。

## 4. 国际标准与政府框架

### 4.1 ISO/IEC 25059:2023 — AI 系统质量模型

- **状态**：`STD-CURRENT`，但 ISO 页面标明正在修订并预计被新版替代；
- **官方来源**：[ISO/IEC 25059:2023](https://www.iso.org/standard/80655.html)；
- **直接作用**：提供一致的 AI 系统质量特性与子特性术语，用于检查质量需求是否完整；
- **论文用途**：作为正确性、鲁棒性、透明性、可干预性等一级评价维度的国际标准依据；
- **边界**：它是质量模型，不为 CERA 给出统一任务阈值或边级公式。

**Agent 例子**：对于会自动调用数据库写接口的 Agent，除了任务正确性，还要评价可干预性：当检测到高风险写入时，系统能否暂停并接受人工接管。

### 4.2 ISO/IEC 5259-2:2024 — AI/ML 数据质量度量

- **状态**：`STD-CURRENT`；
- **官方来源**：[ISO/IEC 5259-2:2024](https://www.iso.org/standard/81860.html)；
- **直接作用**：定义 AI/ML 数据质量模型和可测量的数据质量特性；
- **论文用途**：支持把 Trace、事件、请求—响应对和 replay 材料视作 AI 运维数据进行质量管理；
- **边界**：CERA 的“Trace 字段完整率”“请求—响应配对 F1”和“可 Replay 率”仍是项目级操作化指标。

**Agent 例子**：100 次 Agent 工具调用每次要求 6 个必填字段，应有 600 项，实际可靠记录 570 项，则本文定义的字段完整率为 `95%`；ISO 标准支持数据质量维度，`95%` 的公式与阈值由本文说明。

### 4.3 NIST AI RMF 1.0 与 Generative AI Profile

- **状态**：`OFFICIAL-FRAMEWORK`；AI RMF 1.0 正在修订；
- **官方来源**：[NIST AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework)、[NIST AI 600-1 Generative AI Profile](https://tsapps.nist.gov/publication/get_pdf.cfm?pub_id=958388)；
- **直接作用**：从治理、映射、测量、管理组织 AI 风险，强调可信性、测试、评估、验证与确认；GenAI Profile 进一步关注数据/内容来源、外部依赖和准确性、质量、可靠性、真实性评估；
- **论文用途**：作为 CERA 风险闭环、证据留存和 TEVV 实验流程的官方框架；
- **边界**：NIST 不提供适用于所有 Agent 的统一数值门槛。

**Agent 例子**：对财务 Agent，先映射风险为“错误调用支付工具”，再通过故障注入测量检测率、阻断率、误阻断率和恢复时间，最后根据风险级别决定是否只允许 shadow 模式或必须人工审批。

### 4.4 NIST AI 200-2 TEVV-Athlon

- **状态**：`STD-DRAFT`/官方公开草案，2026-08-07 发布初稿并征求意见；
- **官方来源**：[NIST TEVV-Athlon Framework](https://www.nist.gov/artificial-intelligence/ai-research/tevv-athlon-framework-evaluating-ai-systems)；
- **直接作用**：明确适用于机器学习、LLM、多模态和 Agentic Systems，使用四阶段方法构建可定制评测；
- **论文用途**：支持“指标必须围绕具体目标、事件、测试工具和测量概念设计”，适合作为 CERA 故障注入和 replay 评测的过程依据；
- **边界**：截至核验日期仍是初始公开草案，不应写成成熟国际标准。

**Agent 例子**：以“发现并隔离错误传播边”为测量目标，事件是向工具响应注入静默错误，测试工具是可重放执行环境，测量块包括 Edge F1、反事实消除效应、误修复率和任务恢复率。

## 5. 行业可观测性与性能基准规范

### 5.1 OpenTelemetry GenAI Semantic Conventions

- **状态**：`INDUSTRY-CONVENTION`；GenAI 相关操作和字段仍包含 Development 状态项目；
- **官方来源**：[GenAI Metrics](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-metrics.md)、[OpenTelemetry GenAI 属性注册表](https://opentelemetry.io/docs/specs/semconv/registry/attributes/gen-ai/)；
- **论文用途**：统一运行时指标名称、单位、属性和 Agent/工具/工作流边界；
- **边界**：它定义遥测语义，不负责评价答案正确性或证明因果责任；落地实现需固定所用语义版本。

与 CERA 直接相关的字段包括：

| OpenTelemetry 指标 | 含义 | CERA 用途 |
|---|---|---|
| `gen_ai.invoke_agent.duration` | 单次进程内 Agent 调用端到端时长 | Agent 级时延和尾部时延 |
| `gen_ai.invoke_agent.inference_calls` | 单次 Agent 调用发起的模型推理次数 | 推理放大、重试和成本分析 |
| `gen_ai.invoke_agent.tool_calls` | 单次 Agent 调用触发的客户端工具次数 | 工具调用负载与异常调用密度 |
| `gen_ai.execute_tool.duration` | 单次工具执行时长 | 工具瓶颈、超时和外部依赖分析 |
| `gen_ai.invoke_workflow.duration` | 多 Agent 工作流整体时长 | 端到端工作流时延 |
| `gen_ai.client.token.usage` | 输入/输出 Token 使用量 | Prompt/Completion Token 成本 |
| `gen_ai.client.operation.time_to_first_chunk` | 首个流式块时间 | 客户端首响应体验 |
| `gen_ai.server.time_to_first_token` | 服务端首 Token 时间 | 模型服务 TTFT |

**Agent 例子**：一次研究工作流持续 18.2 s，其中检索 Agent 调用模型 3 次、工具 5 次，最慢工具耗时 7.1 s。OpenTelemetry 字段能定位运行瓶颈；是否是失败根因仍需结合工具结果正确性和反事实 replay。

### 5.2 MLPerf Inference Rules

- **状态**：`INDUSTRY-CONVENTION`，由 MLCommons 维护的可复现性能基准规则；
- **官方来源**：[MLPerf Inference Policies](https://github.com/mlcommons/inference_policies/blob/master/inference_rules.adoc)；
- **直接作用**：规定场景、性能/准确率数据、测试遍历、随机性和延迟/吞吐报告方法；SingleStream 使用延迟分位数，Server 场景在延迟约束下寻找吞吐；
- **论文用途**：借鉴预注册场景、负载生成、分位数和“质量约束下报告吞吐”的测试纪律；
- **边界**：MLPerf 不是多智能体故障归因标准，不能直接给 Edge F1 或修复成功率背书。

**Agent 例子**：比较两种 Agent 编排器时，应在相同任务集、到达过程、模型版本和质量门槛下测 P50/P95/P99 时延及 Goodput，不能让一种系统通过放宽正确性换取更高吞吐。

## 6. 官方依据到 CERA 指标的映射

| CERA 层级 | 可继承的官方依据 | 可直接继承 | 仍需本文定义/验证 |
|---|---|---|---|
| 大模型能力 | GB/T 45288.2—2025 | Accuracy、Precision、Recall、F1、BLEU、能力任务分类 | Agent 任务成功、工具执行成功、协作质量 |
| 安全可信 | GB/T 45654—2025、ISO/IEC 25059、NIST AI RMF | 安全抽样、质量维度、风险与 TEVV 流程 | 高风险调用阻断率、人工接管覆盖率、误修复率 |
| Trace 数据质量 | ISO/IEC 5259-2、智能体互联系列 | 数据质量和互操作维度 | 字段完整率、配对 F1、Span 覆盖率、可 Replay 率 |
| Agent 运行负载 | OpenTelemetry GenAI | Agent/工作流/工具时延、推理与工具调用数、Token 用量 | 截止期、SLO 和任务级 Goodput 阈值 |
| 性能测试协议 | MLPerf、DistServe 论文 | 分位数、固定负载、质量约束下的吞吐思路 | 面向多 Agent 工作流的负载模型 |
| 协作与故障归因 | 智能体标准计划 + 顶会论文 | 问题域、Agent/Step 基线和失败分类 | Edge F1、ECPE、错误抑制、洞察保留 |
| 自治修复 | 智能体安全标准计划、NIST TEVV | 人工介入、动态监测、异常阻断、评测流程 | 修复成功率、回归率、回滚率、振荡率 |

## 7. 论文写作中的推荐表述

### 可以写

- “本文参照 GB/T 45288.2—2025 采用 Accuracy、Precision、Recall 和 F1 评价可判定任务。”
- “本文采用 OpenTelemetry GenAI 语义规范中的 Agent、工作流和工具调用边界组织遥测字段，并固定实验使用的语义版本。”
- “受 NIST TEVV 方法启发，本文通过故障注入、完整 Trace 和 replay 构建面向边级归因的定制评测。”
- “现有正式标准尚未给出多智能体 Span 边级故障归因指标，因此本文定义 Edge F1 和 ECPE。”

### 不应写

- “国家标准规定 Agent 任务成功率应达到 95%。”——未找到这一统一阈值；
- “OpenTelemetry 定义了 Agent 根因归因准确率。”——它定义遥测语义，不定义根因真值；
- “《人工智能 智能体 评测指标与方法》已经规定……”——截至核验日期仍在起草；
- “ISO/IEC 25059 规定 Trace 完整率必须达到 99%。”——ISO 给出质量模型，不给出该项目阈值；
- “只要日志字段齐全就能证明因果关系。”——完整观测只能提供证据基础，仍需干预、replay 或排他对照。
