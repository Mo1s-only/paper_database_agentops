# 论文依据与指标定义

> 检索截止日期：2026-09-22。
>
> 目的：为 `metric/` 中的指标提供可追溯的论文依据，并严格区分“论文原定义”“面向 CERA 的改造定义”和“本课题新定义”。详细书目信息与官方链接见 [参考文献.md](参考文献.md)，国家标准、国际标准、官方框架和行业规范见 [官方标准与规范依据.md](官方标准与规范依据.md)。

## 1. 综述范围

### 1.1 综述问题

哪些近年高质量论文已经为 LLM Agent / 多智能体系统定义了任务效果、运行可靠性、故障归因、可观测性、信息传播、拓扑干预和推理服务性能指标？这些指标中，哪些可以直接用于 CERA，哪些需要改造成 Span 间边级指标？

### 1.2 纳入与排除规则

- 优先纳入 2024–2026 年正式发表于 ICML、NeurIPS、ICLR、ACL、EMNLP、OSDI 的论文；
- 指标必须在论文正文中有明确语义、公式、标注对象或实验口径；
- 预印本和 Workshop 论文可以作为候选方法来源，但不作为“顶会已确立指标”的唯一证据；
- 不把论文中的某个实验结果数值当作跨任务通用阈值；
- 不把模型输出的隐藏推理、LLM Judge 分数或时间邻近关系自动视作因果真值。

### 1.3 来源等级

| 等级 | 含义 | 写入论文时的表述 |
|---|---|---|
| **A：论文原定义** | 指标名称和计算对象直接来自正式发表论文。 | “沿用 X 等人的定义……” |
| **B：论文改造** | 保留原论文的因果或统计语义，但把 Agent/Step 粒度改成 Span 间边粒度。 | “受 X 启发，本文将其扩展到边级……” |
| **C：本课题新定义** | 为 CERA 闭环专门设计，尚不是领域公认标准。 | “本文定义……” |

### 1.4 官方文件状态与论文来源等级不可混用

本文件的 A/B/C 只回答“指标定义来自哪里”；官方文件另使用以下状态：

- `STD-CURRENT`：已发布且现行的国家或国际标准；
- `OFFICIAL-FRAMEWORK`：政府部门或国家研究机构发布的框架、指南；
- `STD-DRAFT`：在研标准、国家标准计划或公开草案；
- `INDUSTRY-CONVENTION`：行业联盟或开源标准组织的语义/测试规范。

例如，OpenTelemetry 的 `gen_ai.invoke_agent.duration` 属于行业语义约定，不是任务正确性指标；ECPE 虽受正式论文启发，仍是本文的边级改造。具体映射见 [官方标准与规范依据.md](官方标准与规范依据.md)。

## 3. 任务效果与可靠性指标

### 3.1 Task Success Rate — 论文原定义 A

AgentBoard 将 Success Rate 定义为在允许的最大交互步数内完成任务的样本比例。对 CERA，成功判据应优先由可执行环境状态、单元测试、数据库最终状态或确定性答案检查器给出，而不是只让同一个 LLM 自评。[R1]

`Task Success Rate = 成功完成任务数 / 总任务数`

**Agent 例子**：100 个代码修复任务中，72 个在步数预算内通过全部测试且没有越权改文件，则 Task Success Rate 为 72%。

**边界**：不同基准的成功判据不同，不能把 Web 任务成功率与代码任务成功率直接横向比较。

### 3.2 Progress Rate — 论文原定义 A，新增建议

AgentBoard 指出，最终成功率会把“几乎完成”和“完全没有进展”都记为失败，因此引入 Progress Rate。连续状态任务用当前状态与目标状态的最大匹配度；离散子目标任务用已经达到的子目标比例，并对历史取最大值以避免短暂回退抹去已取得的进展。[R1]

连续状态：

`r_t = max_{0≤i≤t} f(s_i, g)`

离散子目标：

`r_t = max_{0≤i≤t} (1/K) × Σ_{k=1..K} f(s_i, g_k)`

其中 `f` 为状态—目标匹配函数，`K` 为预先标注的子目标数。

**Agent 例子**：数据分析 Agent 的任务包含“读取文件、清洗、建模、生成图、写报告”5 个子目标。最终因绘图失败而没有完成任务，但已完成前 3 项，则 Success Rate 对该任务记 0，Progress Rate 可记 `3/5=0.6`。

**CERA 用途**：判断拓扑修复是否真正推进任务，还是只改变了最终二元结果。

### 3.3 `pass^k` — 论文原定义 A，新增建议

τ-bench 用 `pass^k` 衡量同一任务在 `k` 次独立运行中全部成功的概率，它与“至少一次成功”的 `pass@k` 方向相反。对无人值守 Agent，`pass^k` 比单次平均成功率更能反映重复执行可靠性。[R2]

若同一任务运行 `n` 次，其中 `c` 次成功，则有限样本估计量为：

`pass^k = C(c,k) / C(n,k)`，要求 `n ≥ k`。

应先逐任务计算，再对任务取平均，不能直接把总体成功率做 `k` 次方。

**Agent 例子**：一个报销 Agent 对同一案例运行 5 次，成功 4 次。`pass^2=C(4,2)/C(5,2)=6/10=0.6`，表示从这 5 次运行中任取两次，两次都成功的组合占 60%。

**边界**：模型温度、环境状态或工具副作用使各次运行不独立时，必须直接评估完整重复运行策略，不能机械套用独立试验解释。

### 3.4 多维 Task Utility — 论文原定义 A

AgentEval 认为开放式 Agent 应用不能只用一个成功率评价，而应按任务目的构建多维效用：先提出标准，再为每个标准定义离散或连续取值，最后检查标准是否稳定、可区分成功/失败样本且不冗余。[R3]

`U_t(s) = {Q_i(s | c_i)}_{i=1..n}`

其中 `c_i` 是第 `i` 个评价标准，`Q_i` 是该标准下的量化结果。该定义保留向量，不要求未经依据地压成单一加权分数。

**Agent 例子**：研究 Agent 的结果可分别记录事实正确性、引用支持、覆盖度和简洁性。某次运行得到 `{正确性=2/2, 引用支持=1/2, 覆盖度=2/2, 简洁性=1/2}`，应保留四维结果，而不是只写“质量 75 分”。

**CERA 用途**：拓扑修复后必须确认最终成功没有以牺牲 Groundedness 或约束满足为代价。

### 3.5 Silent Tool Error Detection F1 — 论文原定义 A，新增建议

Tools Fail 区分显式 API 错误和“接口正常返回但内容错误”的静默工具错误，并把检测任务建模为 Accept/Reject 二分类；论文在多模态工具场景报告 F1，而不只报告 Accuracy，因为“错误工具输出”与“可接受输出”的类别比例可能不均衡。[R4]

`Precision = 正确拒绝的错误输出 / 所有被拒绝输出`

`Recall = 正确拒绝的错误输出 / 所有真实错误输出`

`F1 = 2PR/(P+R)`

**Agent 例子**：100 次搜索工具调用中有 20 次返回内容错误但 HTTP 状态正常。监控 Agent 拒绝 25 次，其中 18 次确为错误，则 Precision=72%，Recall=90%，F1≈80%。

**CERA 用途**：将“外部接口可靠性”从 2xx/5xx 和超时扩展到语义正确性，避免把静默错误传播误归因给下游 Agent。

## 4. 推理服务性能指标

### 4.1 TTFT 与 TPOT — 论文原定义 A

DistServe 将 LLM 推理拆成 prefill 和 decode 两阶段：TTFT 对应请求到首 Token 的时间，TPOT 是首 Token 后每个输出 Token 的平均生成时间。论文按分位数报告它们，并把两者同时作为 SLO 约束。[R10]

`TPOT = (生成完成时间 - 首 Token 时间) / (输出 Token 数 - 1)`

**Agent 例子**：协调 Agent 的模型调用在 0.4 s 收到首 Token，5.35 s 完成 100 Token 输出，则 `TPOT=(5.35-0.4)/99=0.05 s/token`。

**边界**：TTFT/TPOT 是模型服务指标，不等于包含工具、编排和 replay 的端到端任务时延。

### 4.2 SLO Attainment — 论文原定义 A

对每个请求同时检查 TTFT 与 TPOT 是否达到应用预先规定的阈值，SLO Attainment 是满足全部约束的请求比例。[R10]

`SLO Attainment = 同时满足 TTFT 与 TPOT SLO 的请求数 / 总请求数`

**Agent 例子**：100 次调用中 94 次达到 TTFT 门槛，但只有 88 次同时达到 TPOT 门槛，则联合 SLO Attainment 为 88%，不是 94%。

### 4.3 Per-GPU Goodput — 论文原定义 A

DistServe 将 Per-GPU Goodput 定义为：在达到既定 SLO Attainment 目标的前提下，每配置一张 GPU 所能承载的最大请求速率。[R10]

`Per-GPU Goodput = 满足 SLO 目标时的最大请求速率 / GPU 数`

**Agent 例子**：4 张 GPU 能在“至少 90% 请求同时满足 TTFT/TPOT”条件下承载 20 req/s，则 Per-GPU Goodput 为 5 req/s/GPU。

**修订说明**：`指标体系总览.md` 中原先用“达标任务数/时间”表示的是任务级 Effective Throughput。为避免与 DistServe 混淆，论文中应分别写“任务级 Goodput”和“Per-GPU Goodput”。

## 5. 故障归因与标注可靠性指标

### 5.1 决定性错误（Decisive Error）— 论文原定义 A

Who&When 不把“最早看起来可疑的步骤”直接当根因，而通过反事实修复定义决定性错误：原轨迹失败，修复 Agent `i` 在步骤 `t` 的错误后轨迹成功，则 `(i,t)` 是决定性错误。[R5]

`Δ_{i,t}(τ)=1` 当且仅当 `Z(τ)=1` 且 `Z(τ^(i,t))=0`；其中 `Z=1` 表示失败。

**Agent 例子**：检索 Agent 在第 4 步给出错误文档，最终任务失败；若只替换第 4 步输出并重放下游后任务成功，则该 Agent—Step 对满足决定性错误定义。

**边界**：Who&When 在多决定性错误时选择时间最早者作为主要原因；CERA 若研究多错误传播，应保留多标签，不应照搬单标签化。

### 5.2 Agent / Step Accuracy — 论文原定义 A

- Agent-Level Accuracy：预测的失败责任 Agent 与真值一致的样本比例；
- Step-Level Accuracy：预测的决定性错误步骤与真值完全一致的样本比例；
- Step-Level Accuracy with Tolerance：预测步骤落在真值步骤的预先规定窗口内即算正确。[R5]

**Agent 例子**：真值是 `Agent B, step 12`，预测为 `Agent B, step 13`。Agent Accuracy 记 1，严格 Step Accuracy 记 0；若容忍窗口为 ±1，Tolerance Step Accuracy 记 1。

**CERA 用途**：作为边级方法必须超越或至少报告的节点级基线。

### 5.3 证据层消融下的归因准确率 — 论文原定义 A

TraceElephant 在 Partial、Full-Static、Full-Dynamic 三类可观测配置下报告 Agent/Step Attribution Accuracy，实验证明完整输入、工具日志、配置和可重放环境会显著影响归因结果。[R7]

**Agent 例子**：同一批失败 Trace 分别只给输出、给完整静态 Trace、再允许 replay，比较 Step Accuracy 的变化。若完整 Trace 提升但 replay 无提升，说明主要缺口是观测而非干预能力。

**CERA 用途**：Trace 字段完整率本身是数据质量指标；它是否“有用”必须由“加入该证据层后 Edge/Step 指标是否提升”来验证。

### 5.4 标注者一致性 — 论文原定义 A

MAST 使用 Cohen's κ 验证人工失败模式标注的一致性，并将分类法分成系统设计、Agent 间不一致、任务验证三大类、14 个失败模式。[R6]

`κ = (p_o - p_e) / (1 - p_e)`

其中 `p_o` 是观测一致率，`p_e` 是随机一致的期望概率。

**Agent 例子**：两位标注者表面一致率 85%，按标签边际分布估计随机一致率 40%，则 `κ=(0.85-0.40)/(1-0.40)=0.75`。

**CERA 用途**：边真值、责任边和因果传播边均需报告一致性；多标注者、缺失标注时优先使用 Krippendorff's α。

## 6. 信息传播与拓扑指标

### 6.1 CAPE — 论文原定义 A

EMNLP 2025 的信息传播论文定义 Counterfactual Agent Propagation Effect（CAPE），衡量只把单个 Agent 输出替换为反事实值后，最终答案正确性是否翻转。[R9]

`CAPE_i(G,Q) = I[y_Q^cf(G, do(O_i:=Ô_i)) ≠ y_Q^orig(G)]`

**Agent 例子**：原系统答案正确；把 critic Agent 的正确建议替换为错误建议后最终答案变错，则该次 CAPE 为 1，说明该 Agent 的信息能通过拓扑影响最终决策。

**边界**：CAPE 是 Agent 级二元翻转指标，不是边级归因准确率，也不区分翻转方向。

### 6.2 TCTE — 论文原定义 A

同一论文用 Total Counterfactual Topology Effect（TCTE）聚合各 Agent 的 CAPE，并用节点度数进行缩放，衡量拓扑整体对局部干预的敏感性。[R9]

`TCTE(G,Q) = (1/N) × Σ_{v_i∈V} CAPE_i(G,Q)/sqrt(d_i)`

**Agent 例子**：在相同 5-Agent 配置下，完全图对错误输出替换的 TCTE 高于稀疏图，说明完全图更容易把局部错误传到最终结果；但还必须用正确洞察干预检查它是否也更擅长传播有益信息。

### 6.3 ECPE（Edge Counterfactual Propagation Effect）— 论文改造 B

CAPE 干预 Agent 的全部输出，无法判断影响是通过哪条出边传播。CERA 可将干预单位缩小为具体 Span 边 `e=(u→v)`：只替换、屏蔽或纠正经该边传递的消息，并保持其他输入和工具结果不变。

`ECPE_e(G,Q) = I[y_Q^cf(G, do(M_e:=M̂_e)) ≠ y_Q^orig(G)]`

方向化版本应拆成：

- `ECPE_error`：把正确结果注入为错误消息后，最终结果从成功变失败；
- `ECPE_insight`：把错误/缺失消息纠正后，最终结果从失败变成功。

**Agent 例子**：planner 同时把方案发给 coder 和 verifier。只改写 `planner→coder` 的消息会翻转最终结果，而改写 `planner→verifier` 不会，则前一条边在该样本上的 ECPE=1，后一条为 0。

**证据状态**：这是受 CAPE 启发的边级扩展，目前应写成“本文定义”，不能写成 Shen 等人已经提出了 ECPE。

### 6.4 错误抑制—洞察保留双指标 — 论文改造 B

EMNLP 2025 的结果表明：稠密拓扑有利于洞察传播，也容易放大错误；稀疏拓扑能抑制错误，也可能压制有益信息。因此拓扑修复不能只报告错误下降，必须成对报告错误抑制和洞察保留。[R9]

`Error Suppression = 1 - P(下游失败 | 修复后) / P(下游失败 | 修复前)`

`Insight Retention = 修复后仍有效到达下游的正向信息数 / 修复前正向信息数`

**Agent 例子**：隔离一条边后，错误传播从 80 次降至 20 次，错误抑制率为 75%；但有效建议从 40 条降至 10 条，洞察保留率只有 25%，因此该修复不能仅凭错误抑制率判为优秀。

### 6.5 Prompt / Completion Token Reduction — 论文原定义 A

AgentDropout 分别报告 Prompt Token 与 Completion Token 消耗，而不是只报告总 Token，并将 Token 降低与任务性能共同比较。[R8]

`Prompt Saving = (Prompt_base - Prompt_method) / Prompt_base`

`Completion Saving = (Completion_base - Completion_method) / Completion_base`

**Agent 例子**：基线每任务使用 12,000 Prompt Token 和 8,000 Completion Token；CERA 使用 9,000 和 7,200，则两类节省率分别为 25% 和 10%。即使总 Token 下降，也必须确认任务成功率和洞察保留没有下降。

## 8. 对现有 metric 文件的修订结论

1. **保留** Task Success Rate，但新增 Progress Rate 和 `pass^k`，分别覆盖部分完成和重复运行可靠性；
2. **保留** Task Quality，但采用 AgentEval 的多维 Utility 方式，不把所有质量维度随意加权成单分数；
3. **新增** Silent Tool Error Detection F1，把外部依赖评价从 HTTP/超时扩展到语义错误；
4. **收紧** Goodput 定义：任务级 Effective Throughput 与 DistServe 的 Per-GPU Goodput 分开；
5. **补充** Step Accuracy with Tolerance，但容忍窗口必须预注册；
6. **明确** Trace 完整率、边重建 F1、Edge F1、误修复率等是本课题定义，不是假称为顶会通用标准；
7. **引入** CAPE/TCTE 原定义，并将 ECPE 明确标注为 CERA 的边级改造；
8. **成对报告** 错误抑制和洞察保留，防止“切断所有通信”获得表面上的安全提升；
9. **分别报告** Prompt/Completion Token，并与任务成功、回归和干预时延联合解读；
10. **取消通用硬阈值**：TTFT、配对率、完整率、κ 等阈值都应根据任务风险、基线和置信区间确定。
