# 多 Agent 责任归因方向：近邻工作差异审计

日期：2026-10-22  
状态：基于本地精读材料与已实现评测代码的初轮审计；不是完整系统综述，也不证明文献空白。

## 结论

**VERIFIED（本地材料范围内）**：若把贡献写成“构造 Agent 执行图、反向搜索根因、按证据排序并用反事实验证”，与 AgentTrace、EDGE、ErrorProbe、TraceElephant、OpenRCA 2.0 的方法组件明显重叠；若把贡献写成“eBPF 观察并关联 Agent 与系统行为”，与 AgentSight 已公开能力直接重叠。

**INFERRED（候选研究差异）**：现有项目最值得检验的差异不是再提出通用图算法，而是研究多 Agent 任务级责任动作定位中，OS/eBPF 副作用证据相对语义日志到底提供多少增量；增量如何受关系证据质量（直接、推断、缺失、冲突）影响；拒答能否在风险上升时守住错误归因。这个候选差异仍须对 AgentSight RCA 做实际输出对照，并逐篇复核完整论文和最新版本。

## 候选问题表述

在受控、可重放的多 Agent 任务失败中，**相较语义日志，加入带来源状态的 OS/eBPF 副作用证据，何时改变并改善决定性责任动作/步骤定位；当语义—系统关联缺失、冲突或只是推断时，覆盖率与错误归因风险如何变化？**

主张层级：

1. 主贡献候选：同一运行上的语义-only 与语义+系统证据成对消融，测责任动作/步骤收益、错误率、coverage 和 risk–coverage。
2. 方法支撑：保留原始 source pointer，区分 direct / inferred / uncertain / missing；来源状态作为实验变量，而非假定全部链接正确。
3. 条件性贡献：只对可重放案例使用修复干预与无关控制；未通过控制时只称候选，不称因果责任。
4. AgentSight 是已有观测/RCA基线和测量来源，不是本文的“新工具”贡献。

## 已发现的盲测泄漏及修正状态

**VERIFIED（代码审计）**：

- `my_paper_coding/failure_pilot/run_fault_matrix.py` 的 `infer(trace, fault)` 依据 `fault` 分支选择候选规则；评测循环把同一个故障标签交给预测器。旧 9/9 不能解释为盲测归因准确率。
- `my_paper_coding/evaluation_gate/cross_task_counterfactual.py` 的 `infer(trace, task_name)`、`evaluate(events, task_name)`、`counterfactual(..., task_name, spec, ...)` 都读取任务名/任务专属 spec。任务名和 spec 对应故障类别，旧 9/9 精确匹配及 9/9 反事实翻转均非标签盲测结果。
- 旧轨迹由同一 harness 生成预测输入和真值，最多用于 schema、确定性夹具、评分接口的回归测试。

新增 `failure_pilot/blind_attribution_eval.py` 使用 trace-only `predict(trace)`，另用独立 CLI 子命令事后评分；`prepare_blind_fixtures.py` 为旧合成场景生成不含故障名的运行 ID 并剥除 fixture attributes。该实现是小型零 API 协议检查，不是论文归因方法，也不涵盖真实 AgentSight 的观测质量或完整反事实验证。

另一个 `failure_pilot/analyze_failure_pilot.py` 的预测函数虽然不接收真值，但旧 runner 在同一进程中先读取 truth 再预测。它不应纳入严格盲测结果；后续若复用，需采用预测/评分独立进程和冻结文件协议。
