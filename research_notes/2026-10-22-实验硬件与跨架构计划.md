## 2. 对论文主问题的作用

主问题仍是：在受控多 Agent 失败中，语义日志相较于语义 + AgentSight/eBPF 系统副作用证据，能否改善决定性责任动作/步骤定位；关联缺失、冲突或仅为推断时，错误风险和拒答覆盖如何变化。

硬件扩展不把论文改成“GPU/硬件论文”，而支持两层实验：

1. **主实验（确认性）**：一个固定、完整记录的主机和 Agent 软件栈，同一运行成对构造 semantic-only 与 semantic+system/provenance 输入，检验主假设。
2. **跨硬件复现（次要/外部有效性）**：同一任务、注入与 Adapter 在 ARM64 和必要时 AMD 节点复跑，检验事件捕获、关系状态分布、归因风险/coverage 和结论方向是否对平台敏感。平台分层报告，不混合成同质样本，也不声称所有硬件均泛化。

可新增次要 RQ：**同一工作负载和采集/归因协议在 x86_64 与 AArch64 平台复现时，跨层证据可用性、关联质量和责任归因结果是否稳定？**只有主结果成立、次平台通过采集准入后才执行。

## 3. 实验顺序与准入门

### H0：现场硬件/软件盘点（零 API）

每节点保存：`uname -a`、`uname -m`、CPU 型号/拓扑、内存、GPU 型号/数量/显存/PCIe 拓扑、驱动/运行时、发行版、内核配置、AgentSight commit、clang/LLVM/libbpf/bpftool 版本、所需 capabilities、BPF build/verifier/attach 结果。不得把凭据或敏感环境变量写入报告。

### H1：观测栈准入（零 API、小型本地任务）

分别检查 AgentSight/eBPF 能否构建、attach，并捕获同一短时受控进程及文件/网络/工具事件；记录事件数、丢失/孤儿/重复、PID/TID/进程谱系、单机时钟锚点、CPU/内存开销。平台不支持时记录阻塞项，不用其他节点的数据补齐。

### H2：主实验（单一主平台、单一 Agent 栈）

- 配置最完整的 Intel/x86_64 节点为候选主平台；先通过 H0/H1 再冻结。
- 固定 Agent 框架和模型后端。若用 Claude Code/API，GPU 不是 Claude 推理资源；若改为本地模型，须记录 checkpoint/hash、量化、推理引擎、采样参数和 GPU 分配，并作为独立实验条件，不与 API 运行混池。
- 从明确分配的 GPU 集合开始（可从单卡）；固定 CPU affinity、内存、并发、功耗策略和负载记录。并发争用会影响时延/时间关联时，按预定并发分层或顺序运行。
- 每个真实 run 在同一主机、同一执行中采集语义源和系统源，再从同一原始工件构造 B1/B3；禁止跨机器拼轨迹。

### H3：跨架构/加速器复现（主实验后）

- 优先在 Ampere Altra/AArch64 节点复现同一任务、Agent/模型条件、工具、故障注入、Adapter 和评分器；不兼容本身作为兼容性结果，不能用推断补造轨迹。
- AMD9555 节点补齐规格并通过 H0/H1 后再纳入；否则只记为可用资源。
- 各平台分别做 semantic-only 与 fusion 配对，比较配对效应和观测质量。不同主机的单调时钟不可直接比较；每节点独立校准、保留误差界。
- 节点有限时只报告平台级复现案例，不声称硬件总体统计泛化。

## 4. 控制变量和论文报告字段

| 混杂因素 | 控制/记录方式 |
|---|---|
| CPU/GPU 争用 | 固定并发、CPU affinity、GPU 分配；记录利用率、时钟、温度/功耗 |
| OS/kernel/collector | 分平台锁定版本、构建参数、配置和事件丢失 |
| GPU 驱动/运行时 | 记录 NVIDIA/AMD driver、CUDA/ROCm；除非直接测量，不推断 GPU kernel 行为 |
| API vs 本地模型 | 主结果固定一种后端；其他模型单独分组 |
| 跨主机时钟 | 用各节点本地时钟锚点和误差界，关系可为 direct/inferred/uncertain/unknown |
| 架构差异 | 平台分层，报告主机内配对增量，不混池 |

实验环境表至少报告：CPU 型号/Socket/core/thread、RAM、架构、GPU 型号/数量/显存/拓扑、OS/kernel、驱动/运行时、Agent/模型版本、AgentSight commit/config、eBPF prerequisites、工具/容器版本、资源分配和负载策略。
