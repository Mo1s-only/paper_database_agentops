## 一句话判断

当前最适合保留的主线仍是方向 01，但应从宽泛的“跨层因果边归因与可验证诊断”收敛为：**面向不完整异构观测的多智能体责任归因——构造来源可审计、关联强度显式、允许 abstain 的跨层执行证据图，并评估它对责任 Agent/步骤/传播定位的增量价值。**

AgentSight/eBPF 是系统观测来源，不是论文贡献本身；Claude Code 原生日志提供语义层；Adapter/provenance graph 负责保真规范化与跨源关系；归因方法和可执行复验负责验证诊断是否有用。没有干预证据的边应称为执行依赖/候选责任关系，不直接称为因果边。

### UNVERIFIED

- 跨层证据相较语义层单独是否能提升责任 Agent/步骤/边定位，尤其是哪些故障类别有增益。

- 反事实修复与无关干预控制是否能稳定区分责任事件和相关症状。
- 相对于 TELLER、EDGE、AgentTrace、Who&When 等工作，收敛后的方法在任务定义、观测假设、责任粒度或验证协议上是否有足够独立的新意；现有本地对比表提供线索，但投稿定位前还需核查完整最新原文和实验边界。

## 建议的论文问题框架（待用户确认）

- **RQ**：在多智能体故障的语义日志与系统观测异构且部分缺失时，来源可审计、允许拒答的跨层执行证据图，能否相较语义日志单独提升责任 Agent/步骤/错误传播定位，并在可重放场景中通过最小反事实干预验证候选责任？
- **研究对象**：多 Agent 消息、LLM/工具调用、文件/进程/网络副作用及任务失败结果。
- **方法候选**：分源保留 → adapter 事件规范化 → 带 direct/inferred/abstain 状态的 provenance 关系 → 候选责任子图 → 排序/拒答 → 仅对可执行候选做反事实检查。
- **主比较**：语义日志-only vs 语义+系统/eBPF；系统-only 和最终结果-only 为诊断性基线；hook 显式 ID 作为受控上界，独立报告。
- **主指标**：责任 Agent/Step top-1 或 macro-F1、错误归因率、覆盖率/abstention；前置报告跨层对齐 precision/recall 和 provenance 完整性；反事实修复率、误干预率与成本为验证/副指标。
- **边界**：不声称 AgentSight 单独完成归因；不把时间邻近直接升格为因果边；不声称对所有公开数据集或任意框架泛化；无反事实支持的结论标为 observational localization。

## 方向决策访谈

### Q1（待答）

我建议论文主张写成“来源可审计的跨层证据图 + 多智能体责任归因与可验证诊断”，把因果边限定为经干预验证的关系；不写成“eBPF 直接发现因果关系”或“AgentSight 本身完成归因”。这个主张边界是否符合你真正想做的论文？

- 推荐答案：符合。研究重点是用系统/eBPF 与 Agent 语义互补证据改善可审计的责任定位；AgentSight 是观测器，因果/责任结论由方法和复验支持。
- 用户答复：确认“责任归因 + 可验证诊断”；AgentSight/eBPF 作为观测来源，不声称 eBPF 本身发现因果关系。

### Q2（待答）

主要归因效果实验是否以**可重复的多 Agent 受控故障注入/重放**为核心，利用独立注入配置与可执行任务判据冻结真值；公开数据集用于标签兼容、离线方法对比或外部有效性补充，而不把公开历史标签直接拼接到新采集进程轨迹上？

- 推荐答案：是。受控数据负责主因果/责任验证，公开数据负责补充标签形态与适用边界；后续若有自然失败且能独立标注，再单列扩展。
- 用户答复：确认以受控故障注入/重放为主；公开数据集用于兼容性与补充验证，不把历史标签直接拼到新运行时轨迹。

### Q3（待答）

主实验是否优先覆盖两类最能检验跨层增益的故障：①工具/环境副作用错误（含静默错误）；②错误跨 Agent 传播；把纯路由/角色错误作为语义层可能已足够的负向/对照类别，而不预设跨层方法对所有故障都提升？

- 推荐答案：是。这样可以检验“按故障类型变化的增量价值”，也能避免为了展示优势而只挑跨层方法有利的案例；先用每类小规模 pilot 验证注入与标签质量，再定最终样本数。
- 用户答复：确认按此范围验证；工具/环境副作用错误与跨 Agent 错误传播为重点，纯路由/角色错误作对照。

### Q4（待答）

论文的主归因标签是否以**决定性责任动作/步骤**为主、Agent 为其聚合结果；责任传播边作为关键次级目标，只在独立真值和可执行反事实足够明确时计分？

- 推荐答案：是。这样定义贴近“修正该动作后任务是否恢复”的可操作责任标准；同时保留跨层图和传播关系的价值，但不把观测到的邻接/下游症状冒充因果边。多原因样本允许多个责任动作或 abstain，不强迫单根因。
- 用户答复：确认以决定性责任动作/步骤为主，Agent 为汇总；传播边须有充分真值/反事实证据，并允许多原因或 abstain。

### Q5（待答）

主要实验是否固定为同一批运行、同一归因预算下的成对证据消融：主比较 `semantic-only` vs `semantic+system/eBPF+provenance`，再比较“完整证据但不做反事实验证”与“加入反事实验证”，以分别估计跨层证据和验证步骤的增量？

- 推荐答案：是。另设 final-output-only 与 system-only 作为诊断性基线；hook 显式 ID 只作受控上界，不能替代被动跨层主比较。所有归因输入都隐藏故障类别和真值。
- 用户答复：确认采用同一运行上的成对消融，分别衡量跨层证据与反事实验证的增量。

### Q6（待答）

主方法是否采用**有 provenance 的执行图 + 从失败/违反任务判据处反向生成候选 + 按证据强度/依赖关系排序 + 歧义时 abstain + 对可重放候选做最小反事实验证**；LLM 归因仅作为基线/辅助解释，不做唯一判定器？

- 推荐答案：是。它可解释、可审计，且与“证据缺失时不强行补因”的核心问题相符；主要风险是与 AgentTrace/EDGE 的图搜索和反事实验证相似，必须靠异构跨层来源、关系可信等级和拒答/校准评价明确区分。
- 用户答复：确认以可解释图方法为主；LLM 归因作为基线/辅助，不作唯一裁判。

### Q7（待答）

当前论文范围是否先限定为一个可控 Agent 框架/观测栈，重点验证多故障类型、成对证据消融和反事实真值；把第二 Agent 框架作为论文升级门槛（时间/环境允许时做），而不在证据尚缺时预先宣称跨框架泛化？

- 推荐答案：是。先确保主问题有可信的内部效度和可重放结果；若本栈结果成立且有可复用 adapter，再补第二框架作为外部有效性验证。投稿目标或毕业要求若硬性要求跨框架，再把它升为必做项。
- 用户答复：确认单栈为核心；第二框架作为结果成立后的升级验证。

## 已收敛的当前论文主线

> 面向异构且不完整的多智能体运行观测，构建带来源证明、关联置信状态和拒答能力的跨层执行证据图；研究它是否能提升决定性责任动作/步骤定位，并用可执行反事实验证可重放案例中的候选责任。

主实验采用受控故障注入/重放；以工具/环境副作用错误、跨 Agent 错误传播为重点，纯路由/角色错误作对照。主比较是同一运行内语义-only 对比语义+系统/eBPF+provenance；另比较完整证据无/有反事实验证。图搜索/证据排序/abstain 是主方法，LLM 只作基线/辅助。传播边为次级指标，须有明确标签和干预证据。当前先限一个 Claude Code + AgentSight 栈。

方向 05 的信号消融与指标可靠性并入方法评价，不作为平行主线；方向 02/03/04 暂缓。具体 RQ、贡献、指标、基线、边界和下一闸门见 `my_paper/方向框架/01_跨层因果边归因与可验证诊断/00_主线重梳理_2026-10-22.md`。
