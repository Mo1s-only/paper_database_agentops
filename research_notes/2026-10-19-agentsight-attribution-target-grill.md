# AgentSight 在论文归因中的作用：研究决策记录

- 日期：2026-10-19
- 本轮目标：明确归因对象、AgentSight 的增量证据与当前论文主张边界。

## 当前摘要

- 现有方向把任务失败归因到责任 Agent、决定性 Step 和传播 Edge；系统执行证据用于解释工具调用及环境副作用，并提高责任链的可审计性。
- AgentSight 是观测来源；Trace Adapter 负责把应用语义事件和系统事件对齐；归因方法还需独立真值和必要的反事实复验。身份关联或时间邻近本身不构成因果证明。
- 已有两个真实受控双 Agent 场景各为 `n=1`。语义规则的 Agent/Step/Edge 预测与预冻结真值一致，但每个场景 AgentSight 只捕获原生 4 次工具调用中的 3 次；错误传播场景缺失的是责任 Bash 步骤。因此目前不能宣称 AgentSight 已提高归因准确率或完整系统因果链已经建立。
- 建议将下一阶段研究问题限定为：跨层系统证据能否改善工具/环境故障来源的区分与责任链完整性，并在观测缺失时可靠拒判。要通过应用日志基线与跨层证据组的配对比较验证。
- 作者已回答“ok”，暂按上述研究主张继续。下一步先分别验证 Adapter 的语义协议、真实跨层配对和扰动稳定性，再评估归因增益。

## 问答记录

- 用户：那我带了 AgentSight 的归因的意义是什么？归什么因呢？
- 当前建议回答：归一次失败中最早的决定性错误步骤、错误沿 Agent/工具/消息关系的传播路径，以及该步骤对应的真实执行机制。AgentSight 贡献系统侧执行证据；具体归因结论须由独立真值、依赖关系和干预检验支持。
- 用户：ok，综上所述，你要用哪些数据来验证我的 adapter 的正确性和稳定性？
- 当前建议回答：用本地 882 条公开轨迹检验语义 schema/真值映射；用可控、零 API 的真实 AgentSight 执行批次建立工具 ID、进程身份、时钟和副作用的独立配对真值；把 1,000 条扰动 fixture 接入生产对齐器检验缺失/冲突时拒判；最后用已有三类双 Agent 场景的小批量真实 API 重复检验端到端稳定性。公开轨迹与合成夹具均不能替代真实跨层采集结果。

## 待确认问题

- 新的真实 API 扩样受既有累计 2.00 USD 硬停止线约束；单场景 2 CNY 上限不自动改变累计上限。先完成零 API 的生产对齐器与本地 AgentSight 真实进程验证。
- AgentRx 原始文件尚未在本地取得，不计入已验证数据；如后续可获取，可作为新的语义协议外部验证集，不用于跨层准确率。

## 后续证据闸门

1. 恢复或补采漏掉的责任工具调用，并量化跨层捕获与拒判。
2. 设计语义层表现相近、系统层原因不同的配对故障，比较应用日志基线与应用日志加 AgentSight 证据。
3. 在可重放环境中检验修复决定性步骤是否改变任务结果；无法复验时标记为观测性定位。
4. 逐场景分开统计原生工具捕获率、已接受链接的精度/覆盖、全链比例、来源完整率与拒判，不把软件单元测试数量当作独立运行样本。
