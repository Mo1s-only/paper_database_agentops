## 三、建议收敛的增量点

### 建议题眼

> **有来源保证的跨层副作用证据，能否提高多 Agent 故障的责任边归因，并在证据关系不确定时以可校准的 abstention 控制误归因？**

重点不是再造一套 tracing collector，也不是声称观察到的时间/进程相邻就是因果。研究对象是三段可审计关系：

`semantic tool/action → observed process/file/network effect → downstream agent/state consumption`

把每条跨层 link 明确分为 `direct/shared-ID`、`controlled-hook/lineage`、`inferred`、`ambiguous`、`missing`，记录来源事件、匹配规则、候选数和时钟/进程谱系。随后比较同一 run 的不同 evidence view，回答：

1. 对工具副作用错误、静默失败和跨 Agent 错误传播，加入实际系统效果证据是否提升 action/edge attribution，而非只改善 failure detection？
2. 当 link 从 direct 降为 inferred/ambiguous/missing 时，coverage 如何变化、false attribution 是否增加，provenance-aware abstention 能否控制 selective risk？
3. 对所选责任边做修复/屏蔽干预，任务 oracle 是否翻转；对无关边做匹配控制时是否不翻转？

### 可证伪假设

- `H1`：在必须观察文件/网络/进程效果才能区分根因的故障上，semantic + provenance-linked system evidence 优于 semantic-only；若不稳定或没有实质增益，撤回核心增益主张。
- `H2`：纯语义/路由错误上 eBPF 增益应小于工具/环境副作用错误；否则需解释额外收益究竟来自更长上下文或提示差异。
- `H3`：link provenance 变弱时，未校准方法的错误强连边风险上升；采用 selective abstention 后，固定 coverage 下风险下降。必须同时报 coverage 与 risk，不能只报准确率。
- `H4`：针对预测责任边的修复/屏蔽比无关边控制更能改变独立任务判据；若正、负干预没有区分度，则边关系不能称为 intervention-supported responsibility。

## 四、对“增加论文含量”的判断

**VERIFIED**：归因算法、语义依赖图、反事实式诊断、Agent 专属遥测 schema、eBPF process/file provenance、跨层攻击日志归因都已经有直接相关工作。  
**INFERRED**：把贡献收敛到“实际系统副作用 + 可审计关联强度 + 多 Agent 责任边 + 独立干预 oracle”的统一实验问题，比继续扩展 UI 或增加单纯采集字段更可能提高论文研究含量。  
**UNVERIFIED**：这一组合是否构成足够新颖的 CCF A 级贡献；必须完成对 AgentSight、Agent-Warden、ALTEDA、TraceElephant、EDGE、DCFA、CausalFlow、TelemetrySuffBench 的全文方法级比较，并做第一轮预注册对照实验后再判断。  
**AUTHOR_INPUT_NEEDED**：学校/导师要求是否硬性指定 CCF 分级；公开多 Agent 运行的隐私/许可证边界；是否允许安排第二框架与独立人工标注。

### Go/No-Go Gate

- **Go**：能在实际运行中可靠记录语义动作到系统效果的 source-preserving link；有至少一类错误只有/显著依赖系统效果证据才能定位；blind paired evaluation 显示跨层 view 改善 action/edge 定位或在相同 coverage 下减少错误归因；目标边干预和无关边负控显著可区分；与 AgentSight/Agent-Warden/ALTEDA 的功能边界说清。
- **No-Go**：所有系统证据仅是时间/PID 共现、无法建立独立可复核的效果链；或跨层证据不改善责任定位；或目标/无关干预结果无法区分。此时把论文收敛到观测链可靠性/失效模式实证，不宣称新因果归因算法。
